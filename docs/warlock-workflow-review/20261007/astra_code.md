## Replacement operating rules

**Stop:** automatic model/native campaigns for every edit; complete source-tree copying as the everyday development method; ceremonial publication companion commits; expanding CONTROL obligations without naming the original scenario they unblock; reporting assertion counts as progress.

**Start:** one active product interaction, one editable integration candidate, one original-requirements ledger. Freeze accepted releases/evidence, not every working edit. Preserve all existing archives; reference their immutable hashes instead of recopying unchanged artifacts. Every task states the before/after user behavior, original scenario IDs, code seam and smallest decisive test. If an infrastructure task cannot name the blocked interaction, defer it.

**Retain:** one Elm policy owner; native effect authority; exact core/plugin ABI pairing; serialized isolated native campaigns; original deadlines and scenario identities; draft preservation; Unknown/no-replay semantics; failed evidence.

Use compile plus focused implementation tests first. Add Quint when lifecycle/authority semantics change; add native execution for native effects, actual keyboard/focus or presentation claims. Run the relevant original scenario once the interaction is complete, then broader release regression at integration milestones. Unchanged hashes inherit evidence with explicit applicability. A failure expands verification only around the demonstrated risk.

Report every 30–60 minutes: user behavior changed, original scenarios closed, blocker, actual incremental tokens/time when available. Two consecutive intervals with no demonstrable product behavior trigger scope correction. Do not reset the goal or launch another reviewer round to manufacture momentum. No additional skill/plugin removes the observed delivery obstacle.

1. **Search and launch from Applications — ELM-UI-005 and ELM-UX-029.** First feasible code slice today: add query/selection state to `G/src/Desktop.elm`, pure ranking to `Catalog.elm`, a typed input/result projection through `Surface.elm`/`SurfaceRenderer.elm` and existing action adapters. Extend native catalog metadata for localized name, generic name and keywords; preserve native-only Exec. Keep query ownership in Elm and reject stale query/catalog actions. Reuse existing `Launch` and native submission authority. Verify ranking/ties, removed identity, stale refresh, no-match/unavailable, refusal preserving query, and one native Enter launch/refusal with no duplicate. Do not claim native IME acceptance from this exercise.

2. **Persistent pinned launchers — ELM-UX-004, ELM-UI-004.** Join desktop-entry identities to taskbar groups, expose keyboard pin/reorder controls, persist validated identity order through the native adapter, and enable the existing zero-family Launch behavior. Verify reorder/restart, removed desktop entry, and ordinary activation never launching a duplicate. This adds an immediately usable taskbar capability.

3. **Visible, identity-correct taskbar previews — ELM-UI-016, ELM-UX-006/007.** Complete the existing controlled renderer’s native exposure boundary and actual popup presentation, including unavailable icon/title fallback. Use one family first. Verify visible live/historical/unavailable states, stale-incarnation rejection and close/reopen resource retirement on the owning tuple. Preserve the curtain until those physical conditions are implemented; do not substitute another model campaign for the presentation change.

Success is falsifiable: the integrated candidate supports search/Enter/refusal recovery; two pins retain order after restart; one visible preview remains identity-correct across minimize and reopen. Requirement closures must link original scenario evidence, not new contract totals. Exact native accessibility, IME, multi-output and release acceptance remain separately measured risks.
