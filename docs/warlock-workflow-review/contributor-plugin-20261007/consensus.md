# Contributor plugin: decisions and verification

The requested six-agent effort produced one shared checker and contribution skill, with thin Claude Code, Codex and Grok adapters. Three GPT 6.1 sol agents implemented the checker, packaging and policy tests; three exact Opus 5.5 agents at high effort independently reviewed discipline, host behavior and adversarial cases. The root integrated repository policy, the guarded loop, marketplaces, PR guidance and CI. [Participant provenance](review-manifest.json) records the actual roles and terminal reviewer model identities. Review reports describe evolving source; subsequent fixes were verified locally.

The plugin follows the [October 7 AAR](../20261007/AAR.md): implement one bounded user behavior in the incremental candidate, retain exact original EARS/scenario oracles, verify the changed behavior proportionately, and record unresolved physical/native/AT obligations. A checker pass is structural consistency. Original acceptance remains external and independently reviewed.

| Review finding | Final disposition |
| --- | --- |
| Resumed own drafts were locked by foreign-dirty snapshots | Explicit per-path adoption with an ownership note; unrelated drafts remain protected. Selection alone never implies ownership. |
| Old partial source evidence prevented further fixes | Retain immutable evidence, mark prior claims historical after relevant source changes, and invalidate their current acceptance. New stale claims still fail. |
| Duplicate partial verdicts reset the no-progress timer | Derive progress from authored source changes or a new verdict identity; repeated hashes/timestamps and QA/generated files do not establish product progress. |
| Missing plugin roots could block prompt hooks | Shipped shell commands fail open; malformed payloads and hook errors are advisory. Explicit loop checks remain required. |
| Cached plugins could inspect the wrong repository or stale code | Discover the working repository from cwd, report checker SHA, refuse a checker that differs from repository code, and prefer the repository CLI. |
| Archive renames concealed deleted source paths | Check both endpoints using `--no-renames`; CI compares paths against the PR base without hashing the archive. |
| Concurrent starts and record writes could overwrite ownership/history | POSIX locking, exclusive creation, atomic replacement, file and directory fsync. Tests exercise concurrent starts and writes. |
| Support work was blocked by stale GUI records | `check --project-only` validates the frozen project without reading a participant record; it cannot be combined with `--require-record`. Product loop checks always require the record. |
| Git environment could redirect checker or fixture operations | Scrub inherited Git routing; isolated test repositories disable external config, signing and hooks. |
| Symlinks or directories in foreign drafts caused incidental failures | Fingerprint their identity without following symlinks. Source/evidence/record paths still reject symlinks. |
| Contradictory acceptance fields and arbitrary source revisions | Reject remaining missing observations, self-review, ignored/source evidence, invalid source tuples and nonexistent commit revisions. These are consistency checks, not reviewer authentication. |

Some reviewer suggestions were deliberately narrowed. Foreign files outside the product tree are still protected; downgrading their changes would weaken ownership. Alternate worktree records do not authorize changing the global slice selector. New `--record` locations preserve prior records without automatic supersession. The 45-minute/two-qualification threshold recommends leaving an investigation; it does not globally block the project or authorize bypassing safety. These are root integration decisions, not a claim of unanimous approval of every implementation detail.

Local verification passed 58 policy, host-command and guarded-loop tests through the protected launcher, plus Claude manifest validation, Grok manifest validation and skill validation. The suite includes cache mismatch, rename preservation, concurrent updates, hostile Git environment, evidence freshness, exact original identities and fail-open hooks. [Validation details](validation.json) record final source hashes. The provided CI template checks original inventory and archived-path changes on pull requests, then runs the offline suite. It does not launch GUI sessions or certify the release. GitHub rejected workflow publication because the existing OAuth credential lacks `workflow` scope; the template is published under plugin references and is not activated. Authentication was not changed.

Host installation/trust has not been performed. Claude/Grok discovery validation is distinct from a live client session; Codex packaging follows the official marketplace/hook contract and requires supported installation and trust. Passive Grok hooks cannot deliver context, so its skill and explicit repository loop carry the instruction. All contributors can use the shared CLI without an AI client, network or credentials. Local records remain self-attestations, and changed source bytes alone cannot prove useful behavior.
