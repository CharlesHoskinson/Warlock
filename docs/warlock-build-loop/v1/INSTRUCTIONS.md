## Each iteration

1. Inspect branch, working tree, source owners and live processes. Preserve concurrent workers and all accepted/failed evidence. Select the smallest unblocked implementation slice with a concrete behavior oracle and original scenario identities.
2. Record the chosen slice and next step in a fresh immutable checkpoint. Use fresh source derivatives for changes to frozen components; assign source ownership before parallel work. Keep native GUI campaigns serial.
3. Implement actual code and review the change. Compile the changed program. Run applicable CPU/decoder/replay/fuzz checks through the unchanged protected launcher; execute explicitly selected Quint scenarios and meaningful coupled implementation traces. Preserve receipts, input identity, original deadlines, native clock/lifetime identity, unknown settlement and physical retirement obligations.
4. Qualify native behavior on the owning source/core/plugin ABI tuple using `python3 -B implementation/elm-build-loop-v1/loop.py native --runner /absolute/reviewed/runner.py`. CPU QA uses `/home/hoskinson/window-integration-qa/qa_run.py` with the original core/scope protections. Do not weaken a scenario, change an oracle or extend a deadline to obtain a pass. A busy native slot permits independent CPU work.
5. Fix failures in a fresh derivative and retain failed reports. Freeze source/build/evidence hashes, publish bounded acceptance and remaining gaps, then commit only owned paths with raw bytes preserved. Respect existing GitHub publication authorization; do not publish unrelated worker changes.
6. Advance to the next unmet slice. Status questions receive a brief answer while work continues. Do not end at a plan or successful component when independent required work remains.

Only the host goal supplies automatic AI continuation. Repository checkpoints do not arm a goal. Do not spawn a second AI daemon, edit client databases, or treat a lifecycle reset as project completion. Respect explicit user pause/cancellation and budget limits. Use the goal tool's repeated-blocker rule before marking a goal blocked; record attempted alternatives and the exact missing external input. Continue independent work while a gate waits.
