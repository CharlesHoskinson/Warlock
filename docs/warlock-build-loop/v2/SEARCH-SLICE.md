# Launcher search implementation result

**ELM-UI-005 / ELM-UX-029**: current query, ranking, no-match, removal/refusal recovery. The integrated Applications popup now accepts a bounded typed query, ranks case-folded localized names and metadata, and binds entries to the current query/catalog publication. Enter uses the existing native desktop-entry identity authority; query text is never executed. Refusal preserves query and returns keyboard focus; Refresh reads the catalog without repeating the launch. Provisional IME input stays local until committed; actual native IME acceptance remains outstanding.

Four changed Elm targets compile, strict native query admission and the integrated host build/self-tests pass. Typed fixtures cover ranking, stale query rejection, no effects from typing, no-match, refusal clearing after refresh and persistent Unknown. A real private Wayland journey types `files`, filters to Files, removes that exact desktop identity, presses Enter, observes exactly one native Refused request, retains the query and focused search field, then refreshes to no-match without a replacement or duplicate launch. Private clients and helpers exit normally and cleanup passes.

This journey exposed a production focus race: unrelated same-popup publications discarded an undelivered search-focus request. The native host now carries it only while the same active lease/mode and every exact enabled target survive. Delivered requests never replay; close, replacement or disabling drops the pending target. Native admission fixtures and a bounded Quint model cover those cases; the model is not a complete native/Elm refinement proof.

**Physical popup presentation fails.** The final screenshot is after Refresh/no-match, despite its original filename. The bar paints the no-match status, but the Applications popup is solid black. DOM content, received keystrokes and focus acknowledgements cannot establish visible controls. Controlled preview mode was not requested; this finding does not justify lifting its safety curtain. All affected original scenarios remain partial. AT, native IME, accepted launch, exact old-refresh/query-change race and independent acceptance also remain open.

[Evidence manifest](../../../implementation/warlock/qa/evidence/launcher-search/manifest.json) links compact behavioral/build reports, source/binary hashes, the black capture and the retained meaningful failures. Full original reports remain unchanged in ignored local QA storage. The canonical source stays in `implementation/warlock`; no new versioned application or qualification tree was published. Native runners select the verified current integrated build for feedback, focus and search modes.

The next product slice is persistent desktop-identity pins, relative ordering across restart and a zero-window pinned launch (**ELM-UI-004 / ELM-UX-004**). The rendering defect is recorded for targeted repair; it must be resolved before original launcher visual acceptance or release.
