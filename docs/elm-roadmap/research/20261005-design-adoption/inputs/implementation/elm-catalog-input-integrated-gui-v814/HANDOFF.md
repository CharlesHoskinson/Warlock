# 814 coherent catalog/input source candidate

This combines the accepted source experiments in frozen 778 and 786. This is a
source/build/CPU candidate; native coexistence and full GUI acceptance remain pending.

The five production differences from 786 are Desktop.elm, OutputController.elm,
Surface.elm, host.c, and shared-host.c. The three Elm modules are exact 778. The
shared host is exact 778/730, retaining cache/callback reference ownership,
immutable first dispositions, duplicate suppression, and historical correlation.
The host combines 786 activation resource loading with 778 pre-enqueue popup
negative classification. No backend, storage, protocol cap or timer change occurs.

Relative to 778, the input modules Bar, Popup, Presentation and SurfaceRenderer
come from 786, CapturedAction is added, and the 786 activation asset, bar/popup
adapters and HTML entry points are retained. Host.c additionally loads activation.
Captured six-field action identity is never reminted: the existing Presentation
eligibility guard checks current state before encoding the captured envelope.

The protected freeze report records both complete parent inventories, exact
production differences, all owned reports and the final build input closure.
Original model and refinement histories remain in frozen 778; this combination
introduces no new policy and does not transfer their abstract assumptions to
native execution. Filesystem crash tests prove controlled process/syscall cases,
not power loss or native authentication. Input harnesses use synthetic DOM/API
objects; physical input, AT, keyboard focus, and WebKit lifecycle remain separate.

Known open gates include first-arrival FIFO assumptions, native coexistence,
packet-budget recovery, practical immutable-history capacity, full accessibility,
GPU/device validation and complete desktop acceptance. In particular the inherited
"Choose Applications again" message does not establish recovery after sticky
whole-packet exhaustion; model-first 816 must address that reachable product gap.
No automatic retry or new effect authorization is introduced. Existing Main clocks
and all inherited native scenario deadlines are unchanged.
