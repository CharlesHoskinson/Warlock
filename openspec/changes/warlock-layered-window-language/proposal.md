# Why

> Current production-language decision (2026-10-30): Warlock-authored production uses Elm and Haskell only; all GUI elements are Elm. Haskell owns native/runtime capabilities, Haskell supplies pure policy where selected, and Elm owns GUI presentation with one authoritative policy owner per domain. Only Elm and Haskell authored production components may ship, including behind an allowed-language wrapper. Development/formal tooling and separately inventoried third-party libraries are distinct. Preserve original IDs, scenarios, behavior, deadlines and historical evidence; old passes do not accept replacements. Implementation remains paused pending readiness and root/Muse authorization. See `warlock-production-language-migration`.

The user requires color, glow, shadow and shading as major elements of layered-window navigation. Existing design contracts preserve focus, outcomes and accessibility but do not fix the spatial language or keyboard-recipient distinction.

# What Changes

Add fourteen layered-window EARS requirements with concrete scenarios, semantic tokens, a three-reviewer council consensus and explicit native qualification work. Preserve the established Warlock brand and all effective Omarchy bindings. Major glow belongs to window/shell chrome; ordinary controls remain crisp.

# Impact

Affects future Elm view projections, native decoration/rendering, navigation catalog and accessibility/resource qualification. No installed configuration or main desktop is changed by this proposal. The frozen baseline and existing thirty-contract consensus remain intact.
