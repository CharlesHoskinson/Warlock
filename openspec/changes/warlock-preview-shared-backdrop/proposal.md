# Shared Elm generated backdrop integration

## Why

Owning generated-color/blur pixels were qualified in native85 while the full shared GUI34 still consumed only transparent FD3 family captures. The shared Main/Bar/Popup provider must explicitly admit generated native color, map FD4 with its own native child grant, retain historical image ownership across current source changes and retire the original resource before terminal receipt acknowledgement.

## What Changes

- Add a distinct typed generated native source and FD4 capture/mapping path in the full shared provider.
- Preserve original transparent source admission, one immutable Elm authority, complete family coverage, native clock/deadline and proof-safe physical ownership.
- Compare actual generated-color WebKit pixels with independent native color, retain historical URI/job across native color changes, and qualify source loss as an exact typed denial.
- Preserve failed geometry fixtures and derive exact displayed dimensions from unchanged CSS constraints and native crop ratio.

## Impact

Additive elm-capture-motion requirements and owning source/ABI qualification. Frozen baseline242/417, separate right-click24/48 and optional C00–C06 remain. No main desktop activation or full release acceptance.
