# Enrollment and settlement

The GTK owner borrows the existing native bootstrap transport. Actual native
scope establishes source identity and clock; web content cannot provide scope,
receiver epoch, capacity, receipt or source eligibility. Native actor retention
is bounded at 256 while the original allocator retains two items, 128 MiB,
eight journal records, four URI readers and two receivers.

Validate the original receiver epoch inside Endpoint.nativeDemandView before
scope query, intent retention, scope admission or reservation. Add membership
inside that same critical section. Existing receiver entries, readers and
original deadlines remain retained. Explicit ReceiptDelivery subject extension
uses the same owning bootstrap and existing journal before new events are
published to Elm.

Capacity and expiry concern an unissued intent. They never produce a native
terminal Refused or advance the request floor. Retry uses the original native
binding, incarnation, clock, publication, lease and deadline. Returning capacity
does not renew the cutoff. A distinct future intent after expiration requires
an explicit lifecycle design and must preserve historical issued operations;
it cannot be implemented by erasing the retained ledger.

Actual issued rejection is distinct from local admission failure. Retain its
exact job and journal proof so Elm can register the known job before receipt
delivery. Suppress capture for an already rejected job. This route still needs
its explicit frontend settlement evidence before product qualification.

The initial dynamic implementation is an isolated client qualification route
with previewEligible:false. Ordinary eligible family capture requires the
original native grant and fidelity gates. No metadata catalog observation is
promoted to eligible pixels by this change.
