## Desktop

The home page leads to a full-viewport simulated Omarchy desktop. The taskbar and popup renderers run compiled Elm in isolated frames and the controller connects through a versioned bridge. A deterministic host owns simulated world facts, validates identities and epochs, and issues receipts separately from observations. Local fixtures represent client interiors and do not access native applications or files.

Host geometry reserves the top taskbar, uses actual anchors and constrained popup placement, and supports workspace, tiling and floating interactions. Effective bindings, visible controls and a legend make actions available when browser or operating-system shortcuts intercept keys. Observed window lifecycle drives the portal; operation intent and receipt do not.

## Exploration

A guided tour points to working surfaces and has keyboard-accessible navigation and dismissal. Design language pages describe components and link to their desktop contexts. The architecture page displays components and connections from the verified model with accessible text and clear model scope. The model must represent the current Elm and Haskell production contract; historical runtime descriptions are identified as historical.

## Delivery and acceptance

Relative bundled assets, fonts, fixtures and links work under `/Warlock/` and without network access when local files are available. Keyboard access, focus, contrast, reduced motion and forced colors are tested across the desktop and documentation. GitHub Pages serves `site/` at the project URL. Simulation evidence remains distinct from native qualification and original scenario acceptance.
