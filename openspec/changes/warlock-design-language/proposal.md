# Warlock design language and catalog

## Why

Warlock has an approved brand and philosophy but lacks a complete reusable design language and source-traced interactive widget catalog. Five actual Opus5.5/high reviewers researched Material, Impeccable, iOS, KDE/Plasma, Windows/Fluent and GNOME and accepted one corrected30-contract candidate.

## What Changes

- Add30 guarded design targets and60 observable acceptance scenarios, with exact five-reviewer ballots, EARS and source-proposal routing.
- Build a repository-owned catalog, additive tokens and visual library using the approved Warlock identity and actual Elm fixture demos.
- Route renderer/input/feedback refinements into existing work packages and qualification gates.

## Capabilities

### New Capabilities

- `warlock-design-language`: design foundations, widget catalog and guarded product integration targets.

### Modified Capabilities

None. Existing in-flight baseline/release/adoption specs remain unchanged.

## Impact

The candidate and receipt live in DesignLanguage/research/v1. All original242/417, separate right-click24/48, S01-S16/C00-C06, native preview13/restore38/recovery34/drag-resize52, ownership and deadlines remain unchanged. Research consensus accepts text; it does not qualify code, browser, native, hardware, AT/IME or a complete release. The catalog remains isolated from production native effects and preserves a single immutable Elm policy controller.
