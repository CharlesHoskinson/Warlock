# Typed local outcomes

Produce local feedback within the existing admission mutex from the actual
native observation and retained intent: binding, subject, clock, native request
sequence, requested presentation stamp, original cutoff and typed outcome. It
contains no job, receipt, token or grant. Initial unissued feedback carries its
own validated source seed, without a Request event. Resume retains the existing
source lifecycle and counter history. Existing C APIs retain their old outputs;
new feedback APIs serve the full GTK host. The distinct `demand-seed` establishes
idle scope without opening capture or consuming the accompanying feedback's
sequence. An issued `source-seed` clears feedback and advances that floor.

Elm admits feedback only for the current enabled picker entry, exact source
binding/incarnation/clock, positive strictly newer sequence and an idle lifecycle.
Feedback changes no scope, job history, resources, cleanup or commands. Source
seeds clear feedback and advance its sequence floor; close hides it while
retaining that floor. Native lock/source denial keeps existing concealment rules.
Labels describe waiting or expiration; no Retry action promises renewal.

Use the same full host, bootstrap, endpoint, Broker, receipt delivery and immutable
Elm policy in the three-subject qualification route. One pool still owns two
physical items. Explicitly extend receipt membership before publishing new
subjects. Native compositor qualification remains separate from model/browser
evidence; ordinary eligible capture and the complete release remain open.
