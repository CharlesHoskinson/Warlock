# Current XDG grab provenance accessor

This fresh derivative starts from exact owning Core205 archive/header closure. It adds a legitimate read-only owner API rather than inspecting private fields through a plugin, changing native eligibility, disabling grabs or changing focus.

1. `CXDGShellProtocol::currentActiveGrab() const` returns an optional bounded strong snapshot of the actual protocol-owned grab, current owner and registered live grabbed popups. It returns no proof unless the exact protocol grab is the current `g_pSeatManager->m_seatGrab`. Absence never authorizes an own-popup exception; with any active grab it must be classified unknown/external unless separately proved.
2. Require unique nonexpired members still present in the protocol's actual popup resource registry, current self/xdg popup association, actual mapped XDG and live Wayland surface resource. Owner must occur exactly once. Bounds64 grabbed/512 total popup resources fail closed; no eviction or callback mutation.
3. Preserve raw nullable XDG immediate parents. A Gtk layer-shell popup can have no XDG toplevel parent. Root305 must independently join the exact resource through public OtherViewState/CPopup getT1Owner and layerOwner, and require actual trusted host popup+bar resource/PID/start ownership. Do not substitute an app window or infer root from coordinates.
4. Snapshot members do not prove there are no other accepted surfaces: root305 must census *every current native compositor surface* against the same held exact grab using existing read-only CSeatGrab::accepts and reject unknown/foreign extras. This API does not reveal private CSeatGrab state, invent client credentials or modify serial validation. Native eligibility remains false while grabbed.
5. Getter executes only in the existing serialized compositor owner-thread callback. It emits no signal, changes no grab, maps no surface and extends references only for the snapshot's lifetime. Consumer must not retain it as reusable authority after callback/current host/view/lease revision changes.
6. Additive nonvirtual out-of-line method and separate snapshot struct; no existing class data/layout or inherited lifecycle method changes. Changed public header consumers must be audited and rebuilt from their actual latest captured sources, not raw owner approximations. Include Core205 latest SeatManager, Core450 InputManager, Core470 render/hit corrections, Core73 geometry/defaults and all retained objects. Preserve433 ordered archive members except exactly rebuilt consumers, actual link closure/AQ155, exports, and owning-header provenance. No installed core/header edits.
7. CPU source/object/link tests are prerequisite only. Actual same-grab provenance, native resource lifetime/external-grab/callback order and original GTK02 require a fresh coherent producer+host+Elm/native campaign. No native acceptance is transferred from Core205.
