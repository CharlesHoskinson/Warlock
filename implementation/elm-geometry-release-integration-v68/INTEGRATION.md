## Durable uncertainty must match the actual engine

V58 Effects allows 64 unresolved entries, guarding native lifetime/incarnation across operation, session and frontend changes. Menu and receipt registries also retain bounded outstanding keys. V275 still writes a single `intent.json` and a single `host-intent.json`; `Journal.begin()` overwrites the prior record without checking unresolved entries. Consequently A Unknown followed by unrelated B can erase A's only durable uncertainty. Typed protocol fields alone do not fix this.

Use bounded per-full-key durable entries, preserving up to 64 unresolved operations without eviction. Retain the existing 0700 namespace `runtime/elm-window-recovery/<instance>/<native-lifetime>`, 0600 single-link files, no-follow descriptors, nonblocking writer locks, atomic write/fsync/rename/directory-fsync and migration ownership checks. Preserve schema-1 legacy readability, explicitly version the new collection representation, and migrate under the existing ownership rules. Capacity exhaustion must reject before native submission or surface dispatch; it must not replace an Unknown entry. Definitive exact settlement frees one entry; Unknown and process loss retain it.

Every entry and receipt key includes effectProtocol, original full binding `{lifetime,session,frontend}` and full intent `{request,generation,incarnation,operation,context:{lifetime,epoch,output,revision}}`. Protocol 1 means minimize/restore/activate and legacy facts revision; protocol 2 means maximize/restore-geometry and geometry revision. Native output generation is not physical output identity. Stable lifetime/incarnation guards span both namespaces. Legacy Restore remains unminimize, including restoring a saved maximized window.

The required ordering is: validate complete commit and scope → durable host admission → close/publication commit → guarded durable broker begin → native submission once → validated full-key settlement durably written → receipt delivered. Storage failure after submission must retain uncertainty and report storage failure, never invent Refused/Committed or replay. Ensure observation requests do not create effect records.

V58 has no `host-uncertain` recovery decoder or `Effects.recover`. V268's decoder admits only the legacy four-field frame, while V275 emits protocol-2 `host-uncertain` with an extra effectProtocol field. Merge a strict typed recovery decoder, restore unresolved entries into the shared allocator/high-water marks, and preserve original issued binding for later receipt correlation. Recovery frames are informational, never commands; they must not create observed geometry or scene facts. Keep stale callback guards ahead of recovery/storage notices and preserve explicit reconnect, not automatic retry.

A journal lock is not complete global old-live-broker revocation. The primary loop still marks that gate open. Verify actual old broker PID/start/cohort retirement and native peer/epoch rejection before a replacement can mutate; independent sessions must not bypass unresolved target barriers. Scope this separately from same-process reconnect and synthetic file locks.

## Shared output and newer core are separate merge obligations

Primary Main consumes `nativeViews` through OutputController; renderer input is wrapped in `{viewProtocol:1,kind:'view-action',scope:{id,generation},action}`. Geometry Main consumes `nativeOwnerScopes` and runs one SurfaceController. The producer must derive physical-output/provider ownership from an admitted current native view, preserve popupOwner/focusOwner and topology generation, reject retired or wrong-view context gestures, and keep one engine/broker. Native scope and frame/context generations remain distinct. Preserve 64-view topology capacity, selected-output transfer, output removal/replug/zero outputs and fresh focus return.

The current monitor/hit-test core `elm-core-parent-hit-test-v66` is not a superset of geometry V40. Direct Window.cpp comparison shows it reintroduces the old MAX toggle: a repeated maximize while already MAX unmaximizes regardless of the requested boolean. V40 implements desired-state set/unset idempotence. Merge V66's ParentPointerFocus include and `refreshParentHitTest()` visible-buffer hook onto V40's geometry Window.cpp; preserve the minimized-input guard and V40 XDG zero-default limit/FullscreenController changes. Also retain the monitor reload and pointer-coordinate/AQ work from that branch. Rebuild the actual owning archive, all affected public-header consumers and geometry authority plugin; neither V49 nor the newer legacy V64 plugin can be loaded against an unrecorded merged ABI.
