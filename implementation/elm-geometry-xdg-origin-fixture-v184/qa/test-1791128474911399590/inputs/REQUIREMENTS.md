# Controlled nonzero-origin XDG fixture requirements

Write-before-code requirements for an isolated native fixture. This is not a GTK toolkit conformance claim and does not change geometry eligibility or compositor behavior.

1. Create one owned wl_surface/xdg_surface/xdg_toplevel, with fixed app ID and PID-qualified title. Use the installed official stable xdg-shell XML and wayland-scanner-generated protocol. Perform initial role-only commit before attaching a buffer. Do not force focus or execute shell commands.
2. Geometry dimensions follow configure dimensions when positive; zero axes retain the chosen ordinary/current dimension. Requested XDG geometry has independently selected nonnegative origin and right/bottom padding; the full wl_surface logical extent includes origin+geometry+padding. CLI integers are canonical decimal, explicitly bounded, and duplicate/unknown/missing options fail before connection. Raw min/max hints are independent (zero unspecified), with each nonzero max>=min. Initial and configured geometry extents must satisfy declared hints and be32..4096; refuse unsupported tiny extents instead of committing an invalid hinted size. Scale is exactly1 or2. `--validate` parses and reports without any socket connection.
3. Negative origin is not claimed by this single-surface fixture: protocol window geometry is intersected with surface/subsurface bounds, and a lone surface at0 cannot supply negative extent. A future subsurface fixture must own/prove that case. No viewport/fractional-buffer profile is claimed here.
4. SHM buffers use scale-multiplied physical dimensions, while window geometry/configure dimensions remain logical. Paint separately identifiable outside area, window-geometry border/four corners, and interior ACK-serial color. Publish known logical landmark coordinates and opaque colors. Validate dimensions/byte arithmetic before allocation; at most8 unreleased buffers,64MiB per buffer and128MiB aggregate. Never evict/reuse unreleased storage.
5. Record JSON events with monotonic sequence/time/PID, native protocol configure serial/state, a distinct ACK event, requested geometry, surface logical and buffer physical sizes/scale, exact buffer serial/landmarks, releases, pointer enter/motion/button/leave and normal termination. Only enter from the owned wl_surface enables local pointer events. Commit journals prove requests queued, not pixels/presentation or compositor-clamped effective geometry. Server sync barriers prove processing only.
6. Support stdin maximize/unmaximize/sync/inspect/quit with bounded command parser and bounded correlated barriers inherited from the existing fixture. Clean normal stdinEOF exits0; partial EOF/transport/protocol failures exitnonzero. Destroy callbacks/role/surface/buffers/pointer/seat in dependency order. No retry of native operations and no synthetic outcomes.
7. Protected CPU QA compiles actual C and generated protocol with warnings as errors, exercises production parsing/dimension/color/coordinate helpers and invalid boundaries without display connection, and captures exact source/generated artifacts, compilation dependencies, link libraries and tool hashes. Native launches remain root-serialized and separately reviewed.

# Native handoff obligations

On the exact owning tuple, test zero origin control and asymmetric nonzero origin with compositor border/reserves, actual reserved bar and scale1/2. Bind titlePID/appid plus native lifetime/incarnation/real process/socket ownership. Record actual set_window_geometry, configure MAX/NONE states, ACK and ensuing selected buffer commit; compare configure extent to logical geometry, not physical buffer size. An observed requested geometry is not proof of its effective clamped geometry.

Sample the published interior and each distinct geometry-corner landmark through actual screenshots, away from layers/popups/decorations. Physically inject parent pointer motions/clicks at those same global pixels and require exact owned wl_surface recipient and matching local logical coordinates. Include outside-pad/border probes without assuming that painted content is an input region. Capture native logical/visual/real goal/current rectangles, main-surface box and renderer UV/viewport state where available. Test actual decorated MAX and exact ordinary placement restore repeatedly, preserving original3s native/5s receipt/6s whole-scenario budgets and full-key Pending/Unknown rules. Only separately reviewed native evidence may establish correct rendering/input origin transforms. No GTK or negative-origin compatibility is implied by this fixture.
