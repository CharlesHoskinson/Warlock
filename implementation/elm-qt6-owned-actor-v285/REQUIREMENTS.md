# Supervised Qt application boundary

Launch only the reviewed Qt250 fixture with the owning private host environment,
Qt Wayland backend and client protocol logging. Register exact PID/start before
consuming its immutable strict279 journal. Choose window-modal/application-modal
explicitly. The actual native entrypoint must verify source/ABI closure separately.

The command vocabulary must match the actual held250 C++ decoder. Every write and
receipt shares its caller's original absolute deadline. Use nonblocking pipe
writes; preserve partial-write evidence and never replay an uncertain command.
Validate malformed commands before recording or writing an attempt.

Normal close requires an actual zero exit, complete final newline and exactly one
final normalexit row. Snapshot partial tails alone do not prove completion.
Failure cleanup is recorded and cannot become normal or native acceptance.
Actual native empty-client census, raw protocol retirement, pixels, modality,
focus, input, resources and process closure remain separate mandatory gates.

CPU tests launch real owned subprocesses with synthetic Qt-shaped journals.
Those tests establish actor supervision and command boundaries only; no Qt GUI
or native toolkit behavior is inferred.
