## Authority split

A menu row may represent an already admitted planning capability while its own authenticated native popup is open. It is never current effect authority. Native geometry effect eligibility remains false under any blocking grab. Selection first closes the exact popup and drops its grab. A native close/sync fence precedes separately correlated fresh action+geometry observations. Only fresh unblocked native facts, full exact authority/target/output/workarea identity, applicable action and absence of unresolved reservations permit allocating one native intent. Cancellation, changed target, external blocker, uncertainty or expiry causes zero effects and no retries.

## Missing authentication prerequisite

The current592 host authenticates controller/view role, topology, popupOwner, publication, lease, Gtk popup pointer, grab readiness and presentation callbacks. It has a GDK sync fence after destroying the popup. Current native geometry409 exports aggregate inputBlocked only (session lock, exclusive layer surfaces, seat grab or layout drag) and geometryEligible/capabilities. Neither aggregate boolean nor a live host lease proves which native grab blocked the target. Therefore the existing wire cannot yet authorize an own-blocker exception.

Required additive observation: trusted host captures its actual GdkWayland popup wl_surface resource ID after native map (never a renderer supplied ID), host PID/start, owning controller/view generation/topology, popup lease and original menu ID. The native producer validates the current full native peer/binding and actual seat grab's resource/client ownership, exact current host popup/root relation and absence of all other blocking causes (lock/exclusiveLS/drag/modal). It returns separately correlated UI-blocker provenance. This is observation-only; effect eligibility and effect guards do not change. Host source-manager/current view/lease authentication plus native exact blocker proof is mandatory; no UI field self-authenticates.

## Prototype contract

The pure Elm prototype accepts two already authenticated trusted observations as its integration boundary. It does not implement the missing transport or claim authentication from typed records. Proof is opaque after matching original admitted planning snapshot against current same structural target with only aggregate eligibility changed by the exact own popup. Stable structural fingerprint must encode *all* original provider action/geometry/window-family fields except known aggregate eligibility/capability consequences; unrelated changes invalidate rather than being ignored.

One bounded prepared slot consumes a monotonic token. Its stages are AwaitClose then AwaitReads. Close confirmation must carry exact original host/scope/menu/lease/publication and the native fence; no observations or intent are allocated before it. Caller supplies fresh positive distinct read IDs from the existing monotonic allocator. Each accepted reply matches exact original binding and request ID, output/workarea/target structural state; both streams must arrive before a single fresh-dispatch decision is returned. Repeated callbacks, wrong/stale IDs, stale lease, expiry/cancel and duplicate selection never dispatch. Deadline belongs to the original selection and is never reset. The caller still uses unmodified Shell.Act/native guard and ReceiptRouter full-key registration. Existing Pending/Unknown/issued/router histories are not owned or modified by this prototype.
