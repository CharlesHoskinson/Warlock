# V46 pure Elm integration contract

This fresh derivative compiles the real shared Controller, provider, Shell, Effects, menu bridge, receipt registry, Main and Popup. Its 78 original V8 menu cases are unchanged. Geometry cases use synthetic explicitly negotiated native envelopes; they grant no native, GUI, backend or release acceptance. Old V8 pure Effects tests that demand retries after Unknown conflict with the persistent unresolved barrier and are not silently rewritten or claimed.

On the authenticated bounded native channel, `{protocolVersion:3,kind:"host-geometry-negotiate"}` starts a separate geometryProtocol1 attach. Repeated controls coalesce while awaiting or after negotiation. `geometry-attached` has the exact V43 capabilities/binding/requestId contract. Effects require explicit effects true and operation membership. Native ops empty retains the original Restore/Minimize provider. Unsupported operations are absent; advertised operations remain visible disabled when current facts/capabilities deny them. Close is presentation dismissal. No fullscreen exit is implied.

For an attach transport/refusal failure, the broker may deliver `{protocolVersion:3,kind:"geometry-unavailable",binding,requestId,reason}` using the original current attach correlation. Only this exact current binding/request clears attach bookkeeping and restores the legacy UI. It never clears pending or Unknown operations. No retry occurs automatically. The broker must not manufacture an effect outcome from a transport error.

`geometry-facts` remains an independent authoritative observation. `context.revision` in effect2 is its geometry revision; effect1 still uses the independent legacy action-projection revision. Workspace-scoped workarea and output-scoped owner generations are validated separately. Matching request/binding, canonical UInt64 identities, strict schemas, closed modes, finite rectangles, ownership/focus coherence and advertised capabilities are checked. Transport authentication, unique raw JSON keys and total wire byte limits remain broker responsibilities.

The provider freezes one legacy context and one optional geometry context. Restore on a minimized window dispatches legacy effect1 restore (unminimize); Restore Geometry on an observed Maximized window dispatches effect2 restore-geometry. Maximize uses effect2. Fixed/constrained/ineligible/minimized/current-state windows disable supported geometry rows. Independent minimized facts must agree before a mixed provider is exposed. Mutating controls are disabled while geometry negotiation or observation awaits. Fresh receipts never manufacture observed mode, minimized state or placement.

Effects owns a single shared request/generation allocator for all five native operations. The bounded unresolved ledger retains Pending/Unknown across snapshots, session/frontend rebind and disconnect. Its guard uses native lifetime/incarnation, independent of presentation labels and session/frontend. Every taskbar and menu path uses this guard; fresh facts do not authorize retry. Only an exactly issued authoritative definitive receipt clears that key. Shell retains exact binding/version/intent registration for ordinary taskbar operations; ReceiptRouter does so for menu operations. Both process retained old keys without replacing an unrelated current transaction or observed state.

Native window-effect envelopes remain protocolVersion3 with effectProtocol1 or2 and exact binding + intent. Receipt keys include version, full original binding, request, generation, incarnation, operation and complete context. Legacy restore retains its meaning. Geometry operations are only maximize and restore-geometry. The broker must forward these namespaces through one native allocator/journal; no second allocator or operation-ID reuse is introduced here.

Actual backend support, V40/V48 native tuple qualification, physical menu interactions, geometry transitions, workarea/output retirement, model approval and roadmap acceptance remain separate gates.
