# Actual GTK window-role compatibility: requirements before fixture code

This is a proposed next mandatory compatibility slice, not an acceptance result.
Original242 requirements/417 scenarios, right-click additions and S01–S16 remain
unchanged. The renderer470 controlled-XDG proof and229/231 parent-pointer proof
are prerequisites for method selection; neither proves GTK, modal or popup roles.

## Candidate and scope

G01. Begin with an actual compiled GTK4 client in the private nested session:
owner A, eligible modal B, nested modal D, and independent same-process peer C.
Use native GtkWindow transient/modal APIs, a GtkEntry with a fixed synthetic draft
in A/B, GtkPopover with a real actionable child, opaque test drawing landmarks,
and explicit role/resource lifetime journals. GTK3 requires a separate fixture
process/binary and independent matrix, never mixed GTK majors in one process.
Installed pkg-config reports GTK4 4.22.4 and GTK3 3.24.52; actual builds must pin
headers/library/tool hashes rather than treating these version strings as ABI.

G02. The selected native tuple is frozen core470/plugin471/AQ155 plus observer225,
whose controlled pixels/input qualification is recorded in231. Use current held
shared-host/Elm/broker source only after the concurrent484 projection-terminal
and184 Escape lanes pass their unchanged oracles. Do not patch those lanes or
transfer old450/454 acceptance to470. A direct GTK/core fixture can proceed
separately, but must label itself as lacking integrated Elm shell acceptance.
No installed configuration, main-session GUI or model changes belong here.

G03. Requested modality is not effective native modality. Journal each actual
GdkSurface/wl_surface resource ID (public gdk_wayland_surface_get_wl_surface),
process PID/start, fixture instance, per-window lifetime, map/unmap/destroy and
transient intent. Independently capture actual xdg_toplevel.set_parent plus the
negotiated modal protocol/legacy route and current authority owner/blocker/focus
relations. A GtkWindow.set_modal call, stacking order, same PID/appid/title or
GTK-side grab alone cannot satisfy a native modal oracle. Unsupported effective
modality remains a recorded blocker, never remapped to a green test.

G04. Declare independent-document GtkWindowGroups for C/A only where the fixture
means independent native families; B/D join A's group. Preserve a separate
adversarial default-group profile to observe real toolkit-global modal behavior.
Do not blame native policy for client-side redirection, or hide toolkit behavior
by silently regrouping a live dialog. Native owner relations and actual client
keyboard recipient must both prove the intended independence.

## Evidence and input

G05. For every overlap/action collect three independent observations: presented
pixels, actual application pointer recipient and actual application keyboard
recipient. Record full bounded per-surface journals, all buttons from owned
baselines, blocked-window negative delivery and synthesized-click counters.
Convert controller-local positions explicitly and also log actual GdkEvent
surface/position; widget allocation is not surface coordinate proof. Link
resource/lifetime to native incarnation and PID/start. No callback calibrates
parent routing.225 must prove focused nested-root surface/mapping/output; child
cursor readback and actual GTK recipient remain separate.

G06. GTK CSD, shadows, window-geometry origin/extent, buffer scale and popup offsets
must be observed through actual protocol/GDK/native facts, not CLI preferred
size or a guessed197 geometry profile. Use full-color interior/corner landmarks
and actual grim output with captured resource/commit/output scope. Extend the
controlled210 oracle only in a new GTK-aware derivative: its current197 shape,
serial palette and exact real==geometry-size contract cannot simply be assumed
for GTK. Frame-clock after-paint and queued configure/ACK are not presentation.
If exact scene/input/presentation receipts are unavailable, label sequential
quiescent observations honestly and leave ELM-LAY-002 atomicity open.

G07. First positive profile is monitor scale1, buffer density as actually chosen by
GTK; then independently qualify monitor scale2/fractional scale and mixed outputs
under original scenario contracts. Do not force GTK to masquerade as197 buffer
scale1/2. Popup anchor/corners must remain in workarea; actual role/grab and parent
lifetime must be evidenced before input. Transparent shadows are intentional
visual/input semantics and cannot be treated as opaque input ownership.

## Behavior and lifecycle

G08. Positive ordinary/MAX/restore on an eligible root must preserve observed actual
ordinary placement and synthetic draft. MAX with nonzero GTK window-geometry
origin is still explicitly unsupported by current470 policy: record refusal/no
mutation and leave positive GTK MAX capability open rather than forcing origins
zero or enabling it. Minimize/restore remains its separate effect1 meaning,
with family eligibility/paint/input/focus and full-key receipts independently
observed; no scratchpad substitution or inferred atomicity.

G09. When a visible blocked owner is clicked, resolve its current eligible modal,
consume blocked press/release, synthesize no click into B/D and preserve drafts.
An eligible independent peer remains clickable/typeable. Change/retire/reopen
modal relations and verify stable sibling order/current recipients. Hold parent
press then retire modal before release: release may not leak into any newly
eligible window or replacement. Test nested child closure returns eligible
surviving family focus and preserves unrelated C. Fullscreen/pin/input-hole
three-way and device/output-loss combinations remain named future gates.

G10. GtkPopover must create/receive an actual application popup role with current
parent resource and placement/grab serial proof. While grab lives, unrelated
shell/native routes preserve declared popup policy; no shell operation may
silently invoke a modal descendant or bypass the grab. Normal child/popover
closure, opener destruction and replacement must retire old callbacks/roles
and leave eligible application focus. This fixture uses explicit owned-widget
close actions; concurrent184 owns the original Escape proof. Full shell nested
focus/accessibility/IME behavior is separately required, not inferred here.

G11. Journal closed commands with canonical sequence and per-role lifetime tokens;
only bounded fixture operations/known synthetic data are accepted. Command
receipt means toolkit request received, not native effect or presentation success.
Pin all native effects to current full binding/incarnation/output/capability keys;
never replay Unknown effects. Close is an actual controlled GTK user action,
not an advertised native Close capability. Verify both normal owned exit and
server-side empty-client census before plugin unload/parent retirement.

G12. Carry inherited absolute6s stage/3s native transport, real5s held-receipt and
existing normal teardown bounds where those source campaigns apply. No fresh
budget for pointer injection, GTK polling, screenshots, final facts or schema
recovery. Original38 restore/34 fault/52 motion identities/deadlines are not
replaced by new GTK cases. Performance thresholds remain unapproved in budgets;
measurements cannot invent budget acceptance. Root alone serializes native QA.
