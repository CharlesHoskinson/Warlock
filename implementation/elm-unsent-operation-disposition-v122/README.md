V122 prototypes a dedicated local terminal transition for an operation that an
authenticated, exactly correlated preflight-unsent batch certificate proves was
not forwarded. It derives from held V104 and must later be merged with the
separate V121 observation/topology remedy. It implements no native mutation,
native receipt, retry, invented observation, Quint logic or deployment.

The stored literal envelope supplies the original binding, effect protocol and
full intent. The transition requires the exact original Shell issued mapping and
an unresolved Pending operation. It removes only that operation, keeps allocator
watermarks, and records a local refusal. An exact Menu receipt-router mapping may
then be consumed into its original local intent/binding refusal. Taskbar operations
have no Menu mapping. Unrelated Pending/Unknown entries and original router keys
remain intact. A later genuine receipt for the locally retired key is stale.

Matching Unknown operations are deliberately preserved, including real native
Unknown outcomes. Definitive outcomes have already removed the issued mapping and
cannot be overwritten. This is a Pending-only prototype; late uncertain operation
resolution and complete shared recovery/native acceptance remain unqualified.

Certificate validation remains the trusted host-to-controller boundary. Public
typed local transition functions do not authenticate arbitrary callers. Production
must invoke them only after matching the retained full batch, live view/topology,
binding, publication and lease. No raw effect-outcome message is manufactured.
