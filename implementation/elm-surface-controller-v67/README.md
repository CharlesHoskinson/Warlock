# Shared Elm surface controller and presentation renderer V67

One opaque SurfaceController owns the existing Desktop interaction model. Surface derives bar/popup controls from authoritative window/catalog projections and typed local interaction state. Its private control-to-message graph retains native intents inside the controller; readonly presentation contains IDs/names/details/enabled state and DOM locators only. Popup is a presentation-only Elm program using the same decoder/presenter as executable replay tests. It never stores a second window/catalog policy model or executes native effects.

Surface actions carry surface origin, publication and popup lease as canonical decimal strings. The controller resolves only an enabled current control from the claimed current view; arbitrary IDs, stale publications/leases, cross-view IDs, unknown fields/protocols and duplicates are refused. Native integration must independently verify origin against the actual WebKit manager; a web-supplied origin field is insufficient. Every changed controller publication advances its counter. Refresh keeps the logical native popup lease; close/reopen or changed popup context receives a new lease. Matching native dismissal retires the current logical view; an old lease cannot dismiss a replacement.

Presentation rejects malformed/duplicate/overcapacity data. Its watermark survives malformed packets, so older frames cannot revive retired controls; lease regression is rejected. Queued old callbacks are checked again against the current presenter. Duplicate-ID checks use Set. Namespaced DOM IDs preserve field/control/window scopes. Status is user-facing and has source live-region attributes; native AT acceptance remains separate.

Launch choice now closes the logical application popup and retires its outstanding catalog reply before returning native submission effects. SurfaceController orders publication before native sends. The final C bridge must apply popup/grab retirement before forwarding submission; Elm Cmd.batch order is not an ordering guarantee. Desktop now owns picker-focus intents rather than a second Main-only focus reducer. A native dismissal outside-click must not steal application focus. Publication/lease exhaustion disables the controller; native surface retirement/restart policy still needs integration/acceptance.

Accepted component evidence: optimized Popup compile, SurfaceReplay compile31 controller/codec cases and PresentationReplay12 cases. Earlier compiler shadowing failure and intermediate packets are retained. Quint executes9 named cases and1000 samples/40 steps for publication/lease/close-before-submit and the planned native closed-lease barrier. It includes delayed same-lease frames after dismissal and stale frames after a replacement. The native barrier/order portion is a design contract, not implemented C/native refinement or new GUI acceptance. No native multi-view run yet.

Native integration next: V65 popup-window host extended with primary Elm bar and a presentation-only popup WebView; one broker/interaction controller, isolated manager routes, bounded readonly snapshots/control requests, monotonic native publication admission and closed-lease barrier, scoped native widget epochs, popup-configured/focus acknowledgements and close-before-submission. Do not replace the core with independent bar/popup native policy models, reuse retired grabs or let renderer data mutate applications directly.

Current source stage contains only policy/renderer programs and replay drivers; the legacy full-panel Main and unrelated copied build drivers were removed. A native host Main/assets/bridge have not been integrated. Full per-output layout/input/transform, stale native epochs, popup generation/focus/IME, fullscreen/lock, actual combined GUI regression, native AT/human UX, production catalog/search/icons/pins, hardware/GPU/WebGPU/C00 and release remain open. No installed desktop changes, complete requirements or sprints accepted.
