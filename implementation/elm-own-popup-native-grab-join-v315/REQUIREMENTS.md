# Same-callback native XDG grab/root/live-member join

Fresh305 observer derivative compiled against actual rebuilt307, never Core205.
No native action guard, effect capability, serial validation or focus setter is
changed. The original302 GTK02 failure remains open. This is observation-only.

`elm_xdg_grab_join` executes on the original serialized compositor owner thread
in the same canonical private QA runtime. It takes a strong current seat grab,
calls legitimate307 `currentActiveGrab()` and samples every current live native
compositor surface using the public visitor and that same grab's `accepts`.
The getter's optional absence is reported xdgGrab=false; it never becomes an
own-menu exception. Any disagreement or replacement refuses the entire result.

For each actual registered mapped XDG grabbed popup, the query independently
finds exactly one mapped/noninert CPopup with the same native resource in current
OtherViewState. It requires unique bounded membership in a mapped current window
or layer popupHead tree, holds that owner strongly and derives its actual root
resource. Safe layerOwner() must match the identified layer; getT1Owner()/visible()
are not called. Nullable raw XDG parents are preserved for layer-shell popups.
Every serialized surface/parent/root must be in the complete native census.
It reports rootAccepted, actual popup owner, mapped state and all accepted resources, including unmapped or
non-popup surfaces. An extra accepted surface is visible rather than silently
discarded. Unknown/foreign/extra members must still prevent future admission.

Surface identity includes kernel Wayland credentials, resource ID and an opaque
per-query connection ordinal, assigned from actual wl_client objects. Reused
numeric IDs on different native connections stay distinguishable within this
snapshot. Ordinals are not stable across queries or authority tokens. The table
covers only clients with live compositor surfaces and reports its total count;
this is not proof that the host process has a unique connection. Host PID/start,
exact connection and trusted map/lease correspondence still need authentication.

nonwrapping shared query sequence. Invalid/missing resources, duplicate native

native eligibility must be validated independently before any action.
