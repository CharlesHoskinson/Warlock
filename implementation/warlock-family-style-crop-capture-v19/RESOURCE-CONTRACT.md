The opt-in client resource protocol observes the original capture request and
subject under the current kernel-authenticated peer, start identity and native
grant registry. Its three closed operations are state, export release and
producer retirement. Every uint64 identity/charge is a canonical decimal string.

The result independently describes producer charge, export charge and export
transfer. A different current capture cannot be erased or reported as the old
capture. Exact scoped export release is idempotent when already absent. State
and release remain available under lock, expiry or source revocation. Producer
retirement refuses a live export and remains PendingLock while locked. Only
actual owned record/descriptor destruction grants backend zero.

The complete response is allocated before resource mutation and sequence
advancement. Lost responses require a fresh original-target observation; no
capture replay or grant refresh is allowed. Sequence exhaustion retains all
resources without resetting history. Result allocation failures retain the
original resources and counter. The counter resets only with a new actual
plugin/core lifetime, alongside the owning registry.

This protocol does not qualify pixels, enable ordinary capture eligibility,
close local imported descriptors/mappings/readers, settle Broker proofs or
frontend journals, retire a live window incarnation or detach a preview binding.
Core16 remains the exact owning ABI. Plugin19 is inactive until native
qualification; the qualified runtime remains GUI92/native128/core16/plugin18.
