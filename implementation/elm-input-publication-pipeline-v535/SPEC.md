# Publication/input pipeline

EARS: When an established surface packet and native authority scope remain unchanged and no effect requires a new publication, an internal desktop update shall not invalidate an admitted physical release proof by publishing a redundant frame.

EARS: When publication, view generation, input epoch, lease or original proof deadline changes, both initial callback admission and delayed verification shall reject the retired proof. A successful verification shall forward once only.

OpenSpec: Press/release at publication10, followed by a redundant native publication11 and an old DOM callback10, produces zero forwards. Coalescing the identical effectless surface retains publication10 and permits one current callback/verification. If the DOM advances to11, an old native proof10 remains invalid; callback stamps shall not be rewritten.

OpenSpec: Publication changes after callback admission but before verification shall produce zero forwards. Duplicate callbacks cannot repeat a forward. View replacement, later input epoch and original500ms expiry remain independent refusal boundaries.

The Quint model abstracts one physical gesture and one view. Actual native widgets/DOM callback execution and original504 causal acceptance remain separate. Model counters are abstract integers; UInt64 refinement is outside this model. The compound CPU replay uses captured native backend frames, actual compiled Elm controllers and production C guards with synthetic engine identities. It is not new native acceptance.
