# Native policy driver

GUI120 connects the original persistent native JavaScriptCore Elm policy to the
unchanged native-issued outbox in its own private transport context. The creator
owns atomic typed input custody, original epoch stamping, exact native ticket
custody before issuance notification or dispatch, deferred native callbacks and
independent receipt confirmation. Native issuer, original Elm lifecycle, C
dispatcher and original physical/journal/terminal/closure authorities are unchanged.

Ordinary input custody holds at most 1065 items and 16 MiB of serialized wrapped
bytes. Refused batches remain with their producer; the eventual host must stop
polling until admission. Urgent native quarantine bypasses full ordinary custody.
Retaining input runs no policy, issuance or effect. A step performs one action;
callbacks only retain bytes. Native returned events occupy separate custody so
ordinary queue pressure cannot erase them. Their aggregate resource bound and
full-workload progress remain unqualified and required before host activation.

The controlled original owner must have one driver. Constructor faults before
admission cleanly release their own contexts and registry entries. A non-null
handle with an admission error preserves uncertain live custody; callers must
retain it. An uncertain driver cannot normally close or be reconstructed. The
original grant cannot reset. Process-owned RAM survives renderer replacement,
but is not a process-loss journal or accepted crash recovery.

The actual C/JSC campaign uses the original native issuer, Bootstrap, broker,
receipt journal and authenticated synthetic peer. It qualifies input item/byte
refusal, constructor faults, foreign creators/epochs, atomic batches, ticket
stages, independent confirmation, Unknown capture/resource retention, scoped
detachment and strict normal ownership teardown. Explicit Quint custody scenarios
and compiled native guard variants supplement this bounded component evidence.
The custody abstraction does not replace or prove the original lifecycle model.
