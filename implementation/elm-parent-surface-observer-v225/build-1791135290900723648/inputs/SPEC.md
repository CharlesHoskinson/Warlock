# Additive observer wire

Existing elm_parent_input_v1 remains version3 with identical request/event opcode order. New elm_parent_surface_observer_v1 version1 supplies destroy and observe(sequence:uint,pid:int,started:string), event observation(sequence:uint,accepted:uint,packet:string). Persistent client stdin adds `observe PID START`; existing commands stay unchanged. Same Wayland client must own input controller and observer; same UID, one exclusive observer. New client requires both globals. All queries use one caller allocated input sequence shared with original commands, no retry. Rejected query reports accepted:false and {} then existing client exits6/normal resource cleanup. Caller bounded deadline still required.

Client response JSON `{sequence,accepted,scope:'parent-surface-observation',observation:PACKET}`. Successful PACKET exact keys: schema1, sequence, revision(uint32 sample order), parent{pid,started,uid}, controller{pid,started}, target{pid,started}, viewId:uint32nonzero, surfaceId:uint32, surfaceExtent:[width,height], corners:[[x0,y0],[xw,y0],[x0,yh],[xw,yh]], viewportDestination:[width,height], output{id,name,origin:[x,y],logicalExtent:[w,h],modeExtent:[w,h],scale:1|2}, pointer{global:[x,y],focusedPid,focusedStarted,focusedViewId,focusedSurfaceId}. Process start tokens are canonical positive uint64 decimal strings; no timestamp guess. Unfocused PID -1/start'0'/viewId0/resource0 are explicit non-authorizing observations; focusedViewId0 means focus is not the selected root. Strict runner must require expected target PID/start, selected root view ID/resource for gesture proof. Output ID may0. Destination[-1,-1] means buffer-derived logical size per actual Weston struct, not unavailable observation. No field is a target receipt/presentation assertion.

Select exactly one mapped xdg_toplevel view owned requested PID/start+sameUID with no parent_view; roles exclude cursor, subsurface and popup. Multiple roots/views refuse. Require clean owning view transform (conversion asserts clean), valid logical surface extent1..4096, sole enabled output, positive mode and scale1/2, bounded safe output name and finite corner mapping. Query never refreshes/mutates a transform, notifies pointer or changes focus. Corner conversion uses owning weston_coord_surface_to_global and coordinate-space-tagged weston_coord_surface; no placement inferred from client callbacks. Per-probe monotonically increasing view lifetime IDs attach actual view destroy listeners; changed selection/destroyed view never reuses an ID, counter exhaustion refuses. Query revision increments only successful emitted observations; it is a sample sequence, not capability/geometry revision. Runtime/socket/module/process identity proof is the independent wrapper's responsibility.

Before and after gesture, runner compares current parent/module/PID-start/output/view/extent/mapping and focused recipient proof. Observation plus original done accepted never replaces actual nested client-local input event. No native qualification until new exact parent module/client builds are adopted under root-controlled private host.
