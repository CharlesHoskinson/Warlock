# Paged immutable retirement archive — proposed schema7

This is a design amendment and executable CPU prototype, not an implementation or full S15 acceptance. Frozen V608/V624 semantics and their64-entry capacities remain historical. Production stores, coordinator, frontend, native producer and shared requirements are unchanged.

V608 keeps full terminal receipts in `settlementHistory` and full Prepared/Released evidence in `releases`; both arrays are limited to64 and all storage to1MiB. `begin` refuses once either historical array is full. V624 adds a64-certificate sidecar containing one latest delivery attempt per released record. Raising these array caps leaves lifetime-sized validation, rewrites and startup memory. Schema7 instead separates bounded live work from disk-scaled immutable evidence and disk-scaled lookup indexes.

## Storage layout and bounds

Private UID-owned0700 `archive-v7/` contains immutable0600 event pages, immutable copy-on-write index pages, generation manifests, `CURRENT` and a version/initialization marker. Page names include generation and SHA256; all relative names obey a fixed grammar. An event page is at most64KiB, contains at most32 envelopes and never splits an envelope. A canonical full envelope is bounded at16KiB; larger input refuses before admission. An index page is at most16KiB and contains at most128 entries. Max supported index depth16 gives a concrete structural bound; depth or uint64 generation/offset exhaustion refuses rather than wrapping. Root metadata is at most16KiB and references page/index roots, committed event ordinal, migration root and native lifetime; it never contains a lifetime-sized list of page names.

The append archive is a persistent tree of page references, not an ever-growing root array. Event lookup uses a persistent B+tree keyed by full origin identity `(native lifetime, session, frontend, effect protocol, exact complete intent)`. Stored keys include canonical bytes or a collision-resolving full-key reference; digest equality alone never authorizes disposition. Secondary roots index per-binding independent request/generation maxima, retirement proof sequence maxima, origin→first immutable release anchor, origin→terminal receipt, and origin→latest delivery certificate. Cache at most64 index pages; eviction discards cache copies only. Iterators read one bounded page and carry a generation/path cursor. Merkle hashes detect mutation relative to a trusted root, not malicious same-UID rollback; authenticated persistent anti-rollback is an independent threat-model decision.

Live unresolved admissions remain bounded64, one in-flight mutation transaction per writer, native request queue16, reconciliation cohort at most64 records and one announced proof scope at a time. Historical discovery is cursor-paged; it does not materialize all records, retirement scopes, release certificates or watermarks. A cohort releases only its matching full origins; progress cursor advances after durable disposition/delivery attestation as required, never evicts an unprocessed origin. Unresolved exhaustion remains fail-closed. Infinite unresolved records are not promised.

Each immutable event conserves exact full original bytes/typed record: Admission/Unknown, definitive native receipt, Prepared with exact proof+accepted join, Released with original anchor, and DeliveryAttestation with original anchor plus current exact proof/join. Unknown stays Unknown; definitive receipts are distinct truth, never inferred from absence. Delivery attempts append; the mutable latest-certificate index points to one attempt but older evidence remains reachable through the archive. Original release proof is never rebound to a new frontend.

## Commit and recovery protocol

Hold verified `archive-writer-v7.lock` first, then `host-writer.lock` guarding admissions, in that exact order shared by Python and C. A daemon singleton lock is separate and never substituted for the per-operation shared archive lock. Acquire nonblocking; contention refuses bounded work rather than blocking the UI indefinitely. No native request, bind handshake or output wait occurs while holding these filesystem locks. Stage startup snapshot/proofs before announcing attached; release all storage locks before the asynchronous C bind. This avoids the separate618 startup race.

For a transaction: validate exact inputs/current generation; reserve page/index/manifest and worst-case completion space; write new bounded event/index pages to exclusive temporary names; fsync each file; rename to immutable names; fsync every containing directory, including newly created shards; write and fsync the new generation manifest; rename its namespace entry; fsync that directory; write/fsync temporary CURRENT; atomically rename CURRENT; fsync archive root. Only then expose the new root, send ACK, or permit a C effect. The manifest/hash tree must reference only fully file- and directory-synchronized pages. An uncertain call poisons the current writer; no continued success frame is manufactured.

A release first commits Prepared and its original exact proof/join. Then unlink exactly its admission and fsync the admission directory, even when absence was already visible. Then append Released and commit the root before frontend release/attestation exposure. A terminal receipt is conserved in a root commit before its live admission is removed; the final absence barrier remains required. Counters and per-binding watermark updates are committed atomically with Admission before native execution. A second allocation below either independent maximum is refused even if its record is entirely cold.

After process restart, a renamed CURRENT/manifest may be visible without its final directory fsync. Verify its bounded newly published transaction page closure, committed predecessor-root anchor and ownership, then fsync the archive root before treating recovered Prepared as removal permission or exposing recovered Released/delivery data. Older immutable subtree pages are verified by hash/type/ownership when traversed; a bounded background scrub can inspect all evidence without loading it at once. No queried record, watermark, proof or key-absence result is exposed until its complete authenticated index path and referenced envelope validate. Startup must not scan all historical events merely to load the hot cache. A corrupt or partially durable visible candidate fails closed; do not silently choose an older root that would lower watermarks or discard uncertain admissions. Restart must keep uncertain reservations blocked until an explicit validated recovery path completes. Power loss may lose unsynchronized namespace entries; recover from the last valid committed root and pending native admissions, producing Unknown without replaying any old intent. The model distinguishes surviving-visible process restart from power-loss rollback.

Capacity/ENOSPC/inode/FD failure refuses before a new effect when Admission and its completion reservation cannot be committed. Preallocation covers worst-case successful completion metadata, not a guarantee that storage will remain healthy. A later I/O failure leaves a persisted live Unknown/Prepared reservation and poisons the writer; no outcome or release is guessed. Completed history consumes disk proportional to retained evidence rather than64 lifetime slots. Archive quota is a configured disk/inode budget; reaching it requires safe explicit expansion/export policy and never eviction of original evidence. Automatic lifetime resets to evade exhaustion are forbidden.

## Compaction, late C admissions and migration

Primary evidence pages are retained indefinitely. Compaction rebuilds secondary indexes/tree shape in bounded streaming passes, preserves all canonical events/full origins/anchors/watermarks and publishes an equivalent generation through the same fsync chain. Only unreferenced temporary/index pages may be collected, after the replacement root is durable and after all reader-generation pins are gone. Event pages, predecessor bytes and reachable migration anchors are not garbage-collected. This preserves evidence without rewriting every historical record; archival retention/export is a future explicit policy.

The paired C admission producer must consult the authoritative paged origin/watermark/retired-scope indexes under the same locks before submitting an effect or writing admission. Exact old Released/terminal keys cannot resurrect; late existing admissions for those keys are validated, removed and directory-synchronized after the restart root barrier. A different late key in a retired scope becomes a separately archived Unknown and remains reserved until its own fresh correlated join; it is not deleted merely because its scope has another released origin. A retired grant remains a native authorization decision, not a disk lookup guess. Compatibility with the current C reader is a mandatory implementation gate, not supplied by this prototype.

Migration is a locked, resumable transaction with schema/version, instance/lifetime, exact predecessor names/bytes/hashes, old marker state and source semantic version. Freeze v3–v6 and V624 sidecar bytes, include all live entries, settled/latest definitive records, Prepared/Released anchors, bootstrap/migration proofs, every allocation/native replay watermark and all current delivery certificates. Stream strict duplicate-key/type validation with bounded readers; no imported record is dropped or silently normalized to Committed. Prepared remains blocked and completes only after reestablished directory barriers. Recheck predecessor hashes under locks before publishing the new root/version marker, fsync both namespace barriers, then activate only the paired schema7 C/Python producers. A crash before activation resumes validation/import; old schema producers cannot write after activation. Retain originals permanently; missing/changed predecessor after an initialization marker fails closed. Rollback to an old producer after schema7 admissions is forbidden unless an independently reviewed lossless downgrade transaction exists.

## Concrete implementation sequence and acceptance

1. Build exact full-record envelope/parser, private directory traversal and bounded page writer in fresh source, with ownership/symlink/hardlink/duplicate-key/size fault tests.
2. Implement transactional page→index→manifest→CURRENT publication, crash injection after every write/fsync/rename/unlink, process restart-visible recovery, ENOSPC/shortwrite/fsync failure and frozen-predecessor migration. Power-loss experiments require an independent storage fault harness; killing a process alone is not power loss.
3. Implement bounded index/cache/cursor paths and run >10,000 terminal/release/delivery cycles in one native lifetime, assert stable resident memory, bounded page reads/writes per append and immutable byte conservation; measure compaction cost and restart latency separately. No numerical performance budget is accepted without hardware baselines.
4. Pair schema7 native C admission/grant reader with Python writer; verify identical keys, locking/order, independent counter maxima, late exact/different admissions, allocation wrap refusal and startup/bind behavior. Native grant-history arrays/request watermarks and frontend64 history slots also require their own scalable/paged protocol amendment; schema7 storage alone does not solve full S15.
5. Integrate cursor/proof-ready/accepted-frontier delivery without rebinding old release proofs; test actual C/native authenticated replies and retained frontend views across restart/lost delivery. Run the unchanged combined user-flow acceptance and hardware/accessibility requirements on one coherent tuple.

Full S15 remains unaccepted until actual filesystem, paired C/coordinator/frontend and native campaigns pass. The prototype's finite symbolic keys and small hot/page bounds establish model sensitivity/order/conservation, not unbounded scalability, full bytes, real locks, hash/index algorithms or storage durability.
