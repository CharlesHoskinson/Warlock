# Scoped native popup readiness and focus acknowledgements

This derivative retains one authoritative Elm Desktop controller and presentation-only popup, with atomic close-before-submit commits. Native popup callbacks now own closure-lifetime PopupScope data with lease and wrapper identity. Retired lease callbacks cannot dismiss/configure a replacement even when the widget pointer matches; direct production-function tests exercise this case before any GTK mutation. Pending focus and issued acknowledgements are retired on closure or publication change.

The host admits popup callbacks and issues focus only after a matching configure notification, completed native grab and current publication/lease presentation acknowledgement. The popup adapter acknowledges after two animation frames and verifies the actual Elm root publication/lease. Focus packets carry the same stamps; the adapter verifies current DOM scope, target existence and enabled state, then acknowledges the actual focused IDs. Native acknowledgements must match the active lease/publication and issued target set. Primary bar focus packets also check current DOM publication/lease. This is mechanical render/focus synchronization; policy remains in Elm.

GTK3 configure-event was not emitted in V73/V74. The V75/V76 moved-to-rect route received null rectangles and rejected them. Both failures and normal cleanup are preserved without extending deadlines. Installed gtk-layer-shell0.10.1 source emits this signal from xdg_popup.configure with null rectangles, then acknowledges the later xdg_surface.configure. V77 accepts a lease-owned notification with optional geometry, and separately requires completed seat grab. Native protocol audit verifies exact xdg_popup rectangles and matching xdg_surface configure/ack before focus issue. No GDK allocation is relabeled authoritative compositor geometry.
