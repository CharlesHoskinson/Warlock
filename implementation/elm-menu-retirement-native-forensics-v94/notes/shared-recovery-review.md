Read-only review of V308 HANDOFF and final production V305 sources, alongside root-owned V99 review. This packet implements no recovery transport.

V305 `native/shared-host.c:83` validates the exact view-commit projection, topology revision, live view ID/generation, popup/focus scopes, and full translated surface batch. Its first `surface_preflight` at line105 is before journal admission. A rejection there can certify this invocation unsent only when the submitted envelope is parseable and can be correlated exactly. Malformed input should fail closed without inventing a partial batch identity.

`native/host.c:550` performs a second actual surface preflight. Its failure is still before `admission_batch`; that is the precise second safe hook for an unsent certificate. `host.c:553` calls `admission_batch`, defined in `host-journal.h:209`. It selects at most one window-effect, verifies full authority binding, then writes its admission record. Failed durable write cannot inherit preflight's guarantee. The current shared `refuse` label logs the same commit-preflight text for preflight and admission failure. `popup_open` failure after line572 also follows admission and must retain journal reconciliation even though the queue loop has not run. The wrapper currently logs view-commit after returning from surface_receive regardless of whether actual admission succeeded: that log is not an acknowledgement.

Refactor the inner call to return a typed disposition, with the original view envelope retained across translation. Emit an authenticated controller event correlated to original topology revision, exact live view scope ID/generation, publication, lease, binding, and the entire ordered request batch. Distinguish preflight-unsent, admitted, and admission-uncertain. A popup owner may already be logically cleared when the certificate arrives; authenticate the scope stored with the submitted batch against live topology, not merely current popupOwner. A replaced/retired scope cannot reauthorize the old batch.

`src/OutputController.elm` currently exposes Renderer/Dismiss/Reflow routing. `nativePopup` checks live scope and current popup owner, appropriate for popup callbacks but insufficient for a delayed rejected-publication receipt after logical dismissal. Add a separately strict batch-disposition event with a bounded submitted-publication record, consumed at most once; reject wrong scope, topology generation, publication, lease, binding, batch contents and stale old correlations. The shared primary allocator must remain the sole allocator.

`src/Shell.elm` stores expected, geometryExpected, geometryAttachExpected, notificationQueued, deferNotifications and issued operation identities. notificationRefresh waits while any expected slot exists. Only an exact preflight-unsent certificate may clear matching observation slots, invalidate old IDs, retain the dirty bit and request fresh observations under fresh IDs after popup reconciliation. Do not clear unrelated slots or erase operation records. Issue no automatic effect replay. Matching unsent effects require a distinct local terminal disposition; journal-admitted/uncertain effects must follow schema5 recover-intent and effect-outcome guards, preserving issued binding/protocol/full intent and Pending/Unknown ledger entries.

Acceptance must include observation-only, operation-only and mixed batches, both preflight boundaries, admission failures and post-admission popup failures. Native retirement scenario10 must pass unchanged with its absolute six-second deadline on one combined reviewed tuple.
