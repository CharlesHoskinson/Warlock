# Single-controller Elm bar and presentation-only native popup

The primary WebKit view runs Main/SurfaceController and owns the one Desktop model. A second WebKit view runs Popup/Presentation only: readonly control snapshots and current scoped UI callbacks, with no catalog/window reducer or direct native effects. The normal layer bar reserves48 pixels and requests no keyboard focus. A lease-owned GTK popup wrapper supplies actual layer-parent xdg_popup/grab; its presentation engine survives close/reopen.

Main emits one surface-commit containing the current readonly frame, bounded native requests and DOM focus intents. C preflights the entire commit before surface/queue mutations, then synchronously retires the popup/grab before forwarding native requests. This avoids relying on Elm Cmd.batch order. Individual controls remain4KiB, readonly/commit envelopes1MiB, and pending+active requests16. The trusted broker retains native authority and GIO command resolution. Popup manager traffic accepts only presentation readiness or an enabled current popup callback; it cannot send native requests/commits. Callback origin is checked against the actual manager before the controller checks its private graph.

Native publication/lease counters retain full uint64 precision as strings. Older publications, lease regressions and delayed open frames at or below the native closed-lease barrier are refused. Each native lease creates a fresh popup wrapper; callbacks from a retired wrapper cannot close a replacement. Escape is handled by the current presentation callback and ignores composing events in source, replacing the raw GTK Escape scaffold. This source rule is not native composing-IME acceptance.
