# Prepared post-close window selection

This isolated V58 derivative corrects a demonstrated UI dependency race. Native popup destruction restores focus under the pointer. That valid native change increments action facts after the immutable open-menu provider was captured. Immediate dispatch then fails the exact native dependency guard. The native guard, normal focus behavior, and existing minimize/restore policy remain authoritative and unchanged.

Stage 1 validates the exact Menu.Activate identity, binding, selected enabled row and frozen provider against admitted Shell state. The local Menu reducer reserves its existing local Pending intent; no native Effects request or generation is allocated and ReceiptRouter remains unchanged. One bounded prepared slot retains that immutable local dispatch, provider, original admitted legacy window list, geometry observations/capabilities, native binding and presentation scope. It dismisses the popup and sends fresh legacy and, where supported, geometry observation requests in the same closed surface commit. The existing host destroys/fences the native popup before forwarding those observations. A canonical monotonic token arms a two-second expiry. Token exhaustion refuses without evicting operations.

Stage 2 admits each observation only when the actual Shell decoder consumes that slot's exact request ID and binding. Stale, invalid, wrong-stream and unsolicited frames cannot finish the slot. During this batch, Shell retains authenticated notification dirtiness without replacing its correlation IDs. Native binding/frontend, target lifetime/incarnation, canonical root, output/provider identity, geometry capability set, all legacy window records and all geometry window records/input blocking must remain identical; only focus and observation revisions/sequences may advance. Revisions cannot regress. Changed workspace/output/workarea/ownership/state/constraints/peers/action applicability cancel the slot. The fresh producer must offer the same typed action enabled.

After both required observations complete, stage 2 uses the fresh operation namespace's exact native context to allocate one native request/generation through the existing Shell engine. ReceiptRouter.registerPrepared preserves the original local dispatch binding and associates it with the complete newly issued native key. It does not reinterpret an old sent command or retry a refused one. The prepared slot clears atomically with registration and dispatch. An independently accepted receipt remains necessary to settle the existing Menu Pending entry; Unknown and unrelated original full-key mappings survive unchanged.

Expiry, explicit matching dismissal/invalidation, output retirement, authority change, disconnect, incompatible observation or allocation/registration failure cancels only the unsent prepared local entry with an exact local Refusal and requires a fresh user selection. Unsent preparation is canceled before disconnect marks actually sent operations Unknown. Notifications resume through the existing dirty-bit logic; no effect is replayed. Ordinary taskbar mutation and new menu opening are refused while the one prepared slot exists. Existing unrelated receipts still route and settle normally.

Interfaces: MenuBridge.preparedSnapshot exposes token, legacy/optional geometry request IDs and readiness bits; expirePrepared token rejects stale timers; advancePrepared receives the actual Shell message plus previous/next Shell states after update. Shell.Effect.ArmPrepared routes through Main's existing task timer to TaskbarShell.ExpirePrepared. Main publishes observation requests only with the closed frame. A prepared token alone cannot authenticate a native frame or authorize a transport operation.

Required independent CPU acceptance: focus-only revision3→4 creates no native intent before both post-close observations, then emits one fresh-context command; reverse response order; stale IDs/binding, invalid schema, target/output/owner/workarea/capability/state/blocked changes, expiry/stale timer/explicit cancellation/disconnect, reservation/bar guards, preserved unrelated Pending/Unknown and exact full-key receipt correlation. Native qualification must repeat the real MAX→Minimize→Restore→Restore Geometry physical sequence without widening its six-second transition deadline. Original 78/53/21 immediate-dispatch fixtures remain unchanged and separately scoped. No new Quint logic is introduced; geometry model type approval remains pending.
