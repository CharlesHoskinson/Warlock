# Nonzero XDG window geometry: proposed source contract

This packet establishes conversion facts and identifies the missing GTK proof. It does not authorize a nonzero-origin capability, change the zero-origin profile, or qualify native rendering/input. No policy, Quint, ABI, installed configuration, or native desktop changes are included.

## Coordinate names and authoritative conversions

`L` is the layout target's logical rectangle; `V` is its optional visual rectangle; `R` is the window's real goal rectangle; `G` is the committed XDG window geometry in wl_surface-local logical coordinates; `g = G.pos`; `C` is the integer xdg_toplevel configure size. These names must stay distinct: CWindow::logicalBox() returns the full decorated bounding box, not target.position(). The main surfaceLogicalBox() follows the current geometric rectangle. A wl_surface buffer, XDG window geometry, layout target, and decorated bounding box are different objects.

The actual owning conversion gives the following result, including when `g` is nonzero:

* Ordinary floating placement: target setPositionGlobal rounds the target boxes; WindowTarget assigns `R = L`. It does not add or subtract `g` and does not subtract decoration reserves. Restore must retain the recorded ordinary logical rectangle and independently recorded real rectangle; saved visual data cannot be substituted for the logical rectangle. The existing authority refuses a restore whose projected real rectangle differs from the saved real rectangle.
* Decorated default MAX: round target boxes using the paired CBox operation; choose nonempty `V`, otherwise `L`; `R.pos = selected.pos + reserved.topLeft`, `R.size = selected.size - reserved.topLeft - reserved.bottomRight`. Reservations come from the compositor decoration positioner. They are not an alias for XDG geometry origin. The MAX branch has no extra `g` transform.
* Wayland configure: realToReportSize returns nonnegative real goal dimensions. setSize stores those dimensions; sendConfigure converts to protocol integers. For positive supported dimensions `C = floor(R.size)`. The expected size-ACK entry also records floor(R.size). Neither step applies `g` or multiplies by monitor scale. Physical buffer/pixel sizes and viewport mapping require separate conversion.
* Normalized layout constraints: actual layoutMinSize/layoutMaxSize add the current geometry origin per axis only when the corresponding raw limit is greater than 1. CWindow normalization/rules further modify those values (notably max below 5 becomes unlimited). The producer's published normalized layout bounds have already incorporated this origin wherever the owning method does so. Do not add it again, and do not reconstruct raw protocol limits from normalized bounds. Raw hints constrain `C`; normalized layout hints constrain the real/layout size used by this owning profile. This is characterization of this core, not a claim that every normalization conforms to XDG semantics.

CBox rounding must use the owning paired implementation, not independently round widths/heights. The real compiled V166 characterization observed `[-10.25,20.25,100.25,80.25]` becoming `[-10,20,100,81]`; reserves `[1,2]/[3,4]` produce `R=[-9,22,96,75]`. Target.round and MAX.round must be preserved in their actual order. Scale 2 does not turn configure `[96,75]` into `[192,150]`.

## Rendering and pointer compatibility remains open

Main rendering starts with the current real position/size (plus workspace render offset) in Renderer.cpp. ElementRenderer's code to crop/adjust main-surface UVs using XDG geometry is commented out, with an explicit note that it does not work and historically relies on always setting MAXIMIZED. Core89's XDG map callback removed that forced MAX state. Existing viewport, undersized-surface and texture expansion paths can still alter the mapping. Thus neither `surface global origin = R.pos - g` nor `painted XDG origin = R.pos` has been demonstrated for this renderer.

The captured hit tester does explicitly calculate main/subsurface local coordinates as `pointerGlobal - windowGoalPosition - subsurfaceOffset + g`. Its fallback for a surface not found in the tree omits `g`. Popup handling is separate. A desired consistent surface transform would place wl_surface-local `g` at the visible window origin, making local pointer coordinates agree with pixels, but this packet does not claim the existing renderer supplies it. Adding `g` to configure or real placement to compensate would change the established native conversion and can double-apply the origin in normalized hints/input.

The main rendering source is an owning source trace, captured by this packet; Window.cpp/XDGShell.cpp are exact immutable core89 compile captures. ViewHitTester.cpp is the immutable V23 compiled capture inherited by this lane, whose origin method is shown explicitly. Archive metadata names/hash the corresponding objects but do not by themselves prove that every uncaptured renderer source byte was used to compile an object. Close that source/object provenance gate before modifying or claiming the rendering path. The commented renderer block is a concrete source-level risk, not an observed GTK failure.

## Proposed extension inputs and admission rules

A future pure projection may permit finite nonzero `g` without changing the above `L/V -> R -> C` arithmetic, only after independent review and native proof. Keep the current 402/407 exclusion until then. The existing helper receives the origin, raw/normalized bounds, reserves, scale and placement; this is adequate for arithmetic but insufficient for rendered/input compatibility.

For a coherent nonzero-origin profile add the complete committed XDG rectangle (origin AND dimensions), an explicit geometry/surface-commit dependency version, committed surface logical extent, buffer extent/scale/transform, viewport source/destination, and the relevant rendering policy flags. Preserve the separation between a configure request, ACK, and the buffer/geometry commit that actually adopts it. A pre-effect snapshot's geometry can change on the ensuing client commit. Capability/revision fingerprints must include geometry dimensions and all conversion dependencies, not just origin/raw limits/reserves/scale. Version and validate the profile in the adapter/Elm decoder rather than silently changing `wayland-zero-origin-v1` meaning.

Layout rules, source-normalized bounds, decoration reserves, workarea/owner scope and the saved ordinary placement retain their existing exact dependencies. Revalidate the complete profile before mutation and after synchronous callbacks, and bind presentation evidence to the later client commit. If a client changes geometry after MAX or before restore, cancel/reject an incompatible operation rather than recapture the original, retry an effect, or claim a definitive result based only on pending configure size. Saved placement lifespan remains native lifetime/incarnation, not peer session. Reconnect must not convert a saved ordinary real rectangle into an XDG surface buffer rectangle.

## Required native fixture assertions

Use both an actual GTK CSD window and a controlled XDG client. Capture the real protocol `set_window_geometry`, raw hints, configure serial/state/dimensions, ACK serial, committed surface/buffer/viewport state, exact native logical/real goal/current rectangles, and physical parent pointer delivery to the bound recipient. A zero-origin client remains the control.

1. Test positive and negative/asymmetric geometry origins with a buffer larger than the XDG geometry. Place colored markers at known surface-local coordinates including the XDG origin. Pixels must establish where each marker is painted, not infer it from rectangle metadata. Probe the same marker through physical parent input and compare its actual local coordinates; decoration/content/shadow boundaries must agree.
2. MAX with border/reserves and reserved bar/workarea must produce the actual rounded `R` and integer `C`, client MAX state, exact ACK-selected buffer and visible marker/pixel boundaries. Test scale 1 and 2 plus viewport/buffer-scale variants; configure sizes remain logical. Distinguish toolkit CSD from compositor reserves.
3. Ordinary restore must recover the exact original logical and real placement, without adding/subtracting `g` twice, losing CSD margins, shifting on repeated cycles, or recentering. Include different logical/visual boxes, negative/fractional target origins and asymmetric reservations. Unsupported combinations must stay disabled.
4. Change geometry and/or viewport on the commit adopting a configure; demonstrate dependency invalidation/fresh capabilities. Include late old ACK/commit, target retirement and same-title replacement, and monitor/workarea/rule changes. Preserve original native 3s, receipt 5s and whole-scenario 6s deadlines and full-key Pending/Unknown behavior. No observer effect or effect replay is allowed.

A helper arithmetic pass cannot close the renderer/input or client-commit gates. The next smallest safe step is immutable renderer/object provenance plus an instrumented nonzero-origin GTK/XDG fixture on the exact owning tuple, followed by a separately reviewed transform/helper extension if the observations support it.
