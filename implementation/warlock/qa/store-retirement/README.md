# Store acquisition and retirement controls

The shipping Haskell Store registers `Acquiring` before calling native acquisition. Only an explicit negative syscall receipt (or rejected filename before the syscall) records `Closed` without a close. A generic exception or failed publication remains uncertain and seals subsequent work through the same `runOwned` gate.

`retireStoreOwnerIfSettled`, `retireCatalogIfSettled` and `retirePinStoreIfSettled` acquire the existing operation gate without waiting, seal it and return true only for affirmatively closed retained records. They never initiate or retry physical close. Busy returns false. The caller still owns its original deadline and aggregate retirement verdict; a later observation cannot establish that an earlier deadline was met.

The actual production module exports no QA entry or fault hook. Root materializes isolated copies for development checks. `AcquisitionFailureControls.hs` is appended unchanged, with an export addition only, to both the original and changed Store source. Its simulated acquisition event raises a generic exception before returning a value: the old code falsely reports retirement true with no retained record; the new code reports false with one retained record. These counters are not real descriptor cleanup proof.

The separate `StoreRetirement.overlay.patch` is applied only to an isolated copy. Its entry covers empty/closed/busy/open/closing/uncertain state, no second close, acquisition/publication faults, scan exceptions and an actual negative `openat` in a fresh private directory. The Cabal component here builds this QA copy, never a shipping library variant. Use the existing Root-owned protected QA launcher, retained source manifests and fixture roots; do not apply the overlay to production.

`store-retirement.qnt` models two single-use slots with an independent possible-ownership oracle. Fourteen named traces and 10,000 seeded forty-step samples found no counterexample. The uniform run reached the successful two-close witness zero times and its coverage qualification remains failed. `store-retirement-guided.qnt` separately restricts existing actions to a positive path, without changing state assignments or safety; one twenty-step trace reaches that witness. This combination is bounded safety and positive reachability evidence, not exhaustive verification, scheduler timing, physical cleanup or legacy force-retirement proof.

The [retained component report](../evidence/store-retirement-20261102/report.json) records exact old/new sources, ordinary production regressions, all failed and successful observations, actual toolchain/dependency hashes and the current Omarchy trial. Original ARC002, persistent process/callback/provider ownership, native GUI, AT/IME, performance/resource and release obligations remain separate.
