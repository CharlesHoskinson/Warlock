# Release provenance review: bounded model correspondence

Original ELM-DEL-005 / delivery-005 requires all shipped components and applicable notices accounted for, with SBOM, notices and reviewed redistribution dispositions for compiler, packages, host, native libraries and assets. This one-component abstraction addresses only the identity/disposition part, not the full original oracle.

`release-provenance.qnt` models actual and pinned source/notice identity classes (0 missing, 1 pinned, 2 different), whether a notice is listed, binary reviewed/incomplete disposition and applicability, a last decision with observed values, and action flags. Independent source, notice, disposition and applicability mutations, restoration and review can interleave. `safety` requires an accepted decision's observed evidence to match and be complete. Review is an atomic *observation abstraction*: the actual function reads files and catalog at different times, and the model does not establish a coherent snapshot under mutation during review. Mutation after review leaves the old decision stale; `staleDecisionTest` demonstrates this explicitly. No conclusion about production TOCTOU safety follows. One notice and one component abstract multiple entries; inventory coverage, SBOM, mapping, path resolution, malformed catalogs, archive and build steps are outside the model. Reviewed status abstracts nonempty evidence; it does not establish legal authority, cryptographic collision resistance, OS behavior, source-to-binary correspondence or native desktop correctness.
