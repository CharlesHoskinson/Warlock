# ELM-DEL-005 packaging model

Original `delivery-005` asks that all shipped components and applicable notices be accounted for. This model describes a **desired boundary**, not a proof that the builder meets it. A historical synthetic execution exposed a mismatch, and a later receipt-aware probe exercises the fix below. No release, native, legal, or exhaustive correctness acceptance follows.

## Correspondence and scope

Current source snapshot (SHA-256): `adapter/release_builder.py` `640b47a214286ca9ec3fcda74d98d895610202befd49e9b8bcce51706e9a9919`; `adapter/release_compliance.py` `51f7557b4a741106f3b7ffc16df09ae86aa90ca580578ea40a1ff175d4a48964`. Paths relative to `implementation/warlock`. `check_compliance_lock` (318) rejects missing pinned catalogs/provenance; `verify` (300) compares locked inputs; `build` (458) copies/builds, calls `package_compliance` (358), verifies again, produces manifest/tar and calls `audit_archive` (406) with the receipt (552), followed by another `verify` (553). `package_compliance` reviews actual pre-metadata inventory, writes and checks generated metadata, then returns an immutable `ComplianceReceipt` (347) holding reviewed inventory identities and metadata digests. `audit_archive` checks safe inventory, requires a receipt when compliance metadata exists, compares inventory and metadata to the receipt, then checks tar and manifest against the current payload. The three-argument generic audit is supported only without compliance metadata and still checks safe inventory.

The single record holds a phase and opaque revision identities for lock, input, payload, accepted review, manifest and archive, blockers, metadata integrity, output and audit outcome. Independent input/payload/metadata and blocker mutations can occur between phases. `recover` abstracts a fresh, repaired candidate and new lock, not an automatic legal review or production cleanup. Successful audit requires current input, payload, review, manifest and archive identities to agree and exact metadata, with no old lock, unknown or unmapped component. `successSafe` and `oldLockBeforeOutput` express the desired invariants; 14 separately selected tests witness all phases, old/stale/unknown/unmapped refusal, recovery and post-review, post-archive, late-input and metadata interleavings. The test `happyTest` reaches audited success; no sampled-trace reachability inference substitutes for that witness.

The model requires final agreement with the review and a final input check. The implementation now checks receipt identities in audit and checks inputs after audit, but the model's single `audit` action abstracts those separate operations: it cannot establish atomicity across them. The model abstracts component mapping and metadata as booleans, copy/build as a stage, hash identity as collision-free opaque classes, and mutations within an individual function as outside its scope. It assumes exclusive private output during the point-in-time checks; later writes, publication integrity, concurrent input or payload changes between checks, crash recovery, legal authority, filesystem/OS semantics, compiler behavior and GUI/native behavior are not proven. Identity equality abstracts a set of file hashes, not equality of whole archives to inputs. Unknown and unmapped transitions are idealized blockers; the concrete correspondence check exercises specific reviewed-file identities, not arbitrary changes in legal disposition.
