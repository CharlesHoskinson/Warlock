# Actual initial current_build.py review

Source-only review, no import or execution, no QA. Reviewed first public root-authored implementation while selected current recipe work is in progress. Status: concrete fixes requested before protected build.

1. **Compiler inputs must be the locked bytes.** build currently symlinks workspace/src to live PRODUCT/src. Before/after source hashing cannot exclude a changed-and-restored input during compiler read. Copy every locked source into workspace, preserving relative location, and check each destination against its locked hash before compiler launch. The copied elm.json and cache files also need destination hash checks; currently only original inputs are checked. Private staged source/cache inventories should agree with the lock before compile. Recheck staged source/elm.json after compilation. Do not require cache to remain byte-identical after Elm compiles: the private compiler cache may legitimately acquire derived artifacts; distinguish initial locked inputs from generated cache state.

2. **Validate actual command contract.** validate_report checks three ordered module labels and exit=0, but ignores argv/cwd/environment/timedOut and the acceptance booleans. Construct expected argv using locked compiler, exact module, optimize flag and selected report-directory assets target; expected cwd must be its workspace; expected environment must bind that report directory's private ELM_HOME and the fixed policy. Reject any mismatching row and any timedOut=true. Require nativeAcceptance and releaseAccepted false. The explicit report SHA is necessary but does not replace schema/semantic validation. Record separate requirementAccepted/fullReleaseAccepted flags only if used consistently; never infer those claims from build success.

3. **Retain partial failure evidence.** report.outputs is only populated after all three roots succeed. In finally/error handling, hash any files actually emitted under assets and preserve incomplete inventory with passed=false. Append command intent before calling subprocess, then update exit/timeout/log hashes. An OSError before subprocess starts should retain attempted argv/cwd/env and launch error, not omit the command. Current timeout handling does preserve partial stdout/stderr; retain it.

Additional bounded improvement: include interpreter executable hash and protected-launcher source identities as receipt provenance, while explicitly disclaiming full dynamic tool/runtime closure. Original full release builder handles that larger closure. Report should be initialized on disk before first command if retaining provenance after external kill is part of its claim; atomic replacement of only the new run's report does not overwrite historical evidence.

Meaningful checks after fixes: real three-root protected build; validate real receipt; independent second frontend output comparison if reproducibility is claimed; disposable-copy negative tests for a changed/added/removed source, changed static/cache/compiler, altered asset, duplicate/missing root, wrong command/compiler/output path, wrong private ELM_HOME, true acceptance flag, timeout+exit0 inconsistency, altered log, stale lock/recipe and path/symlink. Mutation test code must call actual production validators, not duplicate their logic. No native or release acceptance and no unchanged native rerun.

The minimal capture/build/validate structure is appropriate. Complete equality against capture catches current inventory changes and recipe drift, JSON duplicate keys are refused, source/static inventory enumeration refuses symlinks and special files, generated assets are excluded only by exact relative filename, roots are checked as an ordered list, and output inventory/hash validation is materially stronger than previous wrappers. Keep strict release/native validators untouched.
