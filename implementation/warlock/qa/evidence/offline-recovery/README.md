# Offline predecessor recovery

ELM-UI-020 `offline-recovery`: a documented standalone command selects retained
predecessor resources and a coherent compatible preference copy after a host
failure. Guidance dismissal never gates recovery. No compositor restart,
network access, host IPC or window-effect replay is involved.

The current production profile/CLI passes 40 component observations, including
actual candidate process failure, missing candidate resources, incompatible
candidate preferences, copied settings/shortcut choices/pins/motion, active-host
exclusion, inherited lock after supervisor death, pre-rename preservation and
post-rename Unknown reconciliation. Quint passed ten explicitly selected tests,
1,000 sampled safety runs and five positive reachability witnesses. The model
abstracts file hashes, POSIX semantics, process identifiers and native rendering;
the production tests exercise those corresponding file/process boundaries.

The protected native drill passes 47 checks with normal owned cleanup. Actual
keyboard dismisses help before the candidate host unexpectedly exits. The
standalone rollback CLI then selects a different retained Warlock Elm build,
which reads the exact four prior preference files, presents measured native
controls and accepts keyboard dismissal to the original application recipient.
Application incarnation identities and the actual application fixture remain
connected throughout. The core/plugin/Aquamarine tuple is unchanged. The native
predecessor build and resources remain referenced by their original hashes.

This is partial original-scenario evidence observed by the implementation owner.
The retained Warlock build is not a claim of accepted Omarchy predecessor,
complete redistribution package, main-session rollback, native AT or independent
acceptance. Every missing obligation remains recorded. The two failed native
reports/screenshots retain their original source hashes and are historical only:
one captured before popup focus, the other expected bar DOM focus after Escape
instead of the actual prior application recipient. Their original normal-exit
and deadline assertions were preserved; the current drill uses physical focus
and the real recipient. The earlier component report predates inherited host
locking and is not current evidence. No frozen previous packet was altered.
