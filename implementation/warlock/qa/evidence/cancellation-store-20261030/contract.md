# Durable native cancellation: controlling stage contract

Status: concrete private implementation contract; no code qualification or original acceptance. Preserve native-order evidence, all failed/stopped records and original deadlines. Scope is the daemon/store stage of the existing Restore opt-in. C host/Elm routing remains a separate necessary integration; a synthetic producer admission is not that route.

## Chosen persistence boundary

Use `CancellationLedger(DeliveryLedger)` in new `adapter/cancellation_ledger.py`, selected by RecoveryStore. Its active file is `ledger-v7.json`, not a second mutable independent policy store. Envelope: `{schema:7,lifetime,predecessorV6SHA256,legacy,cancellations}`. `legacy` has the existing schema6 shape; `cancellations` is a bounded array of typed protocol1 Restore records. Keep existing ledger-v6.json immutable after migration, pin exact predecessor bytes, retain all earlier predecessor hashes and release/delivery evidence. Existing release-deliveries-v1 remains a delivery-only sidecar referencing unchanged historical release anchors. No new model of window eligibility is introduced.

Why this small versioned envelope: current RetirementLedger._save forbids live entries disappearing without disposition; _validate also requires migrated entries remain accounted for; _sync otherwise reimports Pending files. A certificate in an unrelated file plus unguarded removal cannot satisfy those invariants. One active atomic envelope lets both legacy reservation state and cancellation certificate have the same durability barrier. Do not change recovery_journal.validate/normalize to accept Cancelled or convert it to Refused. Do not rewrite existing V3–V6 bytes or invent a V6 Released proof.

Refactor only explicit storage/validation seams needed for inheritance: load/save active envelope, initialization under an already-held guard, and exact reservation destination validation. All default V6 checks retain their original behavior. V7 may add a destination only by validating the full certificate against the exact old record; never accept a caller-supplied set of exempt keys. Preserve legacy release/history monotonicity, latest correlation, predecessor coverage, watermarks, target uniqueness and capacity. When cancelled exact latest is removed, set latest=None only if it still refers to that exact key; never overwrite a newer latest. V7 validates predecessor reservations against live entries, unchanged legacy definitive/released history OR exact certified cancellation dispositions.

## Types and public store API (freeze for authors)

`NativeCancellationEvidence`: internal typed result constructed only by the daemon coordinator from a successful strict CancellationEndpoint response on the selected authenticated connection, with immutable deep-copied response and original durable key. Not constructible by frontend dictionaries passed to the store. Disk decoding independently validates the complete shape and certificate correlation; it does not claim a hash is a cryptographic native signature.

Cancellation record fields: `{key, admission, deadlineMonotonicNs, stage, prepared, lastObserved, certificate, ackState}`. `key` is existing full storage_key over the schema2 Pending admission (binding/effectProtocol/full intent). `admission` remains that exact schema2 Pending record; cancellationProtocol=1 is explicit in validated prepared/outcome objects. Stages: Reserved, Prepared, Uncertain, TerminalStored, AdmissionRetired. ACK states: NotSent, Pending, Acknowledged. `prepared` nullable exact effect-prepared; `lastObserved` nullable exact response; `certificate` nullable full immutable terminal response plus deterministic digest over all its bytes/typed fields. Do not equate digest with authentication. Internal operation marker `{kind,attempted}` is required to distinguish saved admission from a possibly submitted prepare/commit/cancel; save attempted BEFORE native transport. Transport failure becomes Uncertain, never locally Cancelled/Refused. Native terminal status is only Committed/Refused/Cancelled; Unknown is nonterminal.

RecoveryStore additions (return immutable copies):

- `cancellation_reserve(bound, intent, deadline) -> {record, submitPrepare:bool}`. Require existing exact host Pending admission, protocol1 Restore, current scope, original immutable deadline, all legacy admission guards, no overlapping legacy/new entry or native slot. New reservation and watermark consumed durably before submitPrepare=True. Exact existing key returns submitPrepare=False plus stored state; never grants permission to replay.
- `cancellation_attempt(key, operation) -> record`. Validate allowed transition/current binding/original prepared identity, persist attempted marker before any native mutation-capable request. Never used as restart replay authority.
- `cancellation_observe(key, NativeCancellationEvidence) -> record`. Validate complete key/binding/protocol/deadline/preparedId and monotone terminal identity. Persist Prepared or Unknown observation without release; persist a complete terminal certificate before any ACK or reservation removal. Unknown cannot replace an already known terminal. Conflicting terminal/ID/deadline refuses and poisons the workflow, never erases old evidence.
- `cancellation_finish(key) -> record`. Under one guard, idempotently finish certified exact admission retirement and local reservation transition; no native call.
- `cancellation_ack_pending(key) -> certificate`. Require terminal stored AND admission retired; persist Pending before returning exact certificate for strict client ACK.
- `cancellation_acknowledged(key, validatedAck) -> record`. Exact full key/preparedId/deadline ACK correlation, persist acknowledged. Native lost ACK leaves terminal and Pending; never reopens execute. A duplicate exact ACK in the same live grant is allowed.
- `cancellation_snapshot(bound) -> records` and `cancellation_recovery_frames(bound)`. Informational only; old-scope uncertainty never authorizes execution. No method returns a new-intent fallback.

Existing `begin`, `settle`, `recovery_frames`, `settlement_frames`, reconciliation release and delivery interfaces remain. New cancellation lifecycle never calls legacy settle(Cancelled). Committed/Refused cancellation outcomes use the same typed cancellation disposition as Cancelled, retaining the complete certificate and leaving legacy settled/history unchanged. This is the chosen implementation, not an optional conversion through old settlement.

## Lock ownership and atomic order

Journal owns its existing lifetime writer lock. Each operation acquires exactly one nonreentrant host_guard. Factor `_..._locked(directory,state)` helpers; never call existing begin/_settle_record/release/synchronization_snapshot public methods while already holding host_guard. No network call occurs while holding host_guard. A serialized daemon coordinator owns the interval between durable attempt and observed response; unrelated writes cannot race its in-memory state. Revalidate on the next lock acquisition.

1. Bootstrap V7 from fully validated synchronized current V6 and existing delivery sidecar; store exact predecessor SHA. Write empty/new V7 using nofollow exclusive temp, complete bounded writes, file fsync, replace, directory fsync, then initialized marker and directory barrier. An unmarked populated or missing-after-marked state fails closed. A crash between V7 write and marker must be handled as a specifically validated initial migration, never guessed. Initialization uses explicit phases and private locked helpers, not nested constructors/locks or object grafting. On existing V7 restart call Journal.__init__ directly and validate immutable V6 plus the existing delivery sidecar; NEVER invoke mutable DeliveryLedger/RetirementLedger constructors, whose dynamic _load/_save/_validate dispatch would target the wrong schema. On first migration complete a normal legacy initialization/sync BEFORE activation under the same already-held lock through extracted helpers, capture the resulting V6 bytes, then activate V7. V6 remains frozen after this barrier; reject later V6 drift. C host reads admissions-v1/shared writer lock, not V6 filenames, so no active V6 mirror is needed.
2. Reserve only after exact standard C admission exists. Sync import with that exact wanted key excluded as existing AdmissionLedger.begin does; apply actual existing target/key/counter/budget rules. One V7 atomic save includes cancellation Reserved plus legacy Pending plus both watermark maxima. Store immutable original deadline here. Mark Prepare attempted durably; only then call strict native prepare.
3. Persist authenticated prepared/Unknown/terminal response after transport. TerminalStored atomic save retains the old reservation plus full immutable certificate. This must complete before ACK, removal or frontend terminal delivery. If an attempted command loses its reply, keep reservation Unknown and original key; never auto-resubmit Prepare/Commit/Cancel.
4. Finish certificate: first reestablish envelope directory fsync if recovering. Under host_guard remove only `storage_key(admission)+'.json'`, after independently validating its exact schema2 Pending contents/full key if present; fsync admissions directory even if already absent. Then atomically remove only that live entry, preserve watermarks/peers/newer latest, and mark AdmissionRetired. V7 disappearance checks accept only this exact terminal certificate. Crash after unlink before V7 save is repaired idempotently from TerminalStored; crash before unlink leaves reservation and certificate safe.
5. At startup and BEFORE ordinary admission import, finish every TerminalStored record and remove any reappearing exact certified admission. AdmissionRetired tombstones remain immutable/bounded. Never filter a different key merely because target or binding resembles it. Persist absence before considering local target reusable. This prevents delayed Pending import from resurrecting a terminal.
6. Persist ack Pending, call strict native ACK only for the original still-live exact grant, persist exact ACK then expose result. Response/output failure leaves durable state. ACK is not a resource-retirement observation beyond what its actual native contract guarantees.

Every write/fsync/rename/close/remove inconsistency poisons the whole store/coordinator lane: no later effect, prepare, commit, cancel or ACK allowed until explicit recovery/reopen validates persisted state. Read-only reporting may expose existing facts; no silent retry of mutating operations. Unknown keeps custody. Bounded state: at most64 cancellation records including historical terminal tombstones, shared existing64 live admissions/target reservations,128 watermark scopes and existing bounded file sizes (1MiB envelope; refuse before admission if reservation of terminal capacity would exceed it). Native one/session and global64 remain independent enforced bounds. Do not evict old certificate merely to accept a higher request; compaction is not part of this stage.

## Daemon hooks and restart

Add a small `CancellationCoordinator(client,recovery)` in `adapter/cancellation_workflow.py`. `handle(request)` is called by daemon.handle_request for negotiation, prepare, commit, cancel, decision-request and decision-ack after exact top-level shape/version/current binding checks. It owns strict client calls, typed evidence construction and durable sequencing above. For prepare, require workspace-navigation blocker clear exactly as ordinary window-effect, plus standard admission. No independent window policy, no calling native raw request to bypass strict client, no direct fallback.

Only an actual incoming live command can initiate a new native action, after durable attempt admission. Duplicate commands return stored complete result or query using the same valid preparation; never replay mutation automatically. A query is read-only and may discover a native terminal. A frontend ACK cannot bypass journal retention; coordinator alone decides when native ACK is safe. Full native lifecycle responses remain separate from the old three-status NativeOutcome/host-admission-settled path.

Integrate coordinator startup after RecoveryStore is opened and before publish_startup emits attached/recovery output. Complete local durable finish operations before attached can enable C admission. After fresh hello, exact binding ordinarily advances: old Reserved/Prepared/Uncertain records remain informational Unknown under their ORIGINAL binding/full key and continue blocking target reuse. Do not retag, send prepare under new grant, or query/ACK old-owner native records using the new grant. Already stored terminal certificates may finish LOCAL exact admission retirement and be reported as historical proof; native old-owner ACK remains unavailable, not forged Acknowledged. Existing native retirement/reconciliation proof route remains necessary for old uncertain resources; this stage must not synthesize that proof. Preserve global native unacked capacity honestly.

## Existing C admission handshake and deferred boundary

Current native/host.c request_kind(~290), request allowlists(~606/~854) and admission_batch(~886)/host-journal.h only admit window-effect; host-admission-settled(~163) accepts only old terminal record. Stage daemon/store tests may provide an actual standard schema2 Pending admission fixture under the existing writer protocol, clearly labelled support, but cannot claim the C/Elm path is usable.

Future narrow host integration must treat effect-prepare as the ONE mutation admission: write the same full-key protocol1 Restore Pending and durable counter allocation before sending prepare. Commit/cancel/query/ACK correlate to that existing owned preparation and must not allocate another Pending/counter. Add a distinct `host-cancellation-settled` DTO with complete certificate; C must exact-validate current delivery binding, original certificate/admission key and stored sidecar provenance, then retire only its matching in-memory reservation. It must not route Cancelled through admission_retire's three-status decoder or unlink a different admission. The daemon already owns exact file unlink after certificate persistence; duplicate C handling is idempotent validation of absent/identical admission, never blind deletion. New host must gate legacy/new overlap using the same shared writer and durable reservations; an old host which does not negotiate this route must never send new lifecycle requests. Same-key late old Pending is removed by V7 sync; other-key conflicting Pending remains blocked, not discarded.
