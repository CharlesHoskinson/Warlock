## Observable correspondence

1. **Absent lookup is not admission or execution.** `CancellationCoordinator.handle` validates the current binding, intent, selection and D before `CancellationLedger.cancellation_receipt_lookup`. The latter locks, checks the active grant and exact key, and returns `None` for an absent row without `_sync`, reserve, attempt, observe, finish, ACK or native RPC. For a present terminal row only, coordinator may emit an informational settlement frame; it does not execute the effect. This is narrower than a claim that all startup/recovery reads are mutation-free: `startup` may finish an already certified retirement. Model `absentLookup`, `brokenAbsentLookup`, `noAbsentLookupMutation` and named `absentLookupTest` are a finite abstraction of the absence condition; the modeled `lookupWrites` flag is an explicit bookkeeping variable, not an instrumented Python or filesystem proof.

2. **Producer sequencing and authority.** `CancellationCoordinator.__init__` requires `settlement_sink`; `daemon.main` supplies its owned `send`. `_observed` records strict native evidence, finishes exact durable admission retirement, persists ACK Pending, emits the matching typed frame, then attempts native decision ACK. Only after `cancellation_acknowledged` is persisted does it emit the Acknowledged update. Unknown/Prepared do not become a terminal frame. `daemon.publish_startup` stages recovery, sends the attached `hello` first, and then the typed historical frames; their outer delivery binding is current while the admission/certificate retains the original binding and D. No historical row creates an in-process owned current native handle. A failed output/ACK is a refusal and recovery concern, not a guessed terminal or automatic effect retry. Model `terminalRetiredAs`, `cacheRename`, `acknowledge`, `restart`, `historicalLookup` and named historical/three-terminal traces represent a subset: the model does **not** explicitly order Pending output, RPC ACK and Acknowledged output, authenticate a sink, or model lost output. Source and strict-double tests support that ordering separately.

3. **C-cache/V7 join and same-target reuse.** `cached_retirement_locked` requires strictly decoded receipt joined to one current validated V7 `AdmissionRetired` record, matching full admission/selection/key/terminal certificate/P/D and producer digest through `make_settlement`. It checks ACK rank cannot exceed durable V7; an Acknowledged cache must match the stored native ACK. It verifies the exact cache bytes again and fsyncs the file and directory. Saved delivery B is provenance only, not current native authority. `CancellationLedger._active_companions_locked`, `begin`, and `cancellation_reserve` use the result to keep an unresolved target fenced and permit a different full K only after valid local cleanup. Native unacknowledged-slot/Busy restrictions remain separate. Model's `validProof`, `cacheRename`/`cacheSync`/`releaseFence`, `targetExclusion`, named `sameTargetAfterSettlementTest` and `newGrantSameTargetAfterCleanupTest` capture the abstract fence and two-key relation, not the Python V7 disk re-read, native Busy, serialized JSON, all file errors or a real C receiver. `validProof` assumes trusted backend/digest booleans and `step` supplies `exactProof`; invalid variants are covered by named negative tests, not by a proof of an authenticated producer.

4. **Orphan and guarded public reads.** The V7 decoder rejects a companion-key collision in legacy definitive settlement/history or release even when no typed cancellation row exists. `_require_legacy_key_locked` excludes companion full keys before legacy begin, settlement or removal; `legacy_reconciliation_records` filters both typed and companion keys before legacy grant retirement. Valid cached cleanup can free a target but cannot make old exact K a legacy request. Public `snapshot`, `recover`, and `blocked` hold `host_guard` while reading companion state; relevant new OSError paths poison/refuse rather than silently accept uncertain custody. Real V6/default behavior remains separate. In the model a spent/reserved entry retains a fence across restart and no old grant can send; it does not encode this distinct orphan legacy decoder/read-lock bug, so the retained Python orphan, reader and fault controls are independent implementation evidence, not a model proof.
