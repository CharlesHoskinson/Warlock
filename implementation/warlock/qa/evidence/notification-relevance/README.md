# Notification expiration relevance and expired-action rejection

This packet advances original ELM-UI-010 / `announce-notification expiration`, `announce-expired action rejection` and `announcement-expiration-irrelevant`. Exact original requirements/oracles are retained. All three remain **partial**: actual speech/braille, wider native lifecycle and independent acceptance remain open.

The immutable Elm notification model observes exact focused action identity and exact pending request/target. Only a newer same-service live-to-expired transition for that focused or user-invoked notification creates a polite expiry event. A matched Refused outcome creates an expired-action event only when admitted native expiry facts or the pending target's already-observed expiry prove it. Both honor DND. Counts, copy, initial history, late focus, policy edits, unrelated expiry and repeated receipts create no event. The existing single root-selected owner carries binding/service/revision/incarnations for expiry and binding/request/full target for refusal. No receipt-triggered Focus or action replay is introduced.

Passive DOM focus observations pass through current popup owner, publication, lease and projected-control admission. They cannot authorize actions. A focused pending or retired action retains its keyed button node, visible unavailable detail and aria-disabled. Native disabled is withheld only for this one readonly node so keyboard focus survives; renderer dispatch, native action gate and Elm resolver still reject its action. Keyboard departure removes the retired placeholder. The control remains in its entry's position to preserve keyed continuity rather than being appended across other entries. A strict optional focusOnly boolean extends control projection while retaining legacy decoding; native/bar/non-notification/contradictory/foreign/stale shapes remain refused.

Native retains up to 64 exact expired ID/incarnation/producer facts and returns a strict typed refusal reason. The original held queued-action journey can expire and replace an ID before Elm receives an expired snapshot; its matched native reason reports the real target without inferring expiry from ID reuse. A substituted producer cannot inherit an expired fact. Existing unicast, availability, consumption, critical urgency, deadlines and Unknown/no-replay semantics remain unchanged. The expiry-fact capacity is bounded by source and a focused size assertion, not a stress/performance qualification.

The quint-llm-kit modeling/execution workflow typechecked executable initialization and a positive witness before implementation, then passed ten explicitly selected named tests, five positive witnesses and 1,000 sampled 30-step safety traces. The model abstracts already-admitted focus/native facts to two opaque incarnations and requests. It checks relevance/DND, at-most-once counts, matched requests, no implicit replay and explicit focus preservation in selected expiry/refusal transitions. It does not model native authentication, producer proof, clocks, Gio threads, DOM lifetime, output retirement or AT. Implementation/native checks cover the concrete boundaries separately; sampled model results are not native acceptance.

Nineteen compiled root checks cover relevance, strict identities, foreign/stale focus and receipts, readonly retained controls, pending expiry across replacement, direct matched native expiry reason, DND and repeat/no-focus behavior. Twenty-one browser checks retain the actual same node through pending, expiry and refusal, verify polite owner/correlation and aria-disabled, block Enter dispatch and permit keyboard departure. Existing refusal checks remain. Native C tests preserve all original gate tests and add passive-focus/readonly-action/strict shape/publication/close negatives. Actual private native Gio producer checks preserve the original lifecycle and add exact expired reason across replacement and producer substitution negatives.

The original protected native notification journey passes 91 recorded checks, including real focused expiry with exact service/revision/incarnation, one polite owner, unchanged actual node/control/document focus, physical Enter rejection on the readonly node, keyboard departure, DND suppression/no replay, original unrelated expiry silence and queued expired-action refusal after reused ID. The broker hold/deadlines remain original. An additional original physical keyboard journey passes all nine surfaces after the shared projection change. Both use the same compiled host and exact owning core/plugin pair, no main-desktop action, and normal owned cleanup. Native user-invoked expiry while focus is elsewhere remains component-only; actual speech/braille and wider lifecycle/independent acceptance remain missing. New retained-control physical pixel qualification is also separate; these native claims concern recorded input/DOM/focus/identity observations.

The source base precedes this delta; current source/compiled/ABI hashes, reproduction commands and evidence hashes are in the manifest. Failed model syntax/compiler/browser fixtures remain locally with hashes. The browser failure fed equal-publication frames from distinct branches; the original publication guard correctly refused them. The final fixture follows one continuous pending/expiry/refusal/departure path. No original requirement, counterexample, native deadline or authority property was weakened.
