# Two clean offline release builds

ELM-DEL-004 `delivery-004` has owner-observed partial evidence. Two fresh
Bubblewrap network/mount/PID/IPC/UTS namespaces run the complete fixed recipe
against a read-only snapshot containing only the reviewed lock files and aliases.
Each build has its own empty output and tmp filesystem; the only shared build
input is the immutable snapshot. No desktop socket or mutable host cache is
mounted. Actual namespace identities, rejection of a listening parent socket,
read-only source, hidden host marker and core limit 1 are recorded for both.

Both builds complete eighteen phases: the three optimized Elm views, all eleven
native host units, linking, native self-tests, compiled replay and nineteen typed
reducer observations. All 56 payload file hashes and both 26,040,320-byte archive
hashes agree. The Elm assets and host remain byte-identical to the previously
qualified artifacts; the exact core/plugin/Aquamarine tuple and loader alias are
retained, not rebuilt. The reviewed lock now includes 9,226 entries and 246
filesystem aliases, including actual ELF interpreter lookup paths and the
compiler's implicit atomic-library input. A separate protected process verifies
the committed lock selection without rebaselining.

Actual archive and payload alterations block release with exact differences.
Changing the Aquamarine alias to a different spelling of the same target also
blocks despite unchanged resolved file bytes. QA restores every changed owned
artifact and reconfirms matching hashes. Both build logs, actual payload manifests
and arguments are retained verbatim. The production command returns nonzero for
failed or differing builds and retains partial logs on timeout.

Historical namespace, argument-limit, missing-loader, lazy Python dependency and
implicit-link failures remain recorded with their original lock/log hashes.
The earlier matching campaign predates alias/timed-out-log hardening and is not
the current source proof. The large input lock is committed once in the candidate;
archives and verified input snapshots remain local at their hashed paths.

This proves the recorded fixed-recipe offline observation on this host. It does
not prove an upstream native core rebuild, another machine/distribution, complete
compiler-source provenance, redistribution/SBOM/notices, native AT/IME/hardware/
resource/journey acceptance, accepted Omarchy fallback or main-session deployment.
Independent original-scenario review and full release acceptance remain open.
No ordinary Elm/native policy changed; the installed Quint distribution and
applicable sources remain pinned, with the existing typed regression retained.
