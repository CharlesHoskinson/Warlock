# Active grouped taskbar items

An active group with multiple windows now retains both its window count and Active state. Either foreground member selects the same group. Inactive and fully minimized groups show the count without Active. The existing renderer uses this observed detail for its active styling and native toggle state; the grouped primary action still opens the picker.

`baseline/` runs the actual production Surface projection with two admitted members: three active cases fail, while inactive and fully minimized cases pass. `final-build/` passes all five cases, compiles the current entry points and host, runs the existing explicitly selected Quint switcher/focus tests and sampled invariants, and passes the original nine browser accessibility checks. This is a display-state correction, with no change to reducer or native effect authority and no new model.

`native-role-and-state/` observes all eight actual taskbar controls by native names and exactly one active toggle state. The fixture now recognizes the bridge's native `button` role alongside `push button` and `toggle button`; the original exact-name, count and observed-state assertions are preserved. That run subsequently misses its original bar-return deadline because it pointer-opens a picker and expects a keyboard opener's return.

The corrected fixture separately observes pointer dismissal returning to the application, then enters through the real Super+Alt+Space applications shortcut, dismisses applications, and uses the toolbar's Home/arrow navigation to reach the same group by control identity. State labels can change while navigating; they do not define the recipient. No DOM focus injection, native focus workaround, synthetic AT tree, extended deadline or removed assertion is used. Earlier input-fixture failures remain in their named packet directories.

`native-reopen-crash/` confirms native taskbar names/state, pointer return and physical keyboard navigation, then encounters WebKit termination while reopening the picker under the real AT reader/inspector. The host exits with failure 1 and enters its existing recovery route. The full native AT journey has failed. The kernel records a core-dump attempt aborted by the protected `RLIMIT_CORE=1`; `coredumpctl` has no dump. No OOM event appears in the bounded crash interval. These facts do not establish the crash mechanism; no core limit or installed component was changed.
