The model now also offers **one combined fixture** `currentWithUnsafeBackup`: a schema-2 active file can coexist with an unrelated pre-existing two-link backup, and a schema-2 save does not inspect or overwrite it. `twoLinkRecoverable` is conditioned on `publishedBackup`, set by this model's own migration hard-link action; it therefore checks original-byte preservation during migration publication/interruption rather than making claims about arbitrary pre-existing foreign backups. `originalBeforeActivation` remains unchanged and requires exact old backup plus file/directory sync before legacy activation. `twoLinkFailClosedWitness` still models actual migration link/interruption, successful active read, subsequent save refusal and recoverable original. No automatic repair is inferred.

For current-schema fixtures, `old=2` names the existing schema-2 byte identity, `active=4` names the complete changed schema-2 image, and a no-op retains 2. `previousActive` records the immediately preceding complete image so a modeled crash before active-directory sync can restore that image; a post-rename sync failure still leaves the visible new image and returns `Unknown`. Values are finite opaque identity classes, not all JSON/revision transitions. This does not model multiple distinct schema-2 edits or durable hardware behavior.
