# Native dense-layout focus

The taskbar now paints the focused control only while its WebKit document owns keyboard focus. This keeps a visible outer contour after pointer-menu use even when WebKit does not match `:focus-visible`, and removes the contour while a popup or application owns focus. Actual selection, Active underline and pressed state remain separate. The adapter reads document/control focus for paint and scroll geometry; it acquires no native keyboard authority and changes no Elm effect policy.

ELM-UI-008 `overflow-first-last` retains its original oracle: all entries are reachable, focus is revealed and labels identify operations. The current native 150% journey on 480x600 visits all 18 configured pins, first/last menus, Menu/Shift-F10, Escape, deliberate wheel scrolling and 480→640→480 output resizing. It passes 133 checks with current-key duplicate rejection, no window effects/launches and normal owned-helper cleanup. Four unique captures require two pixels of paint coverage along every outer edge of the first/last focused pins and both resized outputs. Their actual WebKit observations report `:focus-visible` false and a solid painted contour. An actual pointer-opened popup observes the bar document inactive with outline style `none`.

The original default-size keyboard Activate/Minimize/Restore regression also passes 131 checks, including exact single effects/receipts, state-cue pixels, actual application key recipients, five unique four-edge captures and normal cleanup.
