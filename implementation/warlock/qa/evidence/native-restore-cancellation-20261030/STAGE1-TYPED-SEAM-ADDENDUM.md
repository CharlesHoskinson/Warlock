# Stage1 controlling addendum: negotiation and typed mutation progress

This refines STAGE1-CONTRACT.md (01eb33fd07085f71e60e649a6f6aad9f29257bfa13fb3cd77c59c3f47550732a) for immediate integrated source/model authorship. The incomplete Terra1 v1 header is NOT READY and must not be adopted. No QA or acceptance follows.

1. Keep the ordinary hello response and its exact capability dictionary unchanged. Add only a separate authenticated request `{protocolVersion:3,kind:"effect-cancellation-negotiate",binding,requestId,cancellationProtocol:1}`. Reply `{protocolVersion:3,kind:"effect-cancellation-capabilities",binding,requestId,cancellationProtocol:1,effectProtocol:1,operations:["restore"],maxPreparedPerSession:1,maxPreparedGlobal:64,deadlineClock:"CLOCK_MONOTONIC"}`. Strict exact fields/types, positive canonical decimal requestId, exact binding, verified native peer grant and supported version are required. Store negotiation for the exact session/frontend, reset on epoch change. All five new lifecycle kinds require that successful negotiation; legacy one-shot behavior is unchanged. Negotiation is not authority to bypass key/incarnation/dependency checks and a selected cancellable workflow never falls back to direct submission.

2. The first native mutation in performEffect may be `destinationMonitor->changeWorkspace`, not applyMinimized. The no-cancellation/no-yield execution boundary MUST precede that navigation, damage submission, focus change or any other externally visible mutation. Refactor a typed validated execution seam, not a wrapper which calls performEffect and parses its status string. No temporary session cursor rewrites. Same-session direct protocol1 AND geometry protocol2 requests refuse busy before changing ordering/cache while the prepared slot is live/unacknowledged.

Use explicit types equivalent to:

```
enum class Progress { NoNativeMutation, NativeMutationStarted };
enum class Decision { RefusedBeforeMutation, RefusedAfterProvedCompensation,
                      CommittedObserved, ExecutionUncertain };
struct DecisionFacts { uint64_t revision, outputGeneration; BoundedReason reason; };
struct ExecutionResult { Decision decision; Progress progress; DecisionFacts facts; };
```

Only the internal executor can construct its observed terminal result; cancellation owner cannot infer a proof from an arbitrary status string. The permit/owner gate validates exact key, preparedId and original deadline, then installs execution uncertainty and enters Committing before invoking the mutation-capable body. Existing validation and barrier admission may occur earlier while there are no native state changes. No event pump, nested external dispatch or async continuation is added across this boundary.

3. Preserve existing direct-path validation, compensation checks, wire reason/status and barrier behavior exactly. `refuseAfterNavigation` presently proves a usable fallback focus and unchanged family state before definitive Refused. This is a RefusedAfterProvedCompensation result, NOT proof that no native mutation ever occurred, NOT Cancelled, and NOT general rollback of a window effect. The same typed executor can map it to the existing Refused wire result without altering legacy behavior. Failed compensation, post-mutation exceptions, unproved application or uncertain family/barrier state return ExecutionUncertain and preserve existing uncertain custody. Never turn a generic Refused callback into no-mutation proof. Cancellation is possible only from native Prepared before that boundary and alone has the invariant that no native navigation/focus/window mutation was started for K.

4. Reserve bounded record storage, terminal/control capacity and reply buffers BEFORE Prepared is acknowledged; refuse without admission if reservation fails. Do not pre-render a future terminal reason or revision at prepare time. Capture actual DecisionFacts after the executor's observations and render/cache that decision then, using the already reserved bounded capacity. Preinstall a bounded Unknown fallback at the commit boundary before touching native state. If subsequent observation/formatting/copying fails, that uncertainty record and barrier custody survive; do not erase the slot or claim Refused/Cancelled.

An implementation may use fixed-capacity reply/key arrays or strings whose capacity is reserved to a checked maximum before prepare; all post-boundary formatting must check bounds and avoid capacity growth. Protocol1 full-key counters/operation and bounded native reason vocabulary permit a fixed bound; assert it in production parser/formatter tests. Use typed DecisionFacts, not future JSON templates populated with stale prepare-time facts. Transfer the exact completed cached reply to legacy retry storage without a throwing allocation (reserved capacity or nonthrowing ownership transfer); this needs an actual code path, not a no-throw comment. A transport allocation/send failure after caching a known terminal reply leaves that native decision intact while frontend delivery may become Unknown. A formatting failure before durable terminal cache exists preserves native Unknown fallback. Both remain queryable under exact ownership.

5. Explicit resource split: preparation token/slot custody is not the existing family effect barrier. Cancel/definite refusal retire only the exact preparation token once. Existing executor alone releases family barriers after its existing definitive proof; uncertain execution retains them. Compensation success releases only what current code proves safe. Owner/header destructors cannot release arbitrary native resources. No fake helpers are introduced merely for a retirement test.

6. Extend the model/source test correspondence: count any native navigation/focus/window effect as mutationStarted; cancel-before implies zero. A compensated refusal may have mutationStarted=1 and still be Refused, with zero guarantee of total external rollback; it must never produce Cancelled. Add named cases for navigation-before-window boundary, proved compensation versus failed compensation, allocation/formatting failure after boundary retaining uncertainty, and cached terminal plus lost transport delivery. Existing separate frontendUnknown/nativePrepared, ACK/capacity, stale/wrong-key, deadline and peer invariants remain. The reduced model need not encode every native coordinate, but must label compensation validation as an external executor proof assumption. Real parser/dispatch and actual typed executor integration are required for Stage1 source readiness; an unused owner class alone is insufficient.

No physical Escape, adapter/durable migration, dependent scheduler, native load or original ARC007/008/012 acceptance is supplied by this addendum. Those remain the later explicit obligations of the selected original-scoped work.
