# Stage 1: authored native owner contract

Proposed for actual source/model authorship now; no QA or native acceptance. This compact contract controls the first Restore migration and resolves ambiguity in IMPLEMENTATION-CONTRACT.md. Original obligations are ARC007 receipt-cancelled, ARC008 prerequisite-Cancelled, ARC012 cancellation ordering; ARC013 deadlines remain invariant. Later adapter/durable/input implementation is necessary for full completion. Negotiation failure for a selected cancellable flow refuses; never silently falls back to legacy direct effect.

## Concrete protocol and ownership

Native effectCancellationProtocol=1 capability supports only effectProtocol=1 and operation=restore. Strict request kinds: `effect-prepare`, `effect-commit`, `effect-cancel`, `effect-decision-request`, `effect-decision-ack`. All use protocolVersion=3, cancellationProtocol=1, effectProtocol=1, authenticated binding and complete immutable intent. Preparation additionally has `deadlineMonotonicNs` (canonical positive decimal uint64). The remaining four requests include that same deadline and authority-generated `preparedId` (canonical positive decimal uint64). No extra fields. Deadline clock is native CLOCK_MONOTONIC on the same boot/lifetime; original admitted-selection deadline is required by later host wiring. Stage1 fixtures supply a fixed original deadline and must never reset it.

`effect-prepared` acknowledgement echoes protocolVersion/kind/cancellationProtocol/effectProtocol/binding/intent/deadlineMonotonicNs/preparedId. It is Pending preparation, not a terminal effect outcome. A final Cancelled outcome uses the ordinary effect-outcome fields plus cancellationProtocol/preparedId/deadlineMonotonicNs; it may only originate from the owner transition below. Stage1 native reply helpers for opt-in terminal decisions retain the preparation metadata for every terminal status, so commit-first replay and cancellation correlation do not lose identity. Legacy frames remain byte-schema compatible. Decision query returns the same Prepared acknowledgement or the exact cached terminal outcome. Ack returns a strict effect-decision-acknowledged echo of the same key/metadata; it is not an effect result.

Key = authenticated caller grant/peer ownership plus binding lifetime/session/frontend + effectProtocol + full intent request/generation/incarnation/operation/context lifetime/epoch/output/revision. JSON member order is not identity. Validate/normalize using shared typed parsing/fingerprint, not raw JSON equality. preparedId and deadline are immutable metadata correlated with that key. Reject unsupported protocol/operation before reserving capacity. Never use another connection identity to cancel an owner.

One slot per authenticated session and a global cap of 64 live cancellation slots, counting Prepared, execution-Unknown and terminal-unacknowledged records. This is a chosen new conservative bound, not a claim about an existing native session cap. Reserve reply/terminal storage before acknowledging Prepare. One session can have only one new cancellable request at a time. No capacity eviction or dropping Unknown. A monotonic preparedId allocator refuses exhaustion.

## States, transitions and cursor rules

Native states: Empty, Prepared, Committing, Terminal(Committed|Refused|Cancelled), ExecutionUnknown. Frontend Pending/Unknown/terminal observation is SEPARATE: dropped prepare ACK can make frontend Unknown while native is still Prepared. Exact native cancellation can then legitimately return Cancelled; only the producer's actual state decides. ExecutionUnknown cannot be reclassified as cancelled merely because the frontend asks.

Prepare validates ownership/full key, deadline and capacity, reserves request/generation ordering, and returns Prepared without mutation. Exact duplicate Prepare returns the same preparedId/deadline. Same cursor with different payload refuses. Lower/stale cursors refuse. Expired original deadline refuses without mutation. Preparation slot/resources belong to K only.

Cancel(exact Prepared) atomically sets Terminal Cancelled, caches the exact receipt and retires its preparation resources once. Commit arriving later returns that identical Cancelled receipt. Cancel against Committed/Refused/Cancelled returns the exact recorded disposition, without rollback or a second retirement. Cancel against ExecutionUnknown returns Unknown and preserves uncertain custody. Foreign/stale/absent/corrupted metadata refuses without creating a cancellation tombstone for an invented effect.

Commit(exact Prepared) first checks original deadline and obtains the same validated live-incarnation/dependency/input/family plan used by ordinary effects. Definite failure sets Refused, never Cancelled. The serialized native callback then transitions Prepared->Committing, installs an Unknown fallback, and calls the actual mutation body without pumping/yielding/nested dispatch. There is one atomic cancellation-check/first-mutation ordering boundary. Complete observed application stores Committed; uncertain or partial execution stores ExecutionUnknown with existing barrier custody; a proved pre-mutation refusal stores Refused. Do not permit a Refused result after uncertain mutation merely to simplify the state machine. Cancel cannot interleave within that callback.

Terminal exact decision query is read-only and cannot execute. Ack is accepted only for the exact known terminal receipt after the adapter has durably retained that decision; Stage1 tests are the authenticated caller. Ack permits slot reuse but never erases the allocation watermark. Keep the most recent terminal exact reply in the existing per-session last-reply journal; an exact retry before a higher request returns it, and an older key after higher admission refuses as expired, never re-executes. ExecutionUnknown cannot be acknowledged away; only existing separately validated uncertainty retirement may release it.

Legacy direct `window-effect` for a reserved prepared key must refuse preparation-required; it cannot serve as Commit. A higher unrelated direct/prepared request while a cancellation slot is live or terminal-unacknowledged must refuse busy and must not advance/overwrite its cursor, deadline, preparedId, result or resources. Other authenticated sessions remain independent. On epoch retirement, disarm old preparation and free only proved unexecuted preparation resources; do not let old callbacks operate under a new binding. If a terminal proof was not delivered, frontend/adapter remain Unknown. Uncertain execution/barriers follow existing retirement proof, not automatic reset.

## Concrete code/API seam

New native/effect_cancellation.hpp owns typed Key, Preparation, Phase, cached Decision and bounded slots. API names for authoring: prepare(key,deadline,now), lookup(key,preparedId,deadline), cancel(key,preparedId,deadline), commit(key,preparedId,deadline,now,validate,execute), acknowledge(key,preparedId,deadline), retireOwner(binding). Return a tagged result distinguishing Prepared/Terminal/Unknown from protocol refusal. No generic setStatus method or caller-provided terminal status. `execute` is reachable only using a CommitPermit constructible by this owner after the exact transition; default/direct JSON cannot manufacture it.

In authority.cpp authenticate new dispatch kinds alongside existing window-effect, then call this real owner. Factor existing performEffect parsing, fingerprint/ordering and checked mutation body narrowly: ordinary direct execution and cancellable commit share the same final checks/body; prepare must not make the old duplicate guard return its placeholder Unknown instead of executing an authorized commit. The new direct-path busy fence precedes any cursor mutation. Geometry effects are also prevented from overwriting a live per-session prepared cursor, but gain no cancellation support in this slice. Existing terminal/Unknown barrier semantics remain the executor's responsibility.

Resource callback custody: preparation owns only its bounded slot/encoded key/reply storage and an explicit scoped preparation token. Retire that token once on terminal cancellation/definite refusal or orderly decision completion; never have a generic destructor or `releaseAll` clear native effect barriers. Do not introduce fake helper processes to manufacture retirement counts. Existing execution allocations, window-family barriers and post-mutation uncertainty stay owned by the existing execution body. A testable retirement callback accepts the full key and only the generation-owned preparation token. Unknown execution may release no-longer-needed preparation storage while retaining its decision slot/barriers; these are separate facts. Peer token/resource sets must remain unchanged.

## Runnable model and source tests to author

Model two full opaque keys, two targets/owners, native phase and independent frontend observation, fixed deadlines, slot capacity, allocation watermarks, exact cached terminal replies, owned preparation tokens and execution resources, mutation counts and dependent-waiter state. Actions: prepare/retry, lose/deliver acknowledgement, cancel, atomic validated commit with success or uncertainty, query, durable terminal ack, expiry, foreign/stale requests, legacy-direct bypass attempt, owner retirement. Keep original deadline immutable. Model prerequisite release only for exact same-key/incarnation/generation Committed; mark that dependency rule as proposed architecture, not correspondence to a proven existing production scheduler.

Named tests: cancel-before-commit zero mutations and own retirement; commit-before-cancel stable Committed/no rollback; lost prepare ACK then native Cancelled proof; native Unknown cannot become Cancelled/replayed; duplicate cancel/commit/query stable; foreign full key and other owner unchanged; higher/direct bypass leaves preparation untouched; terminal unacked capacity refusal; exact ack then higher request with old retry refused; expiry unchanged deadline; peer resources retained; cancelled prerequisite withheld/wrong-key Committed withheld/exact Committed releases. Broken variants should demonstrate late-cancel-overwrite and wrong-owner-resource-release violations. Bound simulation seeds/lengths explicitly; no exhaustive claim.

Production C++ tests must exercise the same new owner called by authority dispatch and its real strict parser/callback adapter, including rejected legacy bypass. They can record an injected mutation callback for deterministic order and resource checks but are not live compositor proof. Stage1 must not finish as an unused class or widen Elm/adapter decoders before producer integration. Preserve current ordinary effect regressions. Source-dependent owning native rebuild/ABI/provider pair refresh remains mandatory before any load; all old frozen evidence survives.
