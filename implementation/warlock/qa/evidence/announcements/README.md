Other bars retain visible/readable status without live announcement delivery. The native transport validates that route and consumes each serial once; view receivers project the message without requesting focus or an action. ## quint-llm-kit grounding

The additive `announcement-owner.qnt` model was developed incrementally before implementation using quint-llm-kit’s modeling and implementation workflows. Executable initialization, positive request/refusal paths, then delivery/ownership/repetition were checked in stages. The final unchanged model typechecks, executes all eight explicitly selected named tests, and passes 1,000 sampled safety traces of up to 30 steps (seed 79502). All seven selected witnesses are reached; witness counts and selected commands are retained.

Mapping: `request`/`refuse` abstract the already correlated Launch/Effects/Settings transactions; `sequence` maps to `OutcomeAnnouncements.observe`; `choose`/`popup`/`publication` map to OutputController owner/frame declarations; `frontier`/`publish` map to native validated forwarding and passive receiver deduplication; `focus` requires that this route produce no focus effect. Notification history changes are explicitly not admitted without permission data. All pre-existing authority models and their acceptance properties remain unchanged.

The model uses bounded opaque identities and assumes a matched refusal from the original transaction decoders. It does not prove those decoders, UInt64 exhaustion, process restart, transport loss, timing, accessibility export, speech/braille or hardware/resource budgets. Actual typed/native checks cover concrete correlation separately. Eight named tests and witness counts are model evidence, not delivered features.
