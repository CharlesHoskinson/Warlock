# Receipt lifecycle model: private unvalidated source proposal

SOURCE PROPOSAL ONLY. No typecheck, initialization, named test, simulation, build or native test has been run by this author. Root must first typecheck, run executable init, select each named test explicitly and run proportional seeded bounded safety; preserve any errors/counterexamples. The installed Quint 0.33.0 protected launcher and unchanged qa_run scope/core limit remain root's responsibility. The modeling skill's incremental runtime checks are expressly deferred by the user's instruction. No formal/full correctness, original ARC-007 closure or native/release acceptance is claimed.

The user's bounded scope and type sketch are authorized: one local frontend reducer, two exact-intent identity classes, separate current and unresolved/issued entries, old/new output and separately delivered receipt and recovery observations. Transitions represent local reducer calls, not an atomic native transaction or a guarantee of eventual receipt. Counters 0..2 are allocation classes below real UInt64 exhaustion. Key 1 and key 2 abstract distinct full intents, including request, generation, incarnation, operation, lifetime/epoch/output/revision context; keys also use distinct targets, permitting new Pending after the old current becomes Unknown without violating Effects.blocked. Both share binding/protocol 1; other integers represent mismatches. This is an equality abstraction, not parser validation or identity encoding proof.

Correspondence: `beginOld`/`beginNew` represent Effects.apply begin / Shell admission (with eligible target and remaining capacity assumed), updating counters and one sent mutation. `changeOutput` represents the observed root baseline through OutputController.Topology -> Shell.SupersedeObservations -> accepted action-projection -> Effects.snapshot: current Pending becomes Unknown, unresolved Pending may remain. `receive` matches both issued and unresolved plus binding/protocol/full-key; terminal Committed or Refused changes exactly matching current even after output change and removes its record/issued; nonterminal Unknown retains both and follows existing same-output current update rule. This terminal rule is the proposed contract, not current Effects implementation. `brokenReceiveOld` models the actual old-output terminal discrepancy and is excluded from normal step. `ignored` covers foreign or duplicate without adding effects. `disconnect` maps pending records to Unknown; `recoverOld` abstracts a separately validated exact unknown record and `releaseOld` a separately validated proof, neither sends a mutation. Actual validation, parent binding routing, output source proof and native outcome decoding remain external. Cancelled is omitted: native Cancelled acceptance is a separate channel question.

`receiptPreservesSceneCounters`, `otherCurrentPreserved`, `exactCurrentTerminalSettled`, reservation and bounded properties use explicit pre-receipt ghost state. Tests include same-output, old-output terminal and broken-source negative witness, newer unrelated current, foreign binding/protocol/full-key, duplicate, disconnect, Unknown, proof/release and Refused. The broken witness expects the *negation* of the corrected invariant; it is a diagnostic counterexample, not a claim that a safety failure is acceptable. Unknown and released old records are not automatically retried. The model intentionally allows current Unknown / unresolved Pending after output change; it does not impose unrequested normalization. Record-status fields retained after removal are inert audit residue: only presence/issued permit receipt.

Known limitations for independent review: the external proof is modeled as an enabled action, not a proof validator; two fixed keys cannot establish arbitrary-many-request, native topology, all-failure, scheduling fairness or general recovery coverage; `sends` counts abstract dispatched mutations only. `changeOutput` models a new-output observation without modeling the entire production topology/projection gate; independent production replay supplies that correspondence. All named tests need actual reachability and test-selection verification. Check especially operator typing/effect signatures, action disablement and whether step can deadlock with the selected simulator. No undocumented test result should be inferred from source.
