## Portability and checks

This first composition is local and evidence-dependent: absolute private B paths, Git objects, retained source/tool/provider files, old workspace symlinks, and actual current_build workspace/cache/logs are required. A copied canonical evidence report alone is not a portable build tuple. State these requirements directly; packaging needs a later explicit vendored evidence/runtime mapping and fresh validation, not a silent path rebasing mode. No portable/installable/reproducible whole release claim.

Narrow negative cases: allowed historical path with wrong requested SHA; bad/missing Git blob; attempted resolver access to added module/unlisted path; modified historical helper; duplicate/unknown/overlapping delta; old hash/label/index mismatch; missing added current module; changed host/object/object order/depfile/provider/tool/tuple/alias. Use real production validator and disposable records/files, keeping compiler/native execution out of these read-only contracts. Preserve protected-launch rules when the root runs QA.
