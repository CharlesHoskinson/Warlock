# Visible menu integration handoff

The candidate connects native context invocation to the existing shared controller,
strict provider decoder, bounded menu ledger and actual Shell/Effects allocator.
Menu replacement renews the lease. Disabled rows and stale publications cannot
allocate an operation. A selected enabled row closes the presentation in the same
atomic commit as one generated native command. Late original-key receipts update
the retained menu mapping even after another engine transaction or frontend rebind.
Fresh observed facts remain separate from receipts and never release Unknown.

Protected CPU evidence currently includes 48 visible-controller checks and the
preserved V98 20 replay, 27 Shell and 55 surface checks. Actual app and native builds
are separate compatibility gates. Early compile faults, fixture corrections and
failed native observations are retained rather than overwritten. The original V98
and V3 closures remain unchanged; the prepared freezer checks their captured
hashes as well as each selected V4 source/report tuple. Earlier component Quint
models do not establish implementation equivalence for these new transitions.

The private native menu campaign passed 47 checks with normal cleanup:
`qa/native-1791087420757458406/report.json`, using frozen build
`qa/build-1791087406363320802/report.json`. It exercised real right-click,
Menu and Shift+F10, disabled rows, dismissal, broker-stopped command publication,
authenticated Minimize/Restore receipts and target retirement. This is bounded
single-output native evidence; complete gesture interleavings and release remain
open. The original failed attempts are preserved.

WebKitGTK replays unhandled keys asynchronously through GTK, including an older
Shift press after F10. The native receipt gate now suppresses confirmed duplicates
before mutating proof/epoch/held state. Per-source timestamp watermarks and bounded
same-timestamp signatures preserve distinct Shift/F10 events. Capacity exhaustion
and ambiguous ordering cancel pending and asynchronous proofs; overflow presses
remain held, and epoch exhaustion rejects admission. Twenty standalone C checks
exercise replay classification and timestamp/resource boundaries; they do not
execute the GTK wrapper's cancellation state. Escape uses the current menu scope
when a disabled-row click clears DOM control focus.

The new native harness verifies the actual picker DOM identity before invoking
keyboard context, then verifies the menu's native incarnation. It retains the
six-second observation deadline. It checks disabled actions, actual popup closure
while the broker is stopped, one Minimize/Restore intent with native scene facts,
and menu closure on target retirement. The separate V93 derivative preserves its
original scenarios and deadlines. Both run only through the serialized wrapper;
CPU agents do not run GUI campaigns concurrently.

After production and QA sources stabilize, rerun protected `qa/replay.py` and
`qa/build.py`. Review and run the native menu lane and preserved regression lane
serially, keeping failures and cleanup evidence. Only then invoke the protected
freezer, passing each successful native report explicitly with `--native-report`
and `--regression-report`. The freezer refuses failed or stale tuples and an
existing immutable manifest. It can capture CPU-only evidence when native reports
are omitted, with those qualification gates still open.

Remaining work includes complete gesture/chord/repeat/stale-render interleavings,
bar keyboard invocation, opener focus restoration, accessibility, mixed-scale and
multioutput geometry, application/Files/background providers, all-origin uncertain
operations and lost-broker journal recovery, hardware budgets, IME, the complete
native roadmap and release/user journeys. The manifest must keep
`wholeFeatureAccepted`, `newNativeGuiAccepted`, and `roadmapCompleted` false and
`completedRequirementIds` empty.

The independent `qa/scenario-oracle.json` preserves the accepted V93 91+1
check-name multiset and original source/fixture/report hashes. Freezing checks
whole normalized regression AST equality, exact check/wait call arguments and
order, lane-specific script identities and required menu observations. It does
not substitute a shorter native scenario for the preserved regression.
