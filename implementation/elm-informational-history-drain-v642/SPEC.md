## Contract

A known exact historical origin whose UI reservation was already released remains released. Its new, strictly correlated native retirement announcement can authorize an informational ready/read turn so the serial backend can deliver a fresh certificate and advance to later scopes. Informational participation does not import a live reservation, change Unknown truth, invent a receipt, clear another origin, consume effect counters or replay an old choice.

The existing bounded64 origin slots retain released=true and immutable record/history. The model additionally holds one `informational : Maybe Proof`. Announcements require the same current binding, different queried binding in the same lifetime, a known matching full historical scope and a strictly newer native proof sequence for every matching slot. A different informational or live active scope refuses premature replacement. If a scope includes a live Unknown, ordinary live proof bookkeeping owns that turn; only an entirely locally released scope occupies the separate informational proof.

Informational read requests and admitted replies use the same per-domain expectation and accepted-context guards. Ordinary read emission includes the informational proof ready acknowledgement before the request pair. Only one informational proof is ready at once; historical released slots do not collectively emit an unbounded ready batch. Original current-proof and accepted-frontier guards remain.

An exact strict released frame can validate both live and already released slots. Its record/proof/current accepted IDs/full contexts must pass the unchanged ReconciliationFrame decoder. A matching informational proof then clears the informational state. SurfaceController stores this bookkeeping change even if there is no remaining live Effects.Unknown to clear; it emits no effect or refresh. A malformed informational release cannot clear the active scope. Real live release still follows the original exact/shared-origin/menu reservation rules. Disconnect/binding replacement resets informational/proof/read state without changing released history.

The frontend still refuses a reannounced Unknown for an already released slot, preserving idempotence rather than reblocking it. The historical proof itself is the informational handshake. An unrecognized record/scope, foreign/current queried scope, Future grant or duplicate/stale proof cannot create another ready turn.
