# Qt6 role-journal fixture handoff

This derivative implements an actual Qt6 Widgets/Wayland fixture. CPU qualification covers the real command parser/binary entrypoints and extracted local lifetime functions. No Qt display connection, modal protocol, delivered input, compositor mutation, pixels, or full roadmap acceptance has been qualified here.

The build pins Qt6 6.11.2 and its private QWaylandWindow native interface, all compiler headers, linked libraries, tools and the actual Wayland platform plugin. Use the descriptor client-build-report.json and verify the complete component manifest before a private native attempt. The parent owns all GUI/native execution.

`--run` selects window-modal; `--run-application-modal` selects the toolkit-wide adversarial profile. Both use the same commands and per-process identity journal. Qt modality/type flags are requested or client-observed metadata. Actual xdg_dialog/parent/popup/grab protocol and compositor modal/input blockers require independent raw protocol and native observations. Qt has no GTK WindowGroup equivalence; the window-modal versus application-modal difference must be characterized directly.

Commands include create-owners, create-family, open-owner, open-modal, close-modal, close-owner, open-nested, close-nested, open-popup, close-popup, reparent-modal A|C, inspect, minimize/restore/maximize/unmaximize A|C and quit. Canonical increasing sequence numbers are owned by the caller. Reparent preserves B's draft and follows the selected modality; D/P local retirement is deferred, so the runner must settle actual resource retirement/parent transitions instead of treating deletion requests as server receipts. Local family retirement follows current widget parent ownership, including B moved from A to C.

Window and widget recipient events remain separate: native QWindow platform delivery differs from propagated QWidget handling. Preserve the entire unfiltered JSONL log, both profile selections, immutable role instance, actual map generation, PID/start, wl_surface resource and source resource, raw event/time/position and controller/widget fields. Drawing records are client queued observations; real screenshots and stable allocation/native joins are required for pixel acceptance. Normalexit proves local deferred QObject cleanup only; require actual native client census before unloading the private authority.

The canonical runtime helper is byte-identical to frozen247: direct owned0700 `/run/user/UID/wqa/leaf`, no aliases/dot components, exact FD-resolved path. The client additionally requires QA scope/core limit, Wayland backend, raw client protocol logging, owned display basename/socket and a same-UID peer probe. That probe is a different connection from Qt's actual display connection; it cannot establish the latter's exact PID/start or prevent concurrent same-UID path replacement. Keep the outer protected host/socket/process/module checks.

Retain raw per-process WAYLAND_DEBUG output unchanged. No log parser is supplied here and no assumption is made about `[123.456]` versus `[HH:MM:SS.ffffff]` timestamps or `{queue}` annotations. A future parser must accept the actual owning library dialect and reject ambiguous resource joins. The runner must use an isolated owned session bus and account for all activated portal/accessibility/GVfs descendants and their normal teardown; this fixture neither changes the user's bus nor proves descendant cleanup. CPU tests create no GUI or private bus.

Historical compile/test failures and their exact source inputs are retained. CLI controls mutate the actual production command header. Lifetime controls mutate extracted actual functions while real QtCore QObject/QPointer/deferred deletion is used; QWidget/QWindow and journal are explicit mocks. These results cannot be transferred to actual Qt event delivery, AT/IME, popup routing, renderer support, or complete S01–S16 requirements.
