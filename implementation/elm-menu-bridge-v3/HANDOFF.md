# Shared menu adapter handoff

The production bridge uses the existing Shell/Effects command allocator and
the owned TaskbarShell derivative routes menu and ordinary taskbar actions through
it. NativeProvider builds validated capabilities from coherent native window
facts and canonical ownership roots. The shared Main and Popup applications are
compiled for compatibility; their renderer protocol still needs context-menu
integration before this becomes a visible native desktop feature.

Receipt registration precedes forwarding. The independent original-key menu
ledger remains usable after another engine transaction or frontend rebind.
Taskbar primary, picker selection and direct Shell.Act routes apply the same
menu-origin outstanding-family guard. Failed unsent registration rolls back the
prepared engine state; it does not claim that a previously forwarded command
failed. A strict common receipt shape gate includes ordinary Activate outcomes.
It runs before serialization and before the older singleton handler.

Stale menu events preserve a newer picker. Valid primary actions dismiss the menu
view while preserving its operation ledger. Any resulting engine detachment,
including failed attachment, marks the menu ledger Unknown and dismisses its
view. These guarantees do not supply a journal query for outcomes lost with a
broker, and do not retain ordinary taskbar-origin operations independently of
the engine's singleton transaction.

Exact source closure, attempted builds, compiled fixture results and applied
mutation reports are retained in qa/. The original V2 Quint evidence is separate:
it does not establish formal implementation equivalence for these new adapter
and disconnection transitions. Compile diagnostics and failed fixtures remain
part of the archive.
