# Event-driven native Elm webview

The real GTK/WebKit layer surface now renders the verified native observation projection from `elm-authority-v3`. The native-to-DOM path is implemented, with immutable Elm state, keyed identity-bound rows and persistent incoming subscriptions. Native window actions remain unavailable; unknown minimization state is explicitly shown as unavailable.

`src/Main.elm` uses the already verified pure observer and nullable-state decoder. Incoming attachment is supplied by the native host's verified backend. Outgoing effects are strictly read-only snapshot requests. View state and enabled controls derive from the model. Rows are keyed by full lifetime/session/frontend binding plus incarnation, preventing local ID reuse across restarts from borrowing an old row. There are no historical Elm `Signal` APIs or frontend per-frame native geometry loops.

The owned Python backend verifies the authority process, executable, runtime, session and peer credentials. It subscribes to the native notification socket before requesting the initial projection. It converts relevant change notifications into refresh requests and obtains a fresh atomic window projection. Raw notifications, including titles, do not enter the Elm model. Observation notifications may coalesce over 40 ms before snapshot publication. This channel is not a reliable chord/outcome/control journal and cannot be used for those events. When idle, the selector waits without a polling timer. A bounded control/receipt stream and the complete canonical scene still need implementation.

The native C host owns one backend process, bounds incoming frames to 1 MiB and outgoing messages to 4 KiB, and permits only the declared read-only message kinds. Asynchronous writes keep the main loop responsive; one active and one latest unsent observation request are retained. Replaced unsent requests have not reached native publication and carry no mutation effects. Backend failure disconnects observation state rather than enabling actions. Backend requests cannot select an executable, file or authority endpoint through web content; only trusted launcher arguments select the reviewed backend/config. Assets use the existing fixed local-origin allowlist and CSP, navigation is constrained, storage is ephemeral, and the WebKit sandbox setting remains enabled. This is not complete OS sandbox or native-effect admission qualification.

The protected serial native proof observes a real Wayland fixture in the actual Elm DOM, captures the visible layer, unmaps/remaps the fixture, and verifies an event-driven disappearance and fresh incarnation in the DOM. It checks normal host/backend exit and cleans clients before unloading the plugin and stopping the private compositors. No user desktop windows or configuration were changed.

The QA-only graphics probe rendered a cyan WebGL canvas, read `[0,255,255,255]` without GL error, and found the same cyan pixel in the compositor capture. The sandboxed WebKit process held `/dev/dri/renderD129`. A separate engine diagnostic view reported `Mesa Intel(R) Graphics (ARL)`, Intel, accelerated 2D canvas and the DMA-BUF renderer, on that same DRM device. This establishes hardware graphics availability in this isolated Intel/Mesa path. It does not qualify all rendering workloads, latency, budgets, NVIDIA, high refresh, multiple outputs or assistive technology. The browser-exposed WebGL renderer reported `Apple GPU` on this Linux host; it was not used as the physical GPU identity. The old driver-filename heuristic also misses the installed merged `libgallium` filename; native diagnostics and device FDs provide the positive evidence.

`navigator.gpu` was absent. WebGPU is unavailable through this tested WebKit build. GPU acceleration therefore does not depend on WebGPU here. Alternative engine/native WebGPU experiments and graceful capability policy remain delivery work.

The GPU diagnostic view is separate from the application view and is available only through the explicit QA CLI mode. QA canvas/projection observers are injected only in QA mode and do not become product UI. The first screen is an inspection view, not the final taskbar/switcher design. The private AT-SPI registry warning remains an unqualified accessibility gate.

Failed attempts are retained. The backend initially failed on bytearray membership in an event-name set; conversion to immutable bytes fixes that actual parser fault. Earlier diagnostics were suppressed, and the first source-preflight check correctly rejected a changed QA runner. Build receipts freeze compiler inputs; native runs verify compiled source/assets/backend and bind the current runner hash independently. Original failure deadlines and native parity campaign assertions have not been changed.
