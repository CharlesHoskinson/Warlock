# Pure size-policy integration review

The actual V395 derive/Bounds.admits entry path is ready for bounded pure-policy use when callers provide already-validated measurements in the same size/box convention. No arithmetic defect was found on that path under its finite, nonnegative, zero-raw-maximum and optional/DBL_MAX-layout-maximum contract. Either-axis positive equality disables resizing; contradictory intervals and zero layout maxima refuse. Raw positive maximum1–4 remains restrictive even if the layout source has normalized it away.

Protected actual-header CPU review `qa/review-1791124329570836574/report.json` compiled the captured unchanged helper, witnessed feasible minimum-only admission, tiny raw maximum rejection, derive’s NaN rejection, and a direct-helper counterexample. Exposed intersect() does not validate its arguments: intersect(0,0,NaN,DBL_MAX) can admit800 because std::max ignores the NaN second operand. This is a real unsafe-call behavior, not a derive defect. Use only derive for validated admission, or make the internal helper private/validated in a fresh derivative; do not expose intersect as a general strict parser/policy API.

Native integration is not ready. Raw client hints, effective layout values and optional rules cannot be intersected merely because each uses doubles. V155 identifies window-geometry-origin conversion, compositor reserved extents, rounded visual targets and distinct ordinary/MAX paths. SB005’s chosen workarea must first be projected into the actual configured-client dimension and corresponding rule/layout box. SB006 must not compare both saved logical/visual sizes to one client interval. V161’s distinct bound observations and operation-specific prospective boxes are necessary integration inputs, not facts this helper derives.

CWindow rules override effective protocol bounds, while raw protocol maxima below5 can disappear from layout maxSize. Preserve independent raw hints; never infer that absent layout maximum cancels a raw restriction. Missing optional layout bound here means known absence, not unavailable/untrusted measurement. The V161 unavailable/invalid states must refuse before calling this API. Raw zero maximum means unbounded; layout zero maximum means invalid; DBL_MAX is the explicit layout sentinel. Do not feed Infinity, arbitrary sentinels or improperly converted tiny values.

Fresh integration must specify whether same-space intersections are computed separately for raw-client and layout/rule prospective dimensions, and retain the raw restrictions when rules override. Check live conversions and bounds before dispatch and after callbacks; keep exact-original scope, Unknown, full-key, fixed-axis and ownership gates.
