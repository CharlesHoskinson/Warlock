# Experimental effective configure-axis guard

This fresh isolated prototype proposes a profile guard for V168's actual V402/V406 cross-source fixed-axis counterexample. It grants no native capability, protocol integration, model or broad policy acceptance. Source implementations, original1710 tests and all existing oracles remain unchanged in their original lanes. V161 formal review is a separate prerequisite.

- EF-001: Retain the existing zero-origin Wayland projection, logical/visual/real/configure distinctions, signed-int range, finite/positive input, per-source contradictory/fixed checks and independent raw-versus-layout applicability checks.
- EF-002: For each axis, characterize possible positive integer configure values `c=floor(real)` without intersecting layout-real dimensions directly with raw-configure dimensions. Proposed lower bound is `max(1, ceil(rawMinimum), floor(layoutMinimum))`. Proposed upper bound is `min(INT_MAX, rawMaximum==0 ? INT_MAX : floor(rawMaximum), floor(layoutMaximum))`.
- EF-003: Reject when either axis's effective configure interval is empty or a singleton. Equality reached through different sources is fixed under this proposed profile even when each source interval separately remains nonfixed. Bounds with at least two possible integer configure values are not rejected merely by this guard; the existing projection/applicability checks still apply.
- EF-004: Bound interval arithmetic before integer conversion. Preserve zero raw maximum as unlimited and finite DBL_MAX layout maximum; retain tiny positive raw maxima. Fractional layout lower/upper apply in real space, so floor(layoutMinimum) is deliberate. Do not clamp/project dimensions to satisfy constraints or guess nonzero origin conversions.
- EF-005: Preserve the projected target/real/configure outputs for every accepted original case. This guard cannot retry effects, mutate native state, allocate operation identity, change saved originals, alter Unknown disposition or grant native capability.
- EF-006: Compile the unchanged original1710-test fixture against both the original helper and the experimental helper; retain all outcomes, including any compatibility failure. Independently test cross-source equality both directions/axes, fractional real versus integer raw bounds, empty intervals, two-value intervals, tiny maxima/default minimum, GTK108x42, decorated MAX and ordinary restore.

Concrete proposed oracles: raw min128/unbounded plus layout min1/max128 rejects configure-width128; raw min0/max128 plus layout min128/unlimited likewise rejects. Raw upper129 and layout lower128.9 admit a prospective real129.75/configure129 when the effective configure interval is128..129, proving that comparing real against raw upper129 is wrong. Raw max1/default positive configure min1 rejects; raw max2/default min1 retains interval1..2. Invalid/fixed input sources continue rejecting independently.

This integer-profile rule does not establish a full coordinate-aware formal model, nonzero-origin conversion, decoration/restore compatibility, negotiated wire consumers, actual callback/ACK/pixels or shared08/09/10 acceptance. Independent review is required before adoption.
