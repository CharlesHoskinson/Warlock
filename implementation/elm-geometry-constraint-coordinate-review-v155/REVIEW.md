# Constraint coordinate audit

Core89 keeps the owning geometry73 Window/XDG objects and unchanged layout/fullscreen-handler archive members. Exact source hashes and archive payload evidence are in reviewed-inputs.json. Window/XDG sources here are frozen core89 captures; layout implementation reads are from the original owning source tree, explicitly distinguished from binary acceptance. No source, model, binary or GUI was changed.

`layout/target/WindowTarget.cpp:402–407` delegates minSize/maxSize to CWindow. Frozen `desktop/view/Window.cpp:2892–2928` gives configured window rules precedence over protocol hints, clamps minimum to at least one, and maps each maximum below five to the unlimited sentinel. noMaxSize may suppress protocol maximum entirely. A new authority must retain raw positive maximum 1–4 and cannot recover discarded protocol limits from target.maxSize alone.

Frozen `protocols/XDGShell.cpp:467–482` converts each raw hint greater than one by adding the current xdg_surface window-geometry origin on that axis. This is an offset in logical surface coordinates, not monitor scaling. It is not safe to pretend raw hints and target bounds are identical dimensions. `CWindow::realToReportSize` at 1688 returns real goal size for Wayland without multiplying monitor scale; sendWindowSize at 1735–1756 passes that size to xdg configure. X11 force-zero-scaling has a separate conversion; current geometry eligibility excludes X11 and must retain that exclusion until independently supported.

`layout/space/Space.cpp:79–110` computes monitor logical box minus reserved layers, then separate floating gaps and regular gaps. `FullscreenHandler.cpp:195–198` chooses workArea(target.floating()) for MAX. `Target.cpp:11–14` rounds logical and visual boxes. `WindowTarget.cpp:94–107` rounds the MAX visual box, subtracts compositor decoration reserved extents, sets the real window box and sends configure. Consequently the actual client configure size can differ from the bare workarea size. CSD window-geometry origin and compositor decoration reservations are separate facts. Do not subtract/add either twice.

The MAX branch returns before normal floating/tiled size clamps. Thus core89 does not independently clamp MAX to client min/max; merely removing authority90’s blanket rejection can produce a size incompatible with client hints. The new contract must calculate the same prospective real/configured size as the owning handler, check raw constraints in the actual configured-client coordinate convention, and check normalized/rule constraints in their intended box convention. Reject unsupported conversions instead of intersecting dimensions from different boxes. Preserve positive raw maxima even when core rules or normalization suppress them, unless the specification explicitly authorizes a different override policy.

For exact RestoreGeometry, evaluate the recorded original logical and visual rectangles through the actual ordinary floating restoration path, which sets the logical box directly before configure; it does not repeat the MAX reserved-area subtraction. Changed decorations, window-geometry origin, constraints or output/workarea scope require an explicit compatibility decision and recheck. Successful native mode mutation alone proves neither client ACK nor matching presented pixels.

Before source changes, specify a shared pure projection of prospective logical target, visual box, real client box and configure size, with finite positive checks and exact rounding. Cover zero/unbounded and positive tiny maxima, lower bounds alone, rule precedence versus preserved protocol bounds, nonzero/negative geometry origin, nonzero reserved extents, fractional workareas and monitor scale 1/2. Derive operation eligibility from those prospective sizes and live bounds, then recheck after callback/readback. Do not implement model transition logic until approved. Rebuild a fresh owning authority pair and qualify real decorated GTK and constrained xdg clients; V152’s failed shared menu and full geometry 08/09/10 remain open.
