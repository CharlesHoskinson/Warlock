# Native read-only observation authority

This slice connects the typed Elm observation policy to real native windows in an isolated compositor. It does not change the live desktop or enable window actions.

`native/authority.cpp` registers one `elm_observe` command against the exact candidate core/header tuple used by `maximized-stack-v2`. The compositor invokes its handler synchronously on its event thread. One handler invocation captures this bounded window projection, without subprocess queries, nested dispatch, event-loop pumping or window mutation. The revision covers the projected data and order only; it is not a committed full scene revision or a presentation receipt. Sequence numbers order these inspection snapshots; native control-event streaming and journals remain unimplemented.

Window incarnations use a monotonically increasing native counter and weak native object references. Existing mapped windows are seeded at load. Native open/close events assign/retire IDs; remapping receives a fresh incarnation. Pointers, titles and PIDs are not serialized as window identities. Plugin reload establishes a fresh random authority lifetime and invalidates old bindings. That lifetime identifies this authority instance, while the handshake separately binds the actual compositor PID and full instance signature. Random 64-bit tokens provide probabilistic uniqueness; the production supervisor still needs its durable identity/restart policy.

The native command obtains the caller PID from the compositor IPC server's `SO_PEERCRED`. It binds each read-only session to that PID and its kernel start time, checks UID ownership, and refuses borrowed session/frontend identities. Repeating the handshake advances that caller's frontend epoch. The registration ledger is bounded to 16 live sessions. Strict requests reject unknown fields/kinds, numeric or noncanonical authority counters, duplicate JSON keys and malformed bindings. Read-only snapshot requests are the only admitted operation.

`adapter/endpoint.py` accepts a supervisor-selected private runtime directory, instance, native PID/start time and expected executable SHA-256. It checks directory ownership/modes and symlink policy, socket type/identity, server peer credentials, actual running executable identity/hash, process lifetime and the returned session identity. Requests use only the fixed observation command. Responses require bounded complete EOF delivery and strict schemas. A same-UID socket or a matching version string alone is insufficient. This is local read-only identity verification, not an effect-capable security boundary or protection against a compromised same-user compositor/plugin.

Experimental protocol version 3 reports `minimized: null` because this native adapter cannot yet establish the new minimization state. The copied Elm decoder uses `Maybe Bool`; unknown state is preserved rather than fabricated from hidden/scratchpad state. The native handshake advertises `effects: false` and `minimizedState: false`. No screenshot/buffer capabilities, focus, pin, workspace or minimize action exists. Window titles remain private local observations; retained proof fixtures use a public synthetic title.

The native proof starts a reviewed private Weston/Hyprland session with Xwayland disabled and DRM fallback disabled. It loads only the exact paired observation plugin, verifies both native/session identities, tests malformed and borrowed bindings, observes a real Wayland window, unmaps/remaps it, verifies normal fixture exit, reloads the authority and rejects old bindings. Actual snapshots are replayed through the actual compiled nullable-state Elm reducer, including every projected window record. Additional negative fixtures test a wrong socket peer, a symlink socket and an unsafe runtime. These tests do not qualify full scene eligibility, painted/hit/focus agreement or application effects.

Builds use an immutable per-attempt copy of source, exact owning headers, and recorded compiler dependency hashes. The first failed build is retained: owning upstream header aggregate initializers triggered `-Werror`. Owning headers are now treated as system headers; warnings remain errors in the new translation unit. No upstream header was edited to suppress them. All attempts and native evidence are retained.
