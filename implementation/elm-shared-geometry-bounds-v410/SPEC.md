# Strict geometry bounds consumers

GC001–009 authority409 applies. The broker and active Elm host shall negotiate
observation2 explicitly. Version1 remains available for explicitly requested
legacy transport/decoder tests, with its restrictive constrained-size semantics.
The active host shall reject old1 attach/facts and unsupported versions.

The strict sizePolicy shape is inputs/maximize/restoreGeometry, with null inputs
meaning unavailable/invalid conversion observation and null projections meaning
operation unavailable. The inputs profile alone never enables a capability.
Consumers shall validate finite size bounds, separate configure versus real
spaces, reservations, zero-origin supported projection, integer configure range,
effective fixed intersections, exact per-operation box conversion and enabled
capability coherence. A finite nonzero origin can be observed but cannot carry
any projection or enabled geometry operation. Missing/unknown fields refuse.

When a valid fitting minimum-only window is observed, typed effect and menu
controllers shall allow its negotiated native capability without the prior
blanket constrainedSize rejection. Existing binding/revision/scope/Unknown/key,
input/minimize/family/mode/fixed/retained-original guards remain unchanged.
Synthetic tests prove decoding and controller routes only; require exact native
ABI tuple, configure/ACK/pixels and original397/08/09/10 qualification.
