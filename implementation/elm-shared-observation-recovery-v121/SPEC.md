# Current observation recovery and topology supersession

V121 is a fresh derivative of held V104. It changes only production Shell.elm and OutputController.elm; Main, native C, admission storage and the literal full-batch certificate carrier remain byte-identical to V104. It adds no Quint logic or GUI campaign.

The same shared Shell.matchesUnsent guard now checks current observation IDs before any popup dismissal or prepared-selection cancellation. An exact certificate for completed/replaced reads consumes its old transport record without UI effects, request allocation or cancellation. Compiled frozen V104 controls reproduce both defects: an old same-lease certificate closes a newer menu and cancels a newer prepared selection. The candidate prevents both.

An admitted authoritative topology revision invalidates observational request IDs and allocates fresh paired reads under a live selected view. Supersession is permitted for reads even if they might have been forwarded; it does not claim those reads were unsent. Late old responses and old-view certificates cannot satisfy the new correlations. Zero outputs retire read IDs and forward no authority request. A newly issued live view after zero outputs restarts observations with fresh counters. Retired transport records and conservative transport exhaustion reset at this authoritative boundary. Native operation counters, issued full keys, Pending/Unknown Effects entries and Menu receipt-router mappings are preserved.

Topology cancels only a prepared selection that has not allocated a native intent. Any earlier read effects generated in this same, still-unsent update are filtered before Main registers the final batch. Native mutation effects are retained. Fresh observations are bounded and use the existing single allocator; no action or native effect is replayed.

Geometry attachment has an explicit attachNeeded state independent of an old request ID. It survives topology retirement and zero outputs, is set by actual attach request allocation and cleared only by a matched attached/unsupported response or disconnection. Central refreshObservations prioritizes this requirement for topology reissue, dirty-bit drainage, deferred-notification resumption and operation receipts. Availability remains false until attachment completes. A reproduced failed candidate lost attachment across zero outputs; a later reproduced candidate incorrectly emitted geometry facts after a Pending operation's definitive receipt instead of completing its cleared attachment. Both failed source/input snapshots are retained.

The imperative compiled/C oracle covers exact literal-wire certificates and forged/stale/duplicate/mixed variants, both operation protocols, real Menu-origin actor B Pending/Unknown preservation, actor A recovery, and B's exact original-key terminal routing afterwards. Topology cases include zero/reacquisition, counter capacity recovery, stale old read/attach responses, prepared cancellation and deferred attachment after Pending/remaining legacy reads. Synthetic facts and receipts in CPU tests are controls, not proof of native execution.

Operation-only unsent terminal semantics are deliberately not introduced here; V122 owns that separate local-proof path. Journal-admitted/uncertain storage and popup-failure recovery, oversized/cross-binding generic catalog/launch/reconnect traffic, integration with the latest shared native input host, the original six-second native retirement scenario and one reviewed combined runtime tuple remain unqualified. The unchanged original byte-exact immediate-dispatch diagnostics remain failures; the staged semantic211 suite is separately passed. Full recovery/native/release gates remain false.
