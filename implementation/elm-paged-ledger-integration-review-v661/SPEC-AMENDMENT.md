# Proposed V7 integration contracts (before implementation)

These add precision to proposed ARC-001–014. They do not change frozen V608,
V624, V630, V629 or V647 and do not authorize a schema/protocol switch.

| ID | EARS contract | OpenSpec executable acceptance scenario required |
| --- | --- | --- |
| V7-001 | The paired ledger shall compare the exact validated canonical `(effectProtocol,binding,complete intent)` origin and retain exact predecessor bytes; digest, UInt64 prefix, target address and status shall not authorize origin equality. | Force 32 routing-prefix collisions and a full-digest collision; retain distinct full records or refuse before effect. Change each binding/intent field independently; none aliases. |
| V7-002 | When committing Admission, the ledger shall atomically publish the exact origin, live reservation, independent request/generation maxima and reserved worst-case completion capacity in one validated generation before native invocation. | Crash between every event/index/root publication; no usable root exposes admission without maxima/reservation. Repeat request and separately repeat generation fail closed. |
| V7-003 | When authenticating native retirement, the ledger shall independently conserve scope retirement and native proof-sequence maxima without deriving these from archive count/generation or unvalidated caller JSON. | Archive counters with negative, Boolean, noncanonical or overflowing values are rejected by authority; increasing request cannot repair stale generation/proof sequence. |
| V7-004 | While a restarted root or migrated store has not passed source validation and fresh directory barriers, the paired producer shall refuse effects, admission unlink, release wire and progress acknowledgements. | Visible Prepared/Released/activation rename before directory fsync survives process death but cannot authorize output before restart barriers; power loss uses surviving durable roots. |
| V7-005 | When completing an exact Unknown, the ledger shall conserve its original bytes, publish Prepared proof/join, unlink only its exact admission with directory fsync, publish Released, then publish a separately anchored current delivery certificate before wire. | Crash at every boundary, restart repeatedly, lose release output, then reattest using a fresh accepted pair; original Unknown/release/certificates remain byte-exact and no old intent replays. |
| V7-006 | When paging recovery history, the coordinator shall pin an immutable generation, prioritize all live reservations, publish complete cohort records before its proof, and bound the combined live plus informational tracking to 64 without considering successful output a frontend acknowledgement. | More than 64 retained releases, full live census, retained-view mixed already-delivered/lost records, output loss and repeated restart; each unacknowledged origin is revisited and unrelated new live origin remains blocked correctly. |
| V7-007 | When advancing or retiring an informational cohort, the frontend and coordinator shall correlate an explicit accepted cohort acknowledgement to the exact current binding, generation, cohort and full-origin certificate set; they shall retain all unresolved slots and never create an effect. | Wrong/future/foreign cohort and partial acknowledgements cannot advance or discard Unknown; final reply emits next reads before queued release without clearing last accepted stamps; absent old slot cannot authorize action. |
| V7-008 | When migrating schemas 3–6 and delivery sidecar 1, the migrator shall retain all original source bytes, exact records, immutable release anchors, every available certificate and independent maxima, validate conservation, then durably activate only paired schema7 readers/writers. | Mixed old writer, overlapping Prepared/Released, malformed certificate, missing watermark and interrupted activation all refuse; every old full origin has a conserved destination and no watermark decreases. |
| V7-009 | If archive capacity, lock ownership, UInt64 arithmetic, publication, reservation or migration validation fails, the ledger shall refuse before effect or preserve post-effect uncertainty without evidence eviction or optimistic success. | Reserve worst-case terminal/release/delivery space before effect; exhaust bytes/inodes/reservation and overflow each independent counter; no terminal state is inferred from absence. |
| V7-010 | Where full S15 acceptance is claimed, the integrated implementation shall qualify bounded memory/queues, nondecreasing replay authority, source/toolchain closure, paired C late admission and frontend historical-slot lifecycle across at least 10,000 same-lifetime cycles and reviewed crash/power-loss campaigns. | Actual filesystem/C/compiled Elm/native integrated run with measured resources and original behavior deadlines; independent provenance and sustained scaling gates remain separately reported. |

Cohort acknowledgements and activation handshakes require a reviewed protocol
amendment before source changes. The existing V3 strict release wire trio remains
unchanged in this proposal. A cohort ack is bookkeeping evidence, never native
retirement, a terminal effect outcome or replacement for an accepted read pair.
