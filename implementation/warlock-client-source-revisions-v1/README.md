# Applied client-tree revision prototype

The owning compositor records a read-only revision after surface state and texture
application, including synchronized children whose ordinary commit notification
is suppressed. A display-owned registry retires resource entries and returns
zero if storage or the revision domain becomes unavailable.

The capture plugin snapshots bounded root/child membership, native incarnation,
applied revision, accumulated position, order and synchronization. Changes advance
the client content context; incomplete snapshots refuse capture. Capture validates
the context before and after rendering. The original monitor context is retained.

The actual owning-header plugin and new retained-core archive compiled. The
separate tree-checks-v1 packet passed 65 compiled controls, nine selected Quint
scenarios, 300 samples and 21 coupled traces (508 compared states). The separate
source-native-v1 campaign passed all 73 existing root-client pixel, stale-context
and physical-retirement controls on this new exact tuple; all seven processes
exited normally and cleanup passed.

Native child-only commits, nesting, detachment, destruction/reuse, display teardown
stress and complete surface-tree fidelity remain unqualified. This prototype is
still falseeligible. Provider-v6/Broker/WebKit integration, original preview13,
family/output/minimized coverage, measured budgets and the full release remain
open. Omarchy command vocabulary and effective keybindings remain mandatory.
