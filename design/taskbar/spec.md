# Taskbar

## Overview
The top-mounted taskbar provides application access, window groups, utilities, recovery and persistent feedback. It is stationary, opaque and immediately present. The source order stays intact: recovery controls when present, pinned and ordinary groups, then utilities; detached state places utilities before applications. Nothing in CSS changes this sequence.

## Anatomy
`SurfaceRenderer.viewWithPreview` emits `.surface-bar` with a keyed `.surface-actions[role=toolbar]` and sibling `.surface-status[role=status][aria-live=off]`. Buttons contain optional decorative preview, `.control-label`, `.control-detail` and optional hidden description. `bar:group:` and `bar:pin:` identities map to `.control-group`; `bar:recovery-refresh` maps to `.control-recovery`; other controls map to `.control-utility`. Actual utilities include Applications, Task View, Switch windows, Notifications, Files, System and Settings. Scoped IDs, publication and lease remain unchanged.

The bar is `calc(3rem + 8px)` high. A 6px inset surrounds the scrollport and its controls. Buttons keep intrinsic utility widths; groups start at 128px and cap at 240px. Application labels may ellipsize with their full accessible names retained. Utilities stay readable. A 6px scroll margin keeps the complete focus outline within the scrolling area. Status occupies only its content width up to `clamp(160px, 24vw, 300px)`. Details occupy one line and ellipsize; the existing accessible name preserves their complete wording. The renderer enhancement supplies a keyboard-reachable disclosure for persistent status, with the full text available visually and without a second live announcement. Full application details remain available in the accessible name; a separate visual disclosure for truncated application details requires renderer support. The idle status has no stripe.

## States
Active application uses selected surface and a 3px brand-text bottom marker. Observed window focus adds a neutral 24 × 3px top marker. Keyboard focus uses the shared 2px focus outline and opaque 2px gap, only while `.surface-actions[data-document-focus=true]` owns document focus. Selection, focus and hover stay independent. A minimized group retains its existing detail. Pin identity and “Pinned launcher” identify a zero-window pin; the group count and attention detail remain visible. Disabled controls retain full opacity and disabled semantics. Attention requires a steady warning triangle next to the existing detail, without glow. Pending, refused and unknown feedback preserves source wording and uses its typed outcome symbol on a neutral surface. A neutral untyped status is not classified from its text.

## Behaviour and keyboard
One available family activates, minimizes when active, or restores when minimized. Multiple families open the picker. A zero-window pin invokes its available launcher. The adapter retains arrow, Home and End navigation, native focus ownership and scroll-to-reveal. Enter and Space use button activation. Recovery reads current observations and does not repeat uncertain actions. Status is static `aria-live=off`; the existing announcement owner speaks changes once.

The bar appears and disappears at 0ms. Pointer fills may settle using shared state timing. A launch intent has no portal. Only an observed newly mapped application window starts the shared portal; focus, minimize and restore do not.

## Accessibility and renderer requirements
The current renderer derives `data-window-state` and pressed state from detail text, gives attention precedence over active, and provides no independent observed-window-focus attribute. D01 projects typed independent `data-active-application`, `data-window-focused` and attention facts on each group, retaining simultaneous states. The CSS reads `data-active-application` and `data-window-focused` independently, and shows neutral presentation when the typed activity attribute is absent. The renderer emits an explicit decorative warning element from typed attention. It does not infer focus or attention from text. The attention triangle is decorative and the existing detail carries its meaning. D01 supplies a decorative `aria-hidden` warning glyph from typed attention, typed outcome symbols, and an unavailable cue for disabled controls. These additions preserve the existing accessible names, status announcement ownership, DOM identity and ordering. Until then the source detail provides the attention and operation wording, and the focus marker and outcome symbols remain absent. D01 provides a keyboard-reachable way to reveal overflowed persistent status without adding a duplicate announcement. D01 supplies the shared focus implementation and validates the 6px paint gutter in the real adapter and host.

Use `night`, `dawn`, `high-contrast`, forced colours, effects-off, reduced motion and reduced transparency with the same geometry. At 800px and 200% text scale all enabled controls remain reachable by horizontal scroll. Test 100/125/150/200% scales, 200% browser zoom, 320px effective width, long names, text-spacing overrides, keyboard-only traversal and focus on both scroll edges. No control or status obscures its focus indicator.

## Projection contract
`ActionProjection.focused` identifies the observed focused incarnation and `Taskbar.groups` maps its root to the family; group membership supplies the window-focus fact. `Taskbar.Family.active` derives from that observation; `Family.attention` aggregates admitted member attention independently. `Presentation.barControls` carries both facts through the keyed `bar:group:` or `bar:pin:` control, including pins resolved to a group. `SurfaceRenderer` decodes typed booleans and emits the three attributes without changing control identity, publication, lease or source order. The group detail retains both facts when both apply. A missing fact omits its attribute. The status disclosure retains the existing `aria-live="off"` owner and makes the full outcome available on keyboard request. The committed renderer does not yet provide these projections or disclosure. The staged renderer currently supplies a window-focus attribute, but still derives activity from detail text.

## Disclosure integration contract
The renderer retains the existing keyed status node and its `aria-live="off"` status owner. A keyboard-operable disclosure control follows the toolbar and exposes the complete current status in an opaque bounded panel. Enter and Space toggle it; Escape closes it and returns focus to its trigger. Opening does not move focus away from the taskbar unless the user navigates into the disclosure. Its expanded state is expressed by `aria-expanded` and linked by `aria-controls`. The panel never becomes a second live region. The disclosure trigger and panel reserve focus paint space and remain within the output. The source-shaped specimen demonstrates Enter, Space, Escape and focus return in the same bar as the status. D01 implements the same state in Elm and validates it in the actual renderer and adapter. The native taskbar host is height-bounded; the full panel uses an allocated anchored popup surface with a focus return path, not overflow outside the bar host.

The warning symbol is an explicit `aria-hidden` element emitted by Elm beside the detail, and the button's accessible name carries the attention wording. No generated CSS text conveys the symbol. Typed false overrides any legacy active state. No focus or attention fact is inferred from text or hover in the enhanced projection.

## Focus scrolling integration
The adapter measures the focused control after focus and after presentation or resize. Its allowed horizontal interval is the toolbar client rectangle inset by 6px at each end. If the control crosses either inset, it adjusts `scrollLeft` by the signed difference and remeasures after layout; the 6px scrollport padding makes both outermost controls reachable. The adjustment uses the actual physical rectangles and scroll position, including right-to-left scrolling, and never changes selection or document focus. The focus-applied path uses the same reveal routine after `focus({preventScroll:true})`. The current adapter's `restoreOnly` early return must still perform the reveal when the selected control already has focus. Document focus gates both restoration and the visible ring. The specimen reference is [specimen-interactions.js](specimen-interactions.js); it demonstrates focus-in scrolling only and does not replace production host navigation, handshakes or Elm state.

## Integration boundary
The committed renderer emits a static `.surface-status` and derives activity from detail text. It does not emit the disclosure, independent typed facts or typed outcome glyphs. D01 adds those source-backed projections and the Elm-owned disclosure before the production acceptance can pass. Until then the CSS gives missing facts neutral presentation and the original words remain available.
