# Stable targets and observed toggles

These requirements refine the design contracts DL-005, DL-007, DL-013, DL-014, DL-018 and DL-019 in the [EARS requirements](EARS.md). They state required design behaviour; the evidence for Warlock's behaviour is in the [current guidance](CURRENT.md).

- **WARLOCK-DL-TARGET-001 (event-driven):** WHEN asynchronous preview or status content changes while a control is pressed, the shell SHALL preserve the control's allocated target bounds through release and SHALL refuse any release whose admitted target identity does not match the press.
- **WARLOCK-DL-TARGET-002 (ubiquitous):** The picker SHALL reserve the same thumbnail slot and bounded status and detail geometry in Loading, Live, Historical and Unavailable states.
- **WARLOCK-DL-TOGGLE-001 (state-driven):** WHILE a window menu exposes Always on top, the shell SHALL use a stable label and a checked state derived only from the current correlated native pin observation, with Pending and Unknown reported separately.
- **WARLOCK-DL-TOGGLE-002 (ubiquitous):** The shell SHALL distinguish taskbar application Pin and Unpin vocabulary from the window Always on top control.

The [OpenSpec requirements](../openspec/changes/warlock-stable-target-guidance/specs/warlock-stable-targets/spec.md) give the scenarios: a preview arriving during a press, a target retiring before release, preview freshness changing, a native pin observation confirming, a Pending or Unknown outcome, and a stale observation or refusal. Across them, a pressed target keeps its bounds, a mismatched or retired release is refused rather than retargeted, another incarnation's pixels never stand in for a preview, an unresolved request keeps the last confirmed checked state with its outcome shown separately, a stale observation cannot change the toggle, and no mutation replays automatically. The [implementation workplan](WORKPLAN.md) tracks these requirements with the design contracts they refine, and the [Always on top evidence](../implementation/warlock/qa/evidence/pin-check/README.md) records the native pointer and keyboard journeys.
