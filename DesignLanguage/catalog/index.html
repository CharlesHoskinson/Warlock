The Warlock contributor plugin

One shared offline checker and implementation skill support Claude Code, Codex and Grok. The plugin helps contributors choose original EARS/OpenSpec scenarios, declare source ownership, plan proportional checks and record actual behavior.

  1. Inspect the original requirement and current source route.
  2. Plan one concrete user behavior and declare the files it needs.
  3. Run the required loop check, then implement in the real candidate.
  4. Compile changed targets and observe the decisive behavior and failure path.
  5. Record source changes or original-scenario verdicts, including missing observations.
  6. Review staged work, publish it and continue the next required behavior.
python3 -B plugins/warlock-contributor/scripts/warlock.py doctor
python3 -B plugins/warlock-contributor/scripts/warlock.py capabilities
python3 -B plugins/warlock-contributor/scripts/warlock.py inspect --requirement ELM-UX-016 --scenario ux-016
python3 -B docs/warlock-build-loop/v2/loop.py check

Run these commands from the repository root. The loop check requires an existing contribution record; use the contribution guide to plan and start your own record before implementation.

Read the design contribution guide · Read the plugin manual and client setup.

Scope. The checker does not build the product or certify native, accessibility or release behavior. Client hooks are advisory and differ by host; explicit loop checks remain required. A CI template is included, but no active GitHub workflow is claimed.
