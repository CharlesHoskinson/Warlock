# Warlock visual system

The existing Warlock identity is authoritative. Preserve its folded W and central diamond, “Crafted for flow.” tagline, ink/parchment palette with lilac, mint and gold accents, bundled Space Grotesk display face, Inter body/control face and JetBrains Mono code face. Dark and light themes use their distinct approved palettes. Esoteric identity lives in crisp folded geometry and restrained event-stream illustration; readable controls use familiar desktop affordances.

The catalog surface is Read mode. It uses a persistent documentation rail, searchable component index, a wide reading column with linked section navigation, and real state specimens. Foundations lead to Components, Patterns, Accessibility, Tokens, Evidence and Changelog. Each component uses the same six sections: Overview, Anatomy & states, Behavior & keyboard, Accessibility, Content and Evidence. This is the established visual world extended into documentation, not a replacement brand.

Token evolution is additive: reference palette -> semantic role -> component role. Publish explicit content/container pairs, interaction and outcome cues, focus treatment, spacing/type/density roles and forced-color mappings. Verify actual rendered contrast, responsive text/geometry, reduced motion and keyboard behavior. Source palette values remain unchanged. There is no decorative blur/glass or perpetual animation requirement.

The desktop remains Operate mode. Preserve target and control identity, declared disabled/focus policy, native presentation meaning and outstanding intents. Pending, Refused, Cancelled and Unknown have readable text and distinct cues; focus does not imply selection or settlement. Native timing and allocation limits are governed by their frozen contracts. Document Source Live/Historical/Loading/Unavailable preview behavior accurately; no catalog relabel silently changes it.

Actionable rows must reserve stable geometry before asynchronous preview content arrives. Allocate the same thumbnail space across Loading, Historical, Unavailable and Live, with a bounded detail-line budget. Content arrival must not move a target under a held press. Keep the press-time identity/publication/lease guard and refuse a mismatched release rather than redirecting the gesture. The current picker reserves this geometry; wider native lifecycle and independent qualification remain open.

Always on top should use a stable checkable label with checked state derived from current admitted native observation. Reserve Pin/Unpin wording for taskbar application pinning. The current implementation keeps the label and exposes observed checked state with a visible shape and menu checkbox semantics. [Scoped native evidence](../implementation/warlock/qa/evidence/pin-check/README.md) covers pointer/keyboard MAX toggles and physical overlap; full native accessibility and family/fullscreen adoption remain open.

Native adoption is incomplete. The shell uses a provisional palette and some local glow/shadow treatments; the approved layered-window tokens are not comprehensively applied. Effects-off and reduced-transparency preferences have native save/restart evidence, while comprehensive layered-token adoption remains open. Product reduced motion follows its observed source/override policy, rather than an independent CSS preference inference. Inset focus rings currently avoid clipping; DL-006 remains open for product scope until its outer-ring contract and measured contrast are reconciled. Unify search and button focus roles when adopting the tokens.

The approved 30 contracts and guarded/deferred decisions are in the exact consensus candidate. A browser demo is an isolated example using real Elm modules with explicitly simulated native outcomes. It cannot contact the compositor or alter evidence badges. Static style specimens never become a second desktop policy engine.

See [current guidance](CURRENT.md) for later surfaces, known deviations and contribution routes. The [Warlock contributor plugin](../plugins/warlock-contributor/README.md) supports implementation and evidence bookkeeping; a catalog or checker pass does not close native design gates.
