# Commit-bound compositor route assessment

Production remains6d9/widget65/v14; Qt66 is diagnostics only. V17 passes the isolated atlas matrix but is not loaded on main. A native compositor visual pass avoids Qt image decoding, private QPA borrowed handles, and Qt frameSwapped/error attribution. It paints the retained canonical atlas texture through CTexPassElement at RENDER_LAST_MOMENT, after normal windows/layers and before endRender/output commit. It has no input surface or focus object; every output shows only the atlas fragment on its normal transparent compositor pass. The shared route clock uses one monotonic start time; each output retains its actual presented origin for reversal.

## Exact commit identification is conditional

Exact installed Aquamarine headers provide commitAsync(), SCommitSubmission.id, SCommitResult.id and SPresentEvent.commitID. The accepted async submission snapshots pending output state; a submitted result precedes its presentation. DRM.cpp stores commitID in the pending page flip and propagates it to the actual presentation event. This gives a concrete association between the compositor output buffer that contains the atlas fragment and the presented frame. The compositor's current CMonitorState::commit() instead calls legacy IOutput::commit(); those presentations have commitID0. A generic output-present event alone cannot identify the route's rendered buffer.

The fresh implementation can intercept exact-ABI Aquamarine::CDRMOutput::commit only for a rendered route buffer on an output that advertises AQ_OUTPUT_COMMIT_CAPABILITY_QUEUED. The original CMonitorState::commit still performs updateSwapchain/ensureBufferPresent/preCommit before its virtual backend commit reaches this hook; no private CMonitorState fields or body are copied. The adapter then uses public commitAsync for that exact buffer. Exact exported symbol _ZN10Aquamarine10CDRMOutput6commitEv and Aquamarine ELF buildIDca6570c12287837304f3aa8bf700a0187519f225 are pinned, alongside the compositor ABI. It registers the accepted nonzero ID with the exact buffer pointer, output generation, token/ID/PID/digest, rendered rectangle and clock sample. Commit failure/cancellation/out-of-order/reused-output presentation has no authority. Rejection must leave the original pending output state untouched and use explicit safe settlement; it must not quietly count a legacy commit as a route presentation. Async scheduling adoption must be isolated and reviewed because it changes output commit behavior while motion is active; this is the largest additional risk.

Installed CDRMOutput advertises QUEUED only with atomic KMS and a commit thread. It rejects reconfiguration/nonbuffer changes, busy frame-in-flight, unsupported modes and unsuitable buffers. Installed CWaylandOutput and Headless headers do not override commitAsync or commitCapabilities. Therefore this route cannot claim a universal exact-ID producer for nested/headless outputs. No FIFO/time guess for commitID0 is acceptable. The prototype should discover capabilities read-only, then be tested first with actual GPU compositing/ledger in isolation and finally actual queued commitIDs on root's coordinated DRM fixture. The current normal scheduler can pre-render with commit=false and later submit; registry must follow the exact pending buffer, not assume RENDER_POST immediately commits.

## Alternatives

| Producer | Exact presentation association | Copies and clock | Main risks |
|---|---|---|---|
| Native compositor pass plus supported async commitID | Exact accepted output buffer→commitID→present; capability gated | Retained GPU texture; one native route clock | Commit scheduling integration and unsupported Wayland/headless outputs |
| Owned Wayland layer surfaces with explicit buffer attach/damage/feedback/commit | Exact owned surface generation and commit contents; no QPA alias | CPU raster first would copy/scale each frame; EGL can avoid those copies | Independent client/event loop/surfaces, measured raster cost at240Hz, output topology integration |
| Qt afterRendering feedback on borrowed QPA handles | Surface presentation exists, exact committed image is unproven after failed/skipped endFrame | Qt texture and render cadence | Delayed request can attach to later commit; borrowed handle lifetimes |

Recommendation: stage the native GPU pass and commit ledger first, retaining explicit unsupported capability failure. Do not deploy new output scheduling or use native-ready/done until exact commit acceptance/result/presentation and source digest/identity checks pass formal and actual producer tests. The owned-surface producer remains a concrete universal alternative if async capability coverage or scheduling safety blocks the native route; CPU cadence cannot be assumed acceptable.

## Authority and teardown

The actor still owns fresh family/identity/native commits. Native reserve may retarget retained pixels immediately, with no native endpoint event before the actor's fresh validation/promote and all required output presentations. Source atlases are identity/epoch/digest scoped, bounded, and never recaptured during an eligible rapid reversal. Plugin unload/output removal cancels visual authority and returns diagnostics for fresh actor settlement. Close/reuse retires the old exact identity and its commit ledger. Reduced motion and shell loss request actor settlement; visual cache alone never restores a window. An exact-ABI CMonitor::canAttemptDirectScanoutFast const hook can return false only on participating route outputs and delegate every inactive call to the original, avoiding a borrowed global block flag; snapshot exports must never recursively include the route.
