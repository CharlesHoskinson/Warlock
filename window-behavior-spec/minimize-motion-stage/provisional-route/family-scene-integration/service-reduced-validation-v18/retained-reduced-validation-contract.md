# Reduced motion during pending validation

The retained probe executes the unchanged V13 SceneManager and controller with
their existing deterministic Desktop/Transport fixtures. After context acceptance,
the real metadata worker blocks in the family query. Reduction followed by the
real watchdog clears the accepted scene. Completing the worker cannot minimize
anything. This is a CPU source counterexample, not a native compositor trial.

The repair must preserve the current receipt until fresh identity, family,
destination and scope validation finishes, or a separately reported failure,
deadline, supersession or explicit cancellation ends it. Reduction alone must
not discard it or grant authority to its unvalidated endpoint.

For an existing provisional visual, suppression and request retirement are
separate. Queue cancellation of the exact old renderer token and member set,
retain its capture ownership until its exact acknowledgement, and preserve the
latest user receipt. A successor request must inherit outstanding retirement
ownership without retargeting a renderer already being canceled. Old ready or
endpoint events cannot promote it. An acknowledgement never supplies context or
native authority. After acknowledgement, issue a fresh internal token, retain
the latest receipt/direction, and revalidate before any native effect. Context
still pending must remain pending; no old context can be substituted.

Turning reduction off while retirement is pending must not revive the canceled
token. Fresh preparation may animate only after the old visual has retired and
current validation has succeeded. No duplicate cancel, duplicate commit, stale
callback, lost family member, or early capture disposal is acceptable. Existing
deadline, transport failure, closed/reused-window and uncertainty guards remain.

The accompanying model describes this repair contract with abstract receipt,
token and context witnesses. It does not prove kernel ownership, installed
behavior, capture disposal, rendering, timing, or actual end-user settings.
Product edits require a successful formal checkpoint first, meaningful replay
of the retained counterexample, and tests for visual retirement, successive
receipts, context delays, late callbacks and reduction reversals. Native QA must
use the actual copied user setting command inside the owned private HOME, the
exact integrated source pair, and unchanged original baseline gates before
supplemental cases. Main desktop settings remain untouched during preparation.
