## Separate receipt and visual retirement

Reduction alone cannot finish, cancel or authorize an accepted unvalidated user
receipt. A scene without a visual retains its existing request and metadata
worker until normal validation, explicit reported failure/deadline/supersession
or separate authenticated cancellation. ContextPending stays pending.

For a moving provisional visual, reserve one separate retirement binding before
queueing cancel: exact old internal renderer token, ordered member lifetimes,
source digests/paths, actor/transport/session ownership and receipt at reservation.
The latest receipt remains active. Retain captures until the exact terminal
acknowledgment of that visual. Queue cancel exactly once. Successor requests
inherit the existing retirement binding; they cannot retarget an already
canceling visual, issue another cancellation, discard captures, or borrow old
context. Reduction-off cannot revive the retired token.

The binding is distinct from current request token and Scene object. Every
read-only worker may finish its observation, but all existing native, destination,
gesture-retirement, capture, output-preparation, seed/validate and commit
boundaries must reject authority while visual retirement is pending. Ready and
endpoint callbacks for either old/current tokens cannot promote that phase.
An acknowledgment is visual closure only; it is never context/native validation.

## Exact acknowledgment and fresh record

Only the authenticated existing transport callback with exact old token and
complete ordered old lifetime list can acknowledge retirement. Wrong token,
missing/reordered member, different transport/session/root, duplicate or stale
callback refuses. Existing source/session/renderer transport guards remain.
Source disposal occurs only after that acknowledgment; unknown queue/transport
or native effects stay quarantined and cannot be turned into success by a later
callback or receipt. Definite request deadline/supersession is separate from
physical visual/source closure.

After a normal exact acknowledgment, under the same controller/manager lock:
retire the old visual, dispose exactly its now-unreferenced captures, create a
fresh Scene object and internal token, preserve latest receipt/direction/captured
identity/accepted context and original receipt deadline, clear all old validation,
source, visual/running/ready and accepted-operation authority, and atomically
rebind any still-pending ingress's provisional Scene/token reference. A context
already accepted may be carried as context input; it still requires a fresh
complete existing metadata/family/destination/scope validation. Pending context
remains pending. Context for another receipt cannot activate this record.

Old workers keep the old Scene object. Object identity/receipt checks prevent
late workers or callbacks from gaining authority through an in-place token edit.
Once the new record has fresh validation, current reduced motion settles the
latest original symbolic direction without animation. If reduction is off,
ordinary fresh preparation may seed a new visual after closure. No old renderer
start epoch, old ready/endpoint event or old accepted operation supplies authority.
