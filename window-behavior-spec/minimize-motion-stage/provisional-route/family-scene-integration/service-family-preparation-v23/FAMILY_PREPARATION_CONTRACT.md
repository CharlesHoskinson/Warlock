# Complete family preparation within the existing animation budget

Actual frozen V6 diagnostic (unchanged V20 product) paired 1,396 real spans.
The first capture cost 859.8ms: separate taskbar target call 307.4ms, native
atlas call 153.7ms, synchronous thumbnail publication 250.0ms. The second
capture reached its post-thumbnail identity check at 2026ms; the original
controller watchdog began settlement at 2027ms. Profiling perturbs timing;
these are measured diagnostic phases, not uninstrumented latency acceptance.

This fresh derivative preserves the original two-second controller deadline,
capture geometry/digest/epoch/native identity checks, complete family scope,
renderer output and seed/upload/presentation gates, native endpoint guards,
normal cleanup and minimized preview obligations. It does not pair or change
the separate actor cancellation or readonly longevity branches yet.

## Target lookup

An independently reviewed taskbar API will obtain the complete family's real
visible icon rectangles in one genuine IPC call. Each requested exact
address/stableId/PID must have its own observed real widget/output/geometry
witness. Input order, duplicate refusal, current QS/config/engine generation,
actual source and owner bindings are checked; no invented target, default
rectangle or reuse across QML reload. The legacy single-target API is retained.
The collector honestly counts one bulk query while retaining all individual
endpoint requirements. This consumer is not implemented until that API is
reviewed; capture callers without a selected bulk API keep their original route.

## Thumbnail publication

Visible atlas capture may stage its exact pending crop instead of launching a
separate thumbnail helper before returning each individual source. After ALL
sources have returned, before renderer seed or native preview-ready authority,
one normal owned ImageMagick command creates all pending family thumbnails.
It uses the original per-member crop, +repage and 300x180> thumbnail semantics,
with isolated settings for each input, the same one-second helper timeout,
sealed executable and existing Keeper launch/normal completion proof. No new
dependency, worker, renderer result or capture image is substituted.

Acquire exact preview locks in a consistent address order; check complete
current native identities/geometry and immutable PNG source hashes before and
after the actual command. Validate every generated PNG and its expected crop
size bound before publishing the original two slots and identity metadata under
the same locks. The final existing fresh-family/geometry check still precedes
scene seed. A normal helper exit alone cannot stand in for actual outputs or
their per-window identity checks. Missing/changed source, failed helper,
superseded receipt, changed family, invalid PNG or incomplete publication
refuses visual/native preview-ready promotion.

Staged crops are bounded by the original complete family capacity. Pending
crop references are part of the actor's source lifecycle: failed/abandoned
captures remove only their own pending epoch; released sources clear their
pending crop; normal disposal refuses leftovers. No asynchronous crop worker
or late publication is introduced. The existing controller waits for its
preparation worker before source/actor retirement. A superseded worker may
finish computing an owned file but cannot promote its old intent into a new
scene. All generated temporary PNGs are cleared after genuine helper closure;
uncertain helper completion preserves required material for recovery.

## Evidence required

The model is completed before changing the runtime. Actual CPU/kernel tests
must compare one batched command's per-member decoded pixels and dimensions
against the original separate ImageMagick operations on varied RGB/alpha crops,
prove one genuine owned launch, reject missing/replaced/wrong outputs, retain
sources during unfinished jobs, and replay inherited controller/capture guards.
The collector and service are frozen together with actual module/callback/owner
attestation. The unchanged-budget native baseline must observe all three actual
captures, seed, uploads and presentation; drag-minimize and reversal/recovery
campaigns still need separate real acceptance. CPU models, faster helper counts
or the existing deadline fallback cannot establish full Windows parity.
