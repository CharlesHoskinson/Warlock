# Live cancellation derivative: contract before implementation

Recovery V15 stale-family discharge is the intended frozen base after independent
review. This directory currently has contract/model only and does not inherit a
frozen base yet. No runtime implementation or native acceptance is claimed.

## Current receipt user cancellation

A new private API command must carry exact positive receipt, actor/token and
captured identity plus complete immutable accepted scope; the service supplies
selected session/runtime authority and peer identity. A still-compatible old
intent may be cancelled explicitly as non-settlement. It is not a minimize,
restore, toggle, reduced-motion endpoint or fabricated renderer acknowledgment.

Reserve cancellation under the manager reservation lock only for exact current
receipt/token/member ownership. Record it durably before revoking current worker
and presentation/native-promotion authority. Late preparation and callbacks can
only acknowledge retirement; they cannot promote or settle this intent. New
claims overlapping its scope are refused while cancellation is unresolved;
disjoint actors remain available and continue ordinary motion. This reservation
is not completion: the API must distinguish accepted/pending from durable done.

If any native effect is unfinished or has uncertain return, quarantine persists.
Atomic guarded core calls already holding the shared lock must finish with their
exact returned member result durably recorded before cancellation can reserve.
No frame-budget promise is made for that critical section. Later helper closure
cannot erase a native-effect uncertainty boundary. Preserve original direction,
prepared endpoint and all prior returned results without writing any survivor or
replacement during cancellation.

## Normal retirement and shared keeper ownership

Stopping the whole shared Keeper would disrupt unrelated actors. Add an exact
authenticated per-actor job closure attestation from the live retained keeper:
SCM_CREDENTIALS PID/UID, keeper PID/start/nonce/source, runtime root identity,
selected environment, actor and exact job/source/lifetime records. It proves all
registered jobs of that actor terminal and no unreturned native effect/export.
A Boolean actor-quiet flag, empty numeric process group, absent job inventory or
self-reported JSON is insufficient. Attestation has a fresh snapshot identity and
must match the manager/job/resource inventory before and after observation.

Send producer cancellation for the exact token/family. Drain preparation and
callbacks without fallback settlement. Require actual normal renderer/transport
exit, presentation authority gone and retained source directory identity. During
this phase keep immutable sources and pending cancellation intent durable. Then
collect two guarded complete current client/native-family/output observations,
attest exact actor helper closure and current lease/receipt/scope again, fsync a
non-settlement acknowledgment, dispose only exact proven sources, and durably
mark terminal actor before completion response. Other actors and the shared
keeper remain alive. A failed fsync or uncertain close retains quarantine/sources.

## Restart

A reserved or acknowledged user cancellation must not revert into V15 endpoint
settlement. Preserve its exact original intent and non-settlement choice in the
restart ledger. V15 old service/keeper/renderer closure and fresh lease/root/session
observations must be obtained again. An acknowledged cancellation is refreshed,
never re-toggled, before source disposal/API exposure. Unknown or conflicting
receipt/lifetime/provenance remains quarantine.

## Interruption and reduced motion

Explicit current-receipt interruption may request the same non-settlement
cancellation with authenticated cause. Ordinary renderer cancelled/fatal/rejected
callbacks must not invent explicit user intent. Existing reduced-motion semantics
remain: validated accepted intent settles its guarded endpoint, then stops visual
animation; unvalidated reserved work cannot acquire endpoint authority. Reduction
must revoke stale preparation/presentation and use exact retirement/closure
protocol. These outcomes remain distinct in model, journal and actual oracles.
Original baseline, reversal, reduction and raster oracles stay required.
