# V23 short staging reservations

V22 stays immutable. The independently replayed actual CPU counterexample pins frozen stage/native source hashes: stage holds the lifecycle lock in an actual PNG pread; unrelated old-lease cleanup enters the receipt lock and waits for that lifecycle lock; a new receipt cannot enter until the material gate releases. NativeDesktop is enabled for actual OwnedCommands. SceneController.event/finish_cleanup and watchdog/settle call release_sources under their shared reservation lock, so this is an actual adapter/controller lock path. It is a gated CPU causality proof, not measured native latency.

V23 introduces one exact in-memory staging reservation per epoch. Pure snapshot/path/crop preparation precedes the short lifecycle critical section. Under that lock, require idle/nonquarantined state, unique epoch, and combined pending plus staging capacity at most64. Store a unique reservation object with the exact frozen window/metadata/path/crop/dimensions snapshot; increment a reservation serial only for successful reservations. No descriptor open, PNG read/hash/check, helper, fsync, native query or wait occurs while that lifecycle lock is held.

The owning worker releases the lock before PinnedPNG opens and validates the actual source. The original digest/inode/dimensions/CRC/source validation is unchanged. Reacquire only for a short commit: the same epoch must still map to that exact reservation object, idle/quarantine state must still permit admission, and pending must not contain that epoch. Copy validated material into the pending row, then remove exactly that reservation. A failure closes owned material first and removes only its exact reservation; an unknown/replaced reservation refuses and quarantines rather than releasing foreign state. Stage grants no current receipt or native authority.

require_releasable checks both live staging epochs and unchanged active/uncertain helper epochs. An exact live staging epoch cannot be released or discarded, even before its source returns to the controller. Unrelated completed old epochs remain releasable. require_disposable and helper batch reservation refuse any staging epochs. The64 limit counts pending and staging together. Duplicate/late/foreign reservations cannot publish, and disposal/failed-capture cleanup cannot borrow material closure. Normal failure after a completed material scan returns the reservation before the existing capture wrapper removes its unreturned epoch. Unknown helper group closure remains quarantined with its exact source/output material retained.

NativeDesktop and SceneController remain byte exact V22. The intended only product delta is BatchPreviews lifecycle bookkeeping and stage/release/dispose/reserve gates; crop/helper argv, one-second timeout, pixel/output validation, receipt publication, complete-family checks, hidden-cache route and all helper/native authorities remain exact. Legacy per-member taskbar target calls remain3. No V18/V21/cancellation/actor/bulk-target/performance merge is implied.

The model represents explicit scan lock ownership and includes the retained old-locked-read counterexample. Short memory reservation/commit actions are modeled atomically; this proves lock ownership/resource safety, not OS scheduling or an absolute receipt latency.
