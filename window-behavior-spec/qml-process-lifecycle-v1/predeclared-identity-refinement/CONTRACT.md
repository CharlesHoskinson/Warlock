# Actual Quickshell helper Process registry: proposed before runtime

Separate proposal. No registry implementation/QML semantic change/native launch is authorized by this model. Root reviews before runtime. Base providerV2, popup proposal/derivative, P/A/B-controller/batch packets and exact final Pin helper/capture entries remain untouched. This registry is not a new helper, proxy command, script wrapper, retry or synthetic receipt.

## Actual sources

Observe the genuine fixed PinWindowMenu capture/action Process QObject and its actual stdout/stderr StdioCollector QObjects from the lexical source call path, before the existing launch. Require actual factory engine/lexical contexts, provider activation/source/config/image/thread and menu/owner tuple; actual Process/collector allocation generations; current Process stdout/stderr pointer equality to those lexical collectors; current collector waitForEnd==true. Actual native Quickshell metaobjects/signals/readable property types are verified under frozen executable/module closure. Caller booleans/PID/claimed class or reused QML counters cannot register them.

Observe actual `started()` / `exited(int,QProcess::ExitStatus)` and both actual collectors' `streamFinished()` signals via matched generation/lease callbacks. Public installed metadata exposes these. Source-local Process::onFinished drains collectors before emitting exited, but no installed revision/order equivalence is claimed. Support all actual signal orders; never accept until all mandatory observations exist. No assigned Process.running/command, stream parser or app property, no start/stop/detach/kill/reload call in the registry.

## Kernel/helper lifetime

On actual started, read actual Process.processId, requiring a positive exact integer (not bool/string/fraction/null). Capture actual owned child `/proc` UID/all UID fields/PID/start/parent/process group/cgroup/exe/hash/final raw argv/selected launch environment before and after bounded registration. It must be the actual same owned child of the exact shell lifetime, in the exact QA/private namespace scope. Capture/direct-action roles use their exact frozen direct shebang entries and resolved isolated interpreter. Final argv is exact `/usr/bin/python3 -I -S <private entry> capture|toggle <exact original JSON>`, not a shell/wrapper/proxy. Selectors and entry/interpreter/stdlib/code mappings remain pinned to the host contract. Missing live proof (including a helper that exits before it can be observed) fails this registration; do not infer kernel proof from command, started or receipt and do not retry.

Bind menu nonce, captured public triple or full nine-field owner, Process/collectors/source/config/engine activation, requested exact command/JSON and one monotonically allocated invocation lease before startup. Actual changed command/source/collector/allocation/context, duplicate started/exited/EOF, failure-to-start/null PID, wrong child/parent/argv/exe/env/mappings, PID reuse or malformed observation invalidates completion. QML Process.command may describe a future command while an old process runs, so it is never evidence of current final argv. Use actual raw `/proc` argv. Source/context/destruction or engine reload invalidates input/completion authority; matched old callbacks cannot revive or retire a new lease.

## Exit, EOF and receipt

Normal lifecycle requires actual exited with QProcess::NormalExit and explicitly captured actual integer exitCode. Capture success uses0; toggle success uses0; native refusal2 and pre-send refusal1/post-send uncertainty3 are normal lifecycle if their actual receipts agree, but cannot claim pin success. CrashExit, missing exit, detached child, signal/force termination or unknown status refuses normal lifecycle. Actual stdout and stderr streamFinished are independent mandatory EOF observations, bound to the same actual collector generations and invocation. Freeze each actual bounded collected byte/text observation at its EOF; require stream/collector/source still consistent and refuse later changes/replacement/duplicate EOF. No arbitrary `outDone` flag or stdout alone.

Parse strict bounded duplicate/nonfinite-free exact receipt and immutable captured token projection according to the existing root-reviewed helper/capture schema. Cross-check actual helper authority frontend PID/start/parent/group and exact final receipt file under the selected private evidence directory (owned600 regular/nlink1/no-follow/inode/hash full before/after). Evidence is from the unchanged direct helper, not a QA-generated substitute. Require actual registered child lifetime gone after normal exit, without signalling it; same PID with a different start is retained as reuse/refusal rather than silently declaring it gone. Strict original host helper registration and terminal normal cleanup remain unchanged.

Completion/captured-token eligibility requires exact same current menu/owner/activation/context/row and all normal/EOF/strict receipt facts, revalidated at the consumer boundary. Cancellation may revoke completion while a genuinely registered helper still exits normally: keep its lifecycle record until complete for terminal cleanup. Never discard a registration because the menu closed. At most one active lease per actual Process QObject/collector pair; a new invocation is not armed until prior exit+both EOF+kernel-gone proof is complete. A real new QObject/engine gets new generations, never a reused lease. Extra/changed/missing observations after acceptance revoke it; no automatic retry or native writes from this observer.

## Reload and honest limits

Installed Process metadata/source warns processes may be killed when the configuration reloads. Therefore normal-exit during a pending actual reload is not assumed or guaranteed. Do not startDetached, defer or hide reload, extend deadlines, spoof normal status or drop a child from the registry. Root QA must record actual cancellation/reload outcomes, require registered helper cleanup, and distinguish failed/uncertain completion from normal lifecycle. Before a deliberate QA teardown/reload, retain exact pending registry state and use the existing bounded normal waiting policy; if the actual app kills a pending child, preserve that failure. Product policy changes to handle it require a separate contract review.

Qt CPU tests can exercise real QProcess child/kernel timing and actual Qt signal ordering through stand-ins for public signal semantics; they cannot prove installed QS Process behavior. Actual installed QS/collectors/metaobjects and helper source/peer/lifecycle receipt binding require root private GUI after complete source handoff. No whole unobserved reload-interval safety claim, no native pin/stacking/max acceptance follows from this registry.
