# Proposed mapping and unresolved proof, before popup code

`pin_popup.qnt` roles represent guarded actual allocations: 1 lexical menu Item, 2 actual Toggle pin row Item, 3 lexical popup PanelWindow QObject, 4 existing QsWindow attached QObject, 5 native proxy content Item, 6 actual QQuickWindow, 7 its native root-content Item. The 5/7 alias event represents an actual equality of those pointers; a real registry must return the same object generation, and a matched destruction invalidates both references. Other role/type distinctness comes from real typed Qt objects and fixed call path. Recreate means a newly observed actual allocation, never a caller number. The abstract epoch/nonce increments inherit base exact counter bounds and Pin menu numeric/lifetime policy; this model is not a second counter allocator.

Model relationship booleans are abstractions of the exact C++ observations listed in CONTRACT; they are not QML or IPC success flags. A fresh implementation must derive them from actual pointers/metaobject/native QMetaProperty reads/QPointer/thread/QQmlContext/ancestry. `Ready` abstracts observing a complete fresh tuple; it never repairs a failed source/thread/loader. The model deliberately has no menu-root visual-parent requirement. Source alone determines which lexical objects were returned; the provider's generic metadata does not classify arbitrary same-shaped Items as a genuine product menu.

`Capture` retains the complete tuple, engine activation, menu nonce, full captured owner token (abstracted as owner version) and exact layout version. `Confirm` means a fresh observation at the consumer boundary matches every field and original eligibility. Cancel/new invocation or any selected relationship/lifetime/source/context/layout/owner change invalidates acceptance. Other family members cannot be substituted. The readonly model has zero native pin mutations, and input readiness is not receipt/completion authority.

## Actual input episode obligation

`nativeInput` is a separate source-bound native observation, not driver intention. Before and after each future physical button/key operation, the full B wrapper must retain and verify the actual read-only probe event suffix with monotonic sequence and same owned fixture/compositor lifetime, actual button/down/up or keyState/symbol/time/Seat and exact native pointer/keyboard owner. Match the physical route's exact expected balanced episode; missing, duplicated, cancelled, wrong-owner, stale or conflicting events refuse. Pointer command write success, physical keyboard process exit0, EOF, successful IPC ACK and a function argument `true` cannot establish actual press/release delivery. Original native probe semantics and observation timing limitations remain explicit. Actual widget onClicked/key route receipt plus helper lifecycle/post-state remain separately required. A pre-core key observation is not a claim of final app delivery.

The existing immutable B-controller component does not provide a full actual wrapper/episode registry. Root's planned fresh A2 observation oracle may provide a reviewed shared episode contract for a later B derivative. No acceptance can come from mock event callbacks or by weakening existing release/controller/model conditions.

## Proposed public Qt route

1. Genuine fixed widget lookup returns lexical menu and row/popup references, after evaluating its existing Quickshell global; read-only provider receives those actual references.
2. Source/owning-thread checks precede all QObject/QML cache access. Verify current actual factory singleton/core/engine and complete process/config/image closure. Resample guards across every meta-property/getter/connection callback.
3. Find the actual popup's WindowInterface native base metaobject via inspected class ancestry. Resolve the registered attached function with the public Qt API; lookup on actual row with `createIfMissing=false`. Require existing actual attached object and exact current factory engine associations. Retain actual metaobject class/superclass/property index/type/readonly data before validation.
4. Read actual attached `window` and `contentItem` pointers, and the native WindowInterface base `contentItem` property. Compare actual identities, never a name-resolved TaskbarPopup list alias. Check actual popup `owner==menu`, current context/engine associations and all protected allocation generations. This needs CPU base-property-shadowing/attached-lookup semantics proof before trusting a future implementation.
5. Use public actual QQuickItem::window(), parentItem() and QQuickWindow::contentItem() to bind row/proxy content/native window/native root. Content may equal native root or descend from it; row ancestry reaches proxy content. Detect bounded ancestry cycles, null/destroyed/changed pointers and exact per-object contexts. No cast to local Quickshell C++ definitions.
6. Repeat the exact bounded selected-property/context/relationship tuple; return data with complete generations. Consumer combines actual native layer/output/layout/episode/Seat and original menu/helper authorities, revalidating at physical input and commit. No new provider focus/input/action call exists.

## Evidence limits / next review

Installed metadata describes PanelWindowInterface -> WindowInterface and QsWindowAttached readonly `window` / `contentItem`. ProxyWindowBase's `_backingWindow` is not a public property on PanelWindowInterface. Exact copied TaskbarPopup has a list alias shadowing contentItem; local Quickshell source confirms intended separate proxy/native root design but is attribution, not installed equivalence. CPU stand-ins may prove Qt public API semantics only. Actual installed QS object lookup, base property, attachment/root/window/layout and soft/hard reload must be proved by root's private GUI. If an actual supported API/relationship is missing, retain failure and the gap; do not invent one or switch to native layer identity.

The installed public core has no reload-start. There is no safe whole-interval guarantee; scoped observations and explicit consumer revocation before initiated reload are all this profile proposes. Full Process normal-exit/EOF registry, complete Pin native/full B UI campaign, persistent stacking/modal/family/minimize/restore/reload and genuine max+pin remain required outside this profile.
