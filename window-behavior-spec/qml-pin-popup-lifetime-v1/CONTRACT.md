# Pin popup relationship: review before implementation

This is a separate sampled relationship profile extending the reviewed base provider. No popup runtime, QML edits, native input or launcher is authorized by this packet. The taskbar descendant provider, Pin A/P/B controller, helper and batch packets remain immutable. Actual transient Process registration/normal exit/EOF is a separate missing authority.

## Exact lexical call path

A fresh copied PinWindowMenu.qml may identify its actual lexical `root`, `toggleButton`, TaskbarPopup (new lexical id only), and existing row `QsWindow` attached object. The fixed source lookup must originate from the genuine returned menu instance in the actual taskbar widget. No active-window fallback, lookup by label, arbitrary Item, claimed class, nonce or native-layer address establishes lexical identity. The provider receives real QObject references; external source/config/engine guards establish which fixed call path produced them. Its generic metadata cannot classify an arbitrary menu as the product menu.

Root is an Item; TaskbarPopup is a separately allocated PanelWindow interface. The row's visual ancestry does **not** reach root. Never use that taskbar relationship as the popup predicate. Require actual popup `owner` property equal to lexical root, all lexical objects' current context associations in the actual factory engine, and actual menu, row, popup, attached object, content Item, QQuickWindow and native root-content allocations with QPointers/generations. Context objects themselves are guarded/generation bound. Export no raw pointers.

## Public readonly attached relationship

Inspect installed Quickshell `_Window` metadata and actual popup metaobject ancestry for WindowInterface/PanelWindowInterface. With the frozen actual Quickshell process/module authorities intact, resolve the actual registered attached function using public `qmlAttachedPropertiesFunction(row, actualWindowInterfaceMetaobject)`. Obtain **only an existing** object via `qmlAttachedPropertiesObject(row, function, false)`; absent/function unavailable fails. Do not create an attached object as a diagnostic. Guard the actual attached QObject and its native `window` / `contentItem` QMetaProperty values, requiring exact types and readonly/readable property definitions. It must report lexical popup as `window` and actual proxy content Item as `contentItem`.

Use the actual native WindowInterface base `contentItem` QMetaProperty, selected from that actual base metaobject, to compare its pointer to attached content. Do not resolve a name on the dynamic TaskbarPopup metaobject: its `default property alias contentItem: contentHolder.children` shadows the base property with a list. Do not treat this list alias as a QQuickItem, perform an opaque cast, require unsupported private C++ ABI, or use `_backingWindow` on PanelWindowInterface (that property belongs to ProxyWindowBase).

The actual row `QQuickItem::window()` must be nonnull, its guarded actual QQuickWindow must equal content.window(), and actual row parentItem ancestry must reach that proxy content. The content must equal, or have actual visual ancestry reaching, the guarded `QQuickWindow::contentItem()` native root. Capture the native root's QObject generation even if it equals the proxy content (then the generation is legitimately the same). All native/content/attached/owner/property relationships and actual contexts must match before/after the bounded observation. Missing, replaced, destroyed, conflicting, cyclic/unbounded, wrong-thread or changed values refuse. The native popup layer remains a separate exact PID/namespace/allocation/output/hit and actual Seat owner witness; a Qt relationship alone cannot authorize physical input.

Public API existence is supported by installed Qt 6.11.2 headers and installed Quickshell tooling metadata. Actual attached function/property behavior, base-property shadowing semantics and installed instance relationship remain unproved until a focused CPU Qt semantic test and root-owned actual QS popup run. Local Quickshell source is attribution only; it is not installed revision equivalence. Failure must remain failure, with selected raw metadata/value types retained before assertions.

## Delayed input and lifetime

Bind the whole process/config/image/actual engine-generation/epoch/provider tuple plus each actual object/context generation to a captured menu nonce and original full nine-field native window owner. A nonce identifies an invocation; it cannot replace object identity. Menu close/cancel, new menu generation, any selected owner/member replacement, actual reload/lifetime/source boundary, row disabled/invisible, layout/output/native layer or actual input owner change invalidates pending input authority. No active/current fallback and no migration of a captured native token to another family member.

Observe the genuine current eligible `Toggle pin` row rectangle/layout twice, including label, enabled/visible and integer interior point witness. Before each physical click/Return, require an exact fresh provider relationship and matching actual native layer/cursor or Seat keyboard ownership and captured menu/owner. Preserve existing integer protocol gates and one actual physical event. Do not infer pin success from this relationship or from a press: completion still requires the exact root-reviewed helper receipt, actual helper process/normal exit/EOF registry and exact native post-state. This profile has no native pin writes.

## Scope

Counters, image pinning/loader/source/owning-thread/core boundaries inherit V1/V2. Matched-generation destruction callbacks cannot retire replacements. Actual native/content window reuse across reload does not preserve lexical menu/row/engine activation identities. Two sampled observations are bounded observations; the installed public API still has no reload-start, so this profile makes no whole reload-interval safety claim. Initiated reload revokes consumer snapshots before action. Unknown concurrent reload safety remains open, never replaced by timeouts, sleeps or instanceId.
