A native worker may join after the last actual EOF callback. The changed-command frontend proposal must re-query actual Registry state when that legitimate transition occurs; local Qt exit/outDone/errDone flags never supply kernel/source/gone/receipt authority.

The proposed optional ProcessArm notification callback carries only the internal exact Process QObject/lease. It schedules an owning-thread Qt callback through guarded actual provider/process QPointers and source revalidation. Kernel workers never touch QObjects or emit UI callbacks. Provider exposes a non-authoritative processLifecycleChanged signal; it contains no success/PID/kernel/EOF/receipt/caller proof flags. Queued callback validates original contexts/source before emitting and ignores retired objects. Old exact lease notifications are ignored by QML before any query; repeated current notifications are harmless opportunities to read state, not native signal/proof duplication.

The UI consumes a receipt at most once per exact role/lease, after actual normal lifecycle and current Registry complete=true with its strict original receipt. Publication locking is UI deduplication only; it cannot override a failed native Registry guard. No helper launch/control/retry/sleep/budget change follows from a notification. Existing native Started/EOF/Exit and watcher-result duplicate rules stay exact; these hints are a different, non-authoritative channel.

Hint/Publish model events reflect notification/no-op and actual verified-current publication.
