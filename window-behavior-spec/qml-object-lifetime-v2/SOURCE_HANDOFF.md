# Base lifetime provider source handoff

This is the root-approved sampled **taskbar widget-descendant** provider component. It is not a complete Pin B harness, popup implementation, native input authority or batch consumer integration. No native GUI was launched and no main/frozen predecessor was changed. Root owns all GUI/native pairing.

## Evidence

V1 final 29-case model/contract preceded C++ implementation. Fresh V2 per-TU clang build uses installed Qt 6.11.2, moc and exact header/dependency hashes. The initial GCC/Qt-header build failure and exploratory wrong executable subdirectory invocation remain recorded; they are not counted as accepted execution. Clean clang rebuild plus actual CPU program execution are separate evidence.

Final CPU evidence: `cpu-evidence-1790937826358427656/report.json`. Ten actual CPU cases total 215 checks: actual QObject/QQmlEngine/context/Item registry (23), actual DSO singleton lifecycle/unload/reopen, image-mode fault, config mode/extra-field/byte-identical-inode replacement, fake Quickshell refusal, wrong Qt thread after and before first query, and a separately mapped byte-identical provider image. All processes exited normally; successful owned private runtime directories were removed. No QGuiApplication, QQuickWindow, display connection, compositor, input or installed QS app was created. CPU `engineScope` is explicitly metadata-only; `observe` refuses a CPU executable even with a claimed core QObject.

NODELETE is proved by actual Qt plugin unload/reopen and retained executable maps with monotonic engine/epoch/provider generations. A QPointer QObject destroyed and recreated at the same address receives a later object generation. The stale destruction-callback case executes real QObject signals. Counter/capacity edge checks exercise pure allocation primitives; they are not a claim that 65,536 live Qt objects were allocated. Core actual reload signal delivery and native window/layout relationship need root-owned QS GUI evidence.

## Source guards

Factory engine and singleton identity are genuine Qt objects, not caller numbers. Owning Qt thread is checked before accessing singleton cache; wrong first-thread access leaves a process-persistent refusal. Actual core lookup requires the frozen actual Quickshell executable path/hash/device/inode/full mode and real singleton/metaobject/constant PID/signals. QPointers are resampled and registry entries relooked up across connections/read callbacks; callbacks retire only matching generations. Context and actual visual ancestry/window observations are checked twice. Production widget observation requires a nonnull actual window; CPU plain Items cannot claim it.

Selected config is strict ordered bounded text; actual PID/start/exe/final raw argv/cgroup/private directories, exact mode600/config inode/hash and RLIMIT_CORE1 are observed. Config inode or source replacement permanently refuses even byte-identical bytes. Actual image dladdr canonical source/hash/mode/device/inode and executable mapping are checked before/after NOLOAD|NODELETE pinning and queries. Same-inode aliases and separately mapped byte-identical executable copies refuse. Different unreviewed code remains the external strict mapped-code/loader closure responsibility; the provider makes no whole-process/global module-classification claim.

All external process/namespace/socket/native layer/frozen-source and real layout/input authority remains the consumer's responsibility. Returned fields are data; no 'verified' header substitutes for those observations. Config must select actual final QS lifetime and be created by an exact private host after that registration, before any provider query; the CPU fixture does this using its own kernel process evidence. A complete native config builder/host integration is not included here.

## Remaining pair requirements

Pin popup is a different relationship profile, proposed in separate `qml-pin-popup-lifetime-v1`; no popup implementation until root review. Actual QS capture/action Process PID/final argv/source/normal exit and both stream EOF registration is still absent. Full B private host/controller delayed/cancel/reload/member/minimize/restore matrix must pair fresh derivatives and preserve Browser20/C1/ServiceResponsive13/A/main observers. Batch consumer needs exact actual engine/object tuple and per-member actual widget/output obligations; original single motionTarget remains byte-exact.

Installed public QS metadata lacks reload-start. This provider only establishes bounded before/after sampled lifetimes and actually delivered completion/failure/destruction boundaries. It does not establish safety of an unobserved reload interval. Consumers revoke before initiated reload and revalidate at each commit/input; unknown concurrent reload remains an explicit limitation.
