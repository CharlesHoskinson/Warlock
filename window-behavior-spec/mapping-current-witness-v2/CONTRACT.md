# Bounded current mapping witness during one actual helper launch

Fresh proposal/model only. Preserve ProcessV2, mapping-device-v1, both strict
actual helper/registry failures and all prior raw evidence. No runtime changes
implement this refinement yet. Actual corrected-config unchanged read-only
capture succeeded exit0 with exact peer/EOF/durable receipt, but current registry
refused an initial executable VMA range already absent at the first map_files
readlink. That successful receipt is not kernel authority.

## One registration and original budget

Keep one actual Qt started, one captured positive integer PID, one original
PID/start/UID/parent/group/exe/argv/cgroup/namespace/selector/source/owner/lease.
No relaunch, native request retry, helper byte change, helper pause, sleep,
refocus, replacement requester, old frame acceptance or larger deadline.
A bounded current-witness collector may discard an incomplete changing loader
snapshot while the same exact original child is demonstrably still live. It
collects a wholly new snapshot epoch under a fixed monotonic two-second cap
from actual started and at most16 epochs. Both limits can only refuse sooner;
neither is taken from a caller or successful helper receipt. A child that goes
away before a full live proof remains a failure.

## Eligible changing observation

Only an actually observed VMA-set/range/protection/name change among already
frozen declared regular images, or readlink ENOENT for an original VMA range
whose disappearance is independently confirmed by fresh actual maps while
the exact original child remains live, may discard that incomplete epoch.
Capture raw error, original row, fresh full maps and exact root before/after
FIRST. This is not acceptance or a filename exception. Unknown/deleted code,
unreadable required data, permissions errors, nonregular/new/unfrozen source,
changed source/hash/mode/FD/mount/subvolume/identity, anonymous executable code,
foreign owner/context or any scope change stays a hard refusal. Rebinding a
new child PID/start or declared field is prohibited.

Discarding clears all partial mapping/FD/hash acceptance and closes every
old epoch FD. Do not combine old before with new after. Root/member/source
identity is captured once and checked anew against the original at every
boundary; it cannot be rebound merely because a new snapshot looks valid.

## Complete current proof

One full current epoch must observe every disk VMA in the current raw snapshot,
all exact map_files backing names, frozen bytes/full modes, retained current
FD/fstat/statx/fstatfs/flags, selected observer/consumer mount/subvolume proof
and exact same raw VMA set in the end snapshot. Require original root identity
and selected environment before and after. No newly appearing disk row can be
promoted without being present in the newly captured epoch and fully proved.
The reviewed Btrfs device-domain translation and mandatory direct non-Btrfs
branch remain unchanged. Only a complete same-epoch proof confers kernelBound.

Within that single complete collection, child identity and all source/VMA/FD
facts already have actual before/after boundaries. Two duplicate whole-file
hash/closure collections are not a separate authority requirement. Record
both actual boundaries, each original selected fact and the epoch. Any source
or scope failure is sticky; mapping-only discarded epoch records are retained.
Normal exit, both actual EOF, gone and exact original durable helper receipt
remain separate mandatory post-proof gates. Successful helper receipt,
command writes, old witness or caller flags cannot fill missing kernel proof.

## Explicit limits

This collection proves a bounded current frozen disk-code agreement, not
historical backing mount ownership, mapping memory bytes, interval stability
between observations or installed QS behavior. map_files follow EPERM remains
retained; no mapped-target FD claim. CPU stand-ins do not create genuine QS
contexts. Whole native frontend B and actual installed fast helper/collector
route remain root-only tests after full source handoff.
