# Separate native MAX and owning-policy campaign B

This is a design/source mapping packet. It does not execute, freeze, install, or authorize a desktop. Candidate V3 and both campaign A packets remain immutable. Campaign A's original14 checks are a separate acceptance result and are never counted as the cases below. A model seed, CPU adapter, dispatcher ACK, projected stacking list, or final endpoint geometry cannot establish native reachability or actual presentation.

## Common observations and inputs

Use exactly root-reviewed V3 core/plugin/helper/policy build and the existing rebuilt read-only probe, together with the reviewed AQ bootstrap host. The new controller binds `(fixture PID,start,title)` rather than borrowing NativeCases.own's single-fixture identity assumptions. Launch the existing immutable Qt fixture separately when a third independent peer is required; preserve distinct raw command/state/event paths and normal retirement for every producer. Tiled cases start tiled and may never call campaign A's arrange(), which explicitly makes a window floating. Dedicated isolated sessions use a fixed dwindle or scrolling config before client creation; there is no live/main config write.

Native MAX setup uses the actual legacy translator `dispatch fullscreen 1 set/unset` on an already guarded actual core+Seat focused lifetime, or the typed equivalent `hl.dsp.window.fullscreen({mode="maximized",action="set/unset",layout_aware=true,window="address:..."})`. Legacy exclusive is `fullscreen 0 set/unset`. Setup is preparation only. Pin intent uses the unchanged captured helper route or real titlebar/button release/physical-keyboard route; genuine input episodes retain source/lifetime/actual delivery and completed schema2 reports. No resize emulates MAX. Every before/after raw record is attached before assertions. Same-member projections and independent peers include public workspace/output, pin/floating flags, both actual modes, exact lifetime and owning tokens, with post-operation fresh confirmation.

Protected band presentation remains a separate capture prerequisite: use a current owned Wayland output capture source under the same scope, actual ready/presentation evidence and a discriminating same-lifetime interior ROI; record output format/scale/orientation and both references before overlap. An indistinguishable ROI, missing capture, hover/active-decoration change or unpublished frame refuses this presentation check rather than accepting list order. No screenshot of the main desktop is authorized. Source-bound snapshots include current helper state/report, public clients/outputs/groups, pin_stack_state, probe.state/keyboard_state and actual pointer/key events. `pin_stack_state.order` is only a source-bound projected order, not a rendered-frame proof. Full source/mode/link/directory and current executable/module binding are mandatory; all process, transport, ordinary authority and unchanged shutdown budgets remain enforced. Source-ready metadata grants no native authority.

## Six areas and actual acceptance

1. **Ordinary and exclusive conservation:** normal floating behavior, unprotected tiled MAX selected target/hit/focus, ordinary blocked peers, exclusive refusal, layers/special behavior when genuinely attainable. Exclusive refusal must have no native pin calls/effects; do not fabricate a completed successful toggle to count a negative case. Check original focus refusal policies and independent peers.
2. **Native MAX and return:** tiled and floating origins independently. Pin/unpin while MAX preserves actual internal/client modes, displayed geometry, original native logical/visual return box, target/space/output tokens and peers. Leaving MAX is a separate genuine native operation; compare native normal return to its saved owning state. Also test pin retained on tiled normal return followed by explicit unpin, with no invented floating conversion.
3. **Protected coexistence and focus:** pin a real tiled MAX then restore it to tiled normal while preserving intent; bring another real MAX into the same workspace. Choose a physically overlapping interior point from actual boxes. Check protected hit, pointer surface, explicit accepted core+Seat focus, independent bits, actual click owner and presentation. Repeat with protected selected MAX, independently pinned child of unpinned ancestor, and unrelated focus while another family has actual modal UI. No inherited child pin-bit intent is accepted as independent intent.
4. **Exclusions:** after a real admitted pin, set only actual `allows_input`/`no_focus` properties in the private fixture and observe refusal; retain and later restore those explicit setup values. Outside-box physical movement, fixed ignoreWindow and mask queries must preserve all ordinary eligibility/priority/fullscreen exclusions. An ordinary tiled peer blocked by `INPUT_BLOCK_BELOW_FULLSCREEN` is never revived. A native read-only windowAt call using an explicit mask proves only that native query, not reachability of a physical InputManager/DragController caller with that mask; label these results separately.
5. **Scrolling:** build a real multirow column via `layoutmsg consume`, change a non-default actual width via `colresize`, and observe a nonzero camera offset via `move`. Pin native layout-managed MAX and leave MAX; require exact original column token, ordered rows, controller sizes/width and camera restoration as well as independent peer/native client state. For stale scope, genuinely close/move an old peer or alter original remaining row membership during MAX. Require native return refusal, truthful actual state, and explicit same-current-owned unpin usability with no fabricated restore success or replacement writes. Preparatory layout operations are never feature proofs.
6. **Transfers:** distinguish workspace dispatcher routes from direct owning assignSpace completion. Observe genuine workspace, output and pre-existing group target moves and actual operation/generation/before/actual modes/reason/accepted outcome. A partial native failure may be accepted as a tested refusal only if the actual failure is reached, its truthful current state is retained, and no corrective synthetic float/unMAX/reMAX/rollback/replacement write occurs. Unknown or unreached failure is pending, never counted from a CPU seed.

## Required observation/fixture prerequisites

The immutable current probe has default hit/core/Seat and native window identities; it has no scrolling column/row/camera/restore or transfer-outcome projection and no mask/ignoreWindow API. Propose a separate read-only QA observer compiled against the exact same owning headers, preserving the old probe byte-exact. It may read public `CNativePinState::record/snapshot/transferOutcome`, `CScrollingAlgorithm::dataFor`, column `targetDatas/getColumnWidth/getTargetSize`, associated public scrollingData/controller and fixed `windowAt` masks; it cannot call setters, capture/rebind/retire, focus or native handlers. Handler-private nativeRestore is not readable through existing public API: saved before-state plus actual current data can prove positive restoration, but an assertion about the private stored restore record needs separately reviewed observation access or remains unaccepted.

Actual visual order additionally needs owned output capture/presentation and a discriminating reference ROI from the same Qt lifetime; list order alone is insufficient. The immutable Qt fixture has different owner/peer labels but no maximization-state projection. Do not interpret its geometry as client MAX state; source-bound actual core/controller client modes remain the mode witness. Existing single1600x1000 private host cannot establish cross-output transfer. A separately reviewed two-output private host derivative is required; no forced backend fallback or live output manipulation is authorized here.

The upstream `CGlobalWindowController::moveWindowToWorkspace` explicitly unsets/restores fullscreen around its move, and ConfigActions' non-silent caller invokes setFullscreenMode afterward too. Its dispatcher ACK cannot prove a direct no-intermediate-mode-cycle transfer. Preserve that ordinary source branch; record its native event sequence as a conservation case. The direct owning target transfer and no synthetic *failure compensation* are distinct obligations. A deterministic, genuine supported-operation failure trigger for every finishTransfer refusal is not yet established. Close/reuse races must not be used as nondeterministic success substitutes. No production fault injector or mode/geometry mutator belongs in a read-only observer. Fullscreen bus events are observations of emitted events only: the native handler internal/client setters do not themselves emit every state change. Absence of an event cannot prove absence of an intermediate native mode change. Source-bound owning conservation and terminal outcomes must be stated separately, and any exhaustive native-call trace needs an independently reviewed observation mechanism.

The host registry in campaign B will differ from the exact nine campaign A roles. A new explicit source-bound producer registry/closure policy is required before a B collector is accepted; the current V2 classifier must not be broadened in place.

## Formal scope

It has35 named cases and2000 bounded traces after retaining the initial stimulus-after-acceptance counterexample. It is an acceptance-protocol proof only; concrete typed decoders, observers, genuine triggers, full source closure and actual native reachability remain separate gates. Its `peersSame` token means the case's specified unaffected fields, not geometry of tiled peers that an ordinary layout operation legitimately recomputes.
