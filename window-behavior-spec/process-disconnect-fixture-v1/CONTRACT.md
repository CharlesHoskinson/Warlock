# Actual diagnostic fixture: no join inside disconnectNotify

The V8 first attempt and exact source/build remain immutable. It timed out, observed two live futex-waiting threads, then was observed gone before symbolized thread diagnosis. Exact Qt mutex ownership and actor/runtime disappearance were not captured; no normal cleanup or fast-helper/kernel/disconnect acceptance is inferred. The first fixture joins a foreign collector signal thread while inside Process disconnectNotify. That is unsafe because Qt may hold sender and receiver connection locks. Its failure is retained, not waived or replaced by direct Registry.callback.

The proposed corrected CPU fixture starts the foreign thread in disconnectNotify but does not join, inspect the Process, read QObject properties or perform other QObject reentry there. The foreign thread emits the actual still-registered collector streamFinished signal. It may wait for Qt activation locks until disconnectNotify and QObject::disconnect return. A diagnostic join is then performed by the existing terminal scope source guard outside all disconnect calls, or after the retire call returns/refuses. No same-Process QObject access occurs from the hook. No helper delay/barrier/control or second transaction is introduced: the helper and readonly kernel worker have already completed the original positive precondition before installing the diagnostic hook.

The owning Registry still must drain the actual admitted callback before commit; source guard join merely makes that admission observable deterministically after unlock. The fixture does not claim delivery occurred while Qt held disconnect locks. Current queue/fault proof comes only from the real collector signal/production relay/callback path and actual Registry state. The original failed inside-hook signal/join route remains unaccepted.

Before installing the hook, the actual positive state and terminal inventory must be saved to an exclusively created regular0600 file under the controller's exact owned0700 evidence directory, with complete writes and fsync. The controller must persist exact config/source/requester metadata and preserve partial stdout/stderr plus live identity/task observations on timeout before cleanup. A failure cannot be rerun until it passes. CPU process-level timeout remains finite; genuine timeout/deadlock stays a failure, with root-authorized guarded abnormal cleanup separately recorded when needed.

The finite model distinguishes held Qt locks, foreign activation, admitted queue, hook return, outside-lock join and retirement commit. It includes the original deadlock counterexample and corrected queue rejection, not successful receipt/native action equivalence. Public Qt execution and source/tuple/kernel/helper proofs remain required after source approval. No GUI or source/runtime authority is granted by this design.
