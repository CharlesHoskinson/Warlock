# Read-only menu capture boundary (before implementation)

At creation of a particular preview context menu, copy exactly the selected public address, native stable ID and PID. Stable IDs are exact canonical lowercase uint64 hexadecimal strings; retain the actual public spelling without numeric conversion. The new capture CLI is a separate read-only product entry and has its own frozen path/hash/0700 authority. It inherits all root-reviewed toggle-helper configuration, own interpreter/final kernel argv, initial selected environment, exact requester roots/scope, compositor lifetime/exe/module, private socket inode and kernel peer, absolute two-second EOF/size/publication guards. It sends only pin_capture with the strict public triple. No token placeholder, active fallback, mutation, retry, or pin_request is sent by capture.

The native capture API requires exactly the two exact string fields and an exact integer PID and resolves one current mapped eligible strong owner whose public fields exactly match. It returns that owner's actual complete nine-field token. The CLI validates typed token, all three public fields and compositor session/PID/start; pre/post transport configuration, source/lifetime/socket guards must remain stable. An absent/foreign/malformed response supplies no menu action authority. Menu capture does not prove the owner remains live indefinitely: the delayed unchanged toggle helper and native generation check remain mandatory at invocation.

Only a reply bound to the still-open same menu nonce and immutable public triple may enable Toggle pin. New menu, dismissal, cancellation, stale reply, closed/reused owner or config/plugin epoch invalidation never acquire a substitute token. Capture does not count as actual pin success. Launcher Pin to taskbar remains separate.
