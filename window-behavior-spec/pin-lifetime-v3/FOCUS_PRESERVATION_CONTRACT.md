# Owning pin action and stacking focus preservation

Before the corresponding native adapter change, capture strong public core focused window and surface, actual Seat keyboard surface and Seat focus resource at the entry to a particular synchronous pin operation. Keep them alive throughout native calls. Completion requires all four to remain exact; do not equate core focus with Seat keyboard focus. A changed or disappeared focus route after a native call refuses completion and reports possiblePartialOutcome; no refocus, rollback, fallback or retry repairs that report.

Replace ConfigActions::alterZOrder for the pin raise phase with the owning public WindowState::raise. Primary ConfigActions source calls simulateMouseMovement after raise; the public owning WindowState::raise does not. Its void return is not a success acknowledgment: post-call exact owner state and the bounded complete protected order predicate remain mandatory. Before/after stacking maintenance independently preserves actual core focus/surface and Seat keyboard/pointer surfaces. The original physical press or keyboard event may establish focus before this captured operation; it cannot be counted as an implementation-driven focus repair.
