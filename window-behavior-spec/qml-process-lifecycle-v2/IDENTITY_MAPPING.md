# Formal identity and temporal witness mapping

The lifecycle model's fields are opaque tokens for actual captured observations, not caller-supplied integers or self-asserted success headers. `kernel` is an abstract conjunction of the concrete strict kernel/source/env/namespace checks in CONTRACT; it is not an accepted wire flag. `receipt.strict` similarly stands for exact immutable helper byte/transport/typed-token receipt proof. Runtime must persist selected raw observations before assertions and directly derive these facts.

Arm captures the genuine Process/collectors/engine/provider/config and original owner/menu tuple. Started can bind only actual as-yet-unknown kernel PID/start after same-lifetime before/after proof. Actual final argv/entry/interpreter/selectors and every other preselected field must equal the exact arm witness; it cannot replace the original menu/owner or actual Process/collector generation. The captured kernel token plus original arm tuple is compared against the current observed tuple at consumer verification. Distinguish source/actor fields from current menu owner/nonce: changing the menu revokes completion while the original registered child can still establish normal lifecycle. Current expected role/owner is never rebound from active focus.

Twenty identity fields represent PID, start, parent, process group, all UID fields, cgroup, namespace, executable, final argv, selected environment, entry/interpreter/code, configuration, actual Process QObject, stdout/stderr objects, actual factory engine generation/epoch/provider, native owner and menu nonce. Actual representations must include every field's exact hash/inode/generation/typed value as specified by the parent contracts, not only a version counter. Twenty named post-capture replacement cases and an arm-to-start Process replacement case ensure comparison survives temporal changes, in addition to startup/exit/EOF/refusal/crash/cancel/reload/malformed/duplicate/old-lease cases.

The invocation lease is a process-persistent exact safe integer allocated by a reviewed provider-image counter, bounded before exhaustion. The model bounds issued leases below SAFE_MAX and explicitly refuses exhaustion; it abstracts that existing counter discipline; it cannot be copied as an unbounded QML increment or reset when an observer dies. CPU bounds/capacity/pinned-image proof is inherited from the actual base provider; additional lease allocation implementation must use that same checked primitive and explicit exhaustion gate. No fixture/caller can choose the lease or kernel identity.

Process.command describes a next launch if modified while running; actual current final argv comes only from the owned live kernel process. Observe normal exitStatus explicitly, not just code0/runningfalse. Direct matched-generation Qt callbacks plus exact collector pointers/source/context bind stream EOF. An old lease signal is inert; a current duplicate or missing required observation refuses. Receipt verification occurs only after normal exit, both EOF and actual registered kernel-gone proof; an early receipt cannot later become completion. Actual source scope must stay valid, and no handler/metadata/body can repair it by writing a bool.

Only a proposed protocol model exists. No actual QS Process registered, no normal-exit/EOF outcome, no source or GUI implementation acceptance is claimed. A future implementation requires root review and CPU real Qt/QProcess/kernel tests, then root actual QS GUI proof. Source-local EOF-before-exit ordering is an attribution limit, not installed behavior.
