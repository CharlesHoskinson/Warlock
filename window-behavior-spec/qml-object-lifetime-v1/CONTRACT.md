# Actual QML object lifetime provider: proposed contract, before runtime

Status: source/model proposal only. Root must review this contract/model before any provider C++ implementation, QML registration/import or native use. No native launch/main edit/deployment. Pin B, batch V1, original single motionTarget and all frozen packets remain unchanged.

## Property and actual observation

A fresh readonly Qt QML extension exposes an engine-local singleton factory supplied with the actual QQmlEngine* by Qt. It observes real QObject/QQuickItem instances supplied by the exact reviewed widget call path. No header, nonce, PID, instanceId, layer address, source hash alone, JS counter or user-provided numeric epoch can register an engine/object lifetime. Pointer values remain internal; exported identities are monotonic generations bound externally to actual PID/start/exe/config/module/socket/peer/EOF.

The extension stores QPointer<QQmlEngine> and QPointer<QObject> plus captured creation generations. QObject::destroyed retires the matching generation without dereferencing its destroyed argument. A reused allocation obtains a new generation; callbacks for an old generation cannot retire or validate its replacement. A widget and its delegate must both be actual QQuickItems in the factory engine, with current QQmlContext/engine associations and the delegate's real parentItem ancestry reaching the supplied widget. The fixed widget lookup still proves that these are the genuine returned taskbar widget/delegate: the provider alone does not classify an arbitrary QQuickItem as a taskbar.

Before and after every bounded read, require the same nonnull guarded provider/engine/widget/delegate, generations, context/engine association, ancestry, selected output/layout witness and owning Qt thread. Do not dereference QPointers across a nested callback without resampling them. Wrong thread, destroyed object, context migration, ancestry change, malformed/absent response, stale snapshot or representability failure refuses the entire observation. Readonly means no property assignment, focus/input, dispatch, action, geometry change, object creation on behalf of an app, or refresh/reload request. Observer construction/connections and internal generation bookkeeping are its only mutations.

## Process-persistent monotonic identities

One process-level registry in the exact provider image allocates never-reused positive counters. engineGeneration identifies each observed actual QQmlEngine lifetime. engineEpoch identifies that engine's current observation activation: a new engine, actual singleton recreation within an existing engine, or an actually observed Quickshell reloadCompleted/reloadFailed boundary obtains a fresh global epoch. They are distinct fields; an epoch change is not a claim that the engine allocation changed. widgetGeneration/delegateGeneration identify actual QObject lifetimes and survive unrelated reads without incrementing. Provider QObject generation is also part of the witness, so clearSingletons/recreation cannot revive an old snapshot.

Use exact safe integers in the first protocol (1..2^53-1) and refuse allocation before exhaustion. Never truncate/wrap, convert uint64 beyond exact QML number range, or reset any counter on engine destruction/reload. Bounded live registries must refuse new registrations on capacity exhaustion; dead entry removal may reclaim storage but cannot reuse any generation. A static counter that resets on dlclose is unacceptable.

Before making any observation eligible, pin the already-loaded exact provider image in the process using inspected glibc RTLD_NOLOAD|RTLD_NODELETE with the applicable immediate binding flag and retain the successful handle. Verify dladdr-derived canonical image path against the sealed config, file device/inode/full mode/hash and actual executable mapping, before/after registration and queries. Reject alias/duplicate provider image, replacement, wrong mapped inode/path/hash, failed pinning or a loader reset. No new library path may be loaded to repair a failed observation. The registry becomes permanently refused if its image/loader ownership changes. Actual Linux CPU DSO unload/reopen tests must prove counter persistence before accepting this loader design; source/documentation inference alone is insufficient.

The process anchor uses actual PID/start and selected final process argv/exe/env/cgroup plus module/dependency byte/mode/link closure. Reused PID/start, config replacement, app restart or changed import library invalidates external authority. The provider's JSON is data; the consumer independently verifies those external authorities. No new arbitrary 'verified:true' response field can establish them.

## Actual reload signal source and bounded scope

The provider constructor registers its actual engine only. Its observation call receives the widget’s already-evaluated Quickshell global reference; only then compare that object to the real singleton from the factory engine with the inspected public QQmlEngine::singletonInstance<QObject*>("Quickshell","Quickshell") API. Validate actual metaobject/signal availability and processId against the real current PID; connect directly to its actual reloadCompleted/reloadFailed and destruction observations. The Qt singleton lookup can instantiate a lazy singleton: do not call it during provider construction or independently initialize app infrastructure as a diagnostic. The fixed widget source must first evaluate its existing Quickshell reference, and the returned actual engine singleton must be that same QObject. Record a QPointer/generation for this signal source and advance the epoch on its matched destruction/replacement, while allowing a genuinely new engine/source to establish a fresh observation. Missing singleton/signal or an unverifiable source/loader refuses, without substituting a QML-generated signal or instanceId. A new factory engine and object destruction/recreation are independently observed even when native windows are reused.

The supported public Quickshell metadata does not expose reload-start. This proposal therefore **does not claim absence of an in-progress reload before the completed/failed signal**. A consumer must revoke its own pending snapshot before every reload it initiates, and require exact object/layout/source/config/activation witnesses again afterwards. Root private QA must include engine destruction, same-engine singleton recreation and actual soft/hard reload, recording what the installed implementation actually does. If a retained object can change semantically during an unobserved reload interval with all selected witnesses unchanged, the provider cannot prove that interval safe: no whole-scene/input authority until a source-backed additional reload-start witness is available. Never invent a before-reload event, declare a grace period, sleep to assume completion, or infer installed upstream branch equivalence.

The observation is bounded to actual before/after sampled lifetimes and actual delivered lifecycle signals. It is not a lock of future app state or a global guarantee about every Qt object. Downstream consumers must revalidate this witness at their own commit/input boundary; all-output family plans remain atomic and their native token/source/input gates remain unchanged.

## Wire and integration plan

Proposed response schema qml-object-lifetime-v1 contains engineGeneration, engineEpoch, providerGeneration, widgetGeneration, delegateGeneration; exact process PID/start and loader/config authority digest are external bindings, not fabricated engine IDs. An absent delegate is explicitly absent and cannot yield an eligible target. The API accepts actual object references, never caller-supplied generations. Validate every numeric field as an exact positive integer with a bound; bool/string/fractional/nonfinite/overflow values refuse.

Implement after root review in a fresh provider source checkpoint. Then stage fresh Pin B and batch V2 derivatives: replace the logical object generations with actual provider observations, bind the complete engine/object tuple before/after each lookup and native input, preserve legacy single motionTarget source exactly, retain duplicate-free family/per-member allocation obligations and count one bulk query once. Do not mutate B controller checkpoint or batch V1 to make them runnable. The separate actual QS capture/action Process PID/normal-exit/EOF receipt registry remains required for Pin B and is not established by an engine witness.
