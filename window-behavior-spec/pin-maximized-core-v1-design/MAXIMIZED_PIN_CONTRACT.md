# Native maximized pin: design for core review

Status: isolated contract and executable design models only. No implementation, compiled candidate, native run, installed change, or acceptance. Frozen V25, PinA1/A2 and V22 remain unchanged. This packet develops the queued V25 MAX_PIN_CORE_PROPOSAL rather than declaring existing pin support complete.

## Exact source and observed boundary

`primary-provenance.json` captures core Git revision efb50993780079460b0cbed1363e2166a2de1d9f and immutable V25 source/model evidence. ConfigActions::pinWindow refuses a nonfloating owner or any FullscreenController::isFullscreen owner. The controller's any-mode predicate includes native maximized mode. Its pinned transition handling treats maximized and exclusive alike, and its default transition may remove another target's fullscreen mode. The generic handler stores per-target modes but its covering selector takes the first unordered-map entry. Per-owner membership and one chosen covering view are different operations.

The legacy core also sets a child's independent `m_pinned` bit from its parent in XDGShell::set_parent and at window creation. A corrected core must stop those two inherited writes. Effective family protection is derived from exact relationships; the child's explicit/rule pin bit is separately owned. Existing already-copied pins cannot be distinguished from genuine explicit intent after the fact: adoption cannot silently clear them. A fresh corrected core can preserve independent bits from creation. Migration of unknown legacy intent remains a deployment issue, not an inferred runtime write.

Parent root's retained A2 run independently passed genuine titlebar/chord/legacy and protected/modal raise gates, then refused owner focus under a modal child before rawWindowFocus. Its failure remains authoritative; this design does not alter its fourteen gates or five-second observation deadline.

## Native action contract

1. Exact strong window owner and current nine-field public receipt remain mandatory. Core capability/source/ABI identity must be authenticated from the actually loaded matching core/plugin, never a QA flag. Existing lifetime/tombstone semantics remain exact.
2. An eligible native internal MAXIMIZED owner (mode 1) can toggle its own pin without changing internal/client mode, native floating/tiled origin, actual rectangle, workspace/output, layout target, saved native restore record, focus/Seat/pointer state, or any other window's semantic fields. Client exclusive mode, internal exclusive mode, unknown modes, hidden/closed/special owners, missing or invalid native restore authority, stale identities, or incompatible core capability refuse before action.
3. The action is one owning core pin operation and, for successful pin, owning core family raise. No unmaximize/float/pin/remaximize sequence, geometry setter, resize imitation, plugin direct pin write, active-window fallback, focus repair, rollback or retry is permitted. Successful core entry must keep native MAX mode and geometry. Return failure/exception after any invoked native call is reported as an invoked/partial boundary; no optimistic success feedback.
4. Pin uses no legacy assignToSpace or last-focused-history side effect for this path. A callback that changes mode, geometry, restore record, membership, focus, identity, source, or peer semantic state invalidates further action/success. A rejected reentrant request does not replace the existing operation's captured intent.
5. Native restore record is created by owning core BEFORE MAX entry, with normal geometry, native floating state, exact target/group member lifetime and native layout return authority. It remains attached to that lifetime throughout MAX. MAX exit uses that owning record, preserving pin and original float/tile state. A maximized-origin pin can remain protected when restored to tiled state; unpin then must not force float. A new ordinary tiled pin continues the existing V25 float-before-pin path.
6. Unknown pre-extension restore geometry is not reconstructed from the maximized rectangle. Adoption is read-only and may admit only an actual extended-core record. Close/address reuse retires the record; unload/reload invalidates old plugin receipts without toggling a surviving core bit.

## Modes, placement and family band

Every queried owner retains its own native mode independently of the one selected workspace covering view. Two protected MAX owners must coexist with native mode and each restore record intact; pinning or raising one must not unmaximize the other. The exact coexistence entry policy must be reviewed before implementation: ordinary unprotected MAX replacement behavior can remain, but entering/retaining a protected MAX must not evict an existing protected MAX. Exclusive fullscreen stays under existing exclusive policy and cannot acquire a MAX pin through this API.

All supported native handlers, including scrolling, need explicit per-target capture/restore and mode membership. No declaration that a custom layout works based solely on default-handler tests. Workarea updates synchronize every admitted MAX target, without overwriting normal restore geometry with MAX geometry. Workspace/output transfer uses owning target/space/fullscreen-record migration, preserving pin and exact return authority; direct `m_workspace` rewrites in focus/workspace-swap paths cannot replace migration. Explicit transfer may legitimately transform geometry under core placement policy; the pin action itself never transfers.

One shared core protected-family policy must drive rendering, hit selection, fullscreen visibility/input allowance and stacking. The effective band includes visible, same-workspace/output exact modal/X11-transient descendants without changing their independent bits. Parent precedes descendant; independent root order follows actual z order. Each eligible view renders exactly once, including tiled-origin protected MAX and restored tiled owners. Main/popup and pinned-final passes exclude/include the same effective set. The protected band remains below top/overlay layers; no top-layer/taskbar takeover. Unrelated window properties and ordinary focus decisions remain native.

## Explicit focus routing

Pin action never focuses. A genuine explicit owner-focus request may resolve to its deepest eligible modal descendant BEFORE `fullWindowFocus`'s modal-parent guard. Resolver uses actual live graph/lifetimes/visibility, bounded cycle-safe traversal and deterministic native sibling precedence; ambiguous/incompatible graphs refuse. Preserve session lock, exclusive layers, Seat grab, root/leaf nofocus and focusability, visible workspace, surface ownership, X11 nofocus, fullscreen ownership and reason-specific decisions. Recheck after any native fullscreen/workspace callback; no redirected owner bypass.

Core fullWindowFocus should expose the exact accepted target/result for its caller. ConfigActions::switchToWindow currently invokes focus then warps, sets temporary forcedFocus and adjusts monitor using ORIGINAL owner. Follow-up must use only the authenticated actually accepted final target, respecting cursor:no_warps/input:follow_mouse; refusal or changed target/lifetime/surface allows no original-owner warp/forcedFocus/monitor side effect. A successful focus must reflect real core focus plus native Seat surface; no synthetic public-only correction.

These are design abstractions, not actual core/property decoding proofs. Rectangle/target/layout tokens stand for full validated native records; visible modal chain is fixed to five owners. MAX seed states describe states the corrected core must represent, not states proved reachable on installed core. Explicit transfer geometry transformation and scrolling layout authority need real implementation/numeric tests.

Core build/source proof alone establishes no GUI or full-parity acceptance.

## Acceptance refinement from actual focus implementation

The primary rawWindowFocus assigns `m_focusWindow` before invoking rawSurfaceFocus. The latter may return for session lock or a rejecting Seat grab, and has no Seat keyboard update when no keyboard exists. Thus a native call can change core focus without matching Seat acceptance. A typed result must query and retain BOTH actual current core owner/surface and Seat keyboard surface/resource, plus current keyboard availability. Success requires the exact selected owned native surface resource, matching core selected owner/surface and a live native keyboard. A partial change/refusal is recorded without synthetic rollback and cannot authorize cursor, temporary forcedFocus or monitor follow-up. Recheck every relevant guard and lifetime after the call and before follow-up; accepted bookkeeping does not replace these actual native observations.

Ordinary no-modal owner focus must remain ordinary owner focus. An unrelated window's focus must not route to another application's compose/transient UI, nor be blocked by that other family's owner/leaf nofocus state. Each actual selected target still obeys its own native nofocus/lock/layer/Seat/workspace/fullscreen policies. An explicitly pinned child of an unpinned ancestor protects its exact descendants without fabricating their independent bits. Final models include these separate conservation and partial-acceptance cases.
