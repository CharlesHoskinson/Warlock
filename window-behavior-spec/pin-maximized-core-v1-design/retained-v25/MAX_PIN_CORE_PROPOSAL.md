# Queued genuine maximized + pin core extension

V25 retains no-write refusal for maximized and exclusive fullscreen. This is incomplete Windows parity; refusal is not the final policy. Do not use unmax/pin/remax: retained primary FullscreenController clears m_pinned into m_pinFullscreened on entry when allow_pin_fullscreen is enabled, and blocks the transition otherwise. Geometry emulation cannot satisfy the actual mode requirement.

## Minimal reviewed core extension candidate

Use a separate isolated Hyprland core source/build derivative and matching plugin headers/API hash, never the installed core or a metadata flag claiming support. Extend the existing owning Config::Actions::pinWindow and FullscreenController policy to distinguish actual internal FSMODE_MAXIMIZED from exclusive FSMODE_FULLSCREEN. Permit toggling the selected maximized owner while preserving its actual maximized mode, before geometry, monitor/workspace and native restore/layout record. Preserve its original floating/tiling restore state; do not force an unmaximize or geometry setter as the implementation. Keep exclusive fullscreen a separate explicit refusal policy.

The core must retain the pin bit through legitimate MAX entry/exit and ordinary workspace/monitor transfer, and keep the existing pin fullscreen bookkeeping for exclusive fullscreen distinct. Audit and extend owning workspace/layout/fullscreen bookkeeping where it currently assumes a single fullscreen owner or floating-only pinned window. V26 protection eligibility must include genuine pinned MAX owners without pretending they are floating. Modal/transient effective stacking follows the same real parent graph, with independent member pin bits. Do not bypass a core bookkeeping invariant by writing m_pinned from the plugin.

Before source edits: model actual mode versus saved restore mode/floating/geometry, two independent pinned MAX owners, per-member modal state, hide/minimize/restore, workspace/monitor transfer, reload/adoption and close/reuse. The transaction captures one strong native owner, verifies source/lifetime/state before every owning call, and exposes partial failures without rollback/refocus/retry. Then compile the isolated core + matching V26 adapter, extend exact immutable Service restore records only if source review establishes a missing mode field, and run root-owned actual old/new-window/MAX/exclusive/family/overlap/input/restore/output cases.

ABI handoff must pin core source revision/patch, full build/header/ELF/mode/link closure, both actual core and plugin hashes, public capability version, exact private PID/socket/peer and all old product regressions. Existing V25 and accepted BrowserV20/C1/Service packets remain immutable. Root reviews the concrete contract/model and source boundary before this separate core implementation or any native launch. No deployment is authorized by this proposal.
