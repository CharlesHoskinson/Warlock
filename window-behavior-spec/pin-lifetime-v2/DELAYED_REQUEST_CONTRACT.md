# Captured pin requests before helper implementation

A synchronous titlebar/keyboard toggle captures the actual public Lua window owner once and delegates pin_window(w); callbacks cannot redirect it to newly active windows. A delayed menu request captures the full native pin_identity(w) while that exact menu owner is current. The nine immutable fields are address,stableId,pid,session,compositorPid,compositorStart,incarnation,epoch,generation. Address/PID/stable alone, active-window fallback, or a new token obtained only when a stale menu item is eventually clicked are insufficient. The private QA must exercise capture before delay and stale generation/config/plugin/session/refocus failures.

The request means toggle this exact owning native window at execution. It does not bind a prior pin value or promise a separate explicit Pin/Unpin menu label; a menu must label this action Toggle pin unless an explicit desired-state API is separately specified/formally implemented. Native transaction semantics remain the accepted strong-owner float-if-needed, toggle pin, raise only if newly pinned, exact post-callback checks/no rollback. Partial errors remain visible and receive no success feedback.

A new isolated product helper takes one explicit full token and one selected immutable mode0600 config under its owned mode0700 HOME/runtime. It requires isolated no-site Python; exact current process/requester PID/start/source/exe/argv/environment/scope, config byte/mode/inode, actual compositor PID/start/frozen executable/cgroup/environment selectors and exact compositor IPC socket device/inode. It refuses foreign inherited handles/environment/import injection. Only the captured full token may form the native repl pin_request(table); canonical ASCII fields and strict integer PIDs prevent command injection. The exact frozen plugin path/hash must be actually mapped in the selected same compositor before sending.

Both read-only validation queries and the ONE mutating request use the same owned socket and actual SO_PEERCRED PID/UID; complete bounded EOF plus before/after PID/socket/config/requester checks required. Raw command/peer/response/errors are retained before parse or authority decisions. No retry follows a send, missing EOF, malformed/partial response, disconnect or post-send authority change: the operation may have executed and is reported uncertain with no completion or rollback claim. A valid explicit native refusal is retained separately from uncertain transport. Success requires exact structured native phase complete/ok true/captured token and before/after same owner identity. No clipboard, network, main routing, native reload, app launch or active/address fallback is introduced by the helper.

The candidate config builder/entry installer targets only new isolated staging paths. No main config/helper/UI deployment. Source-only UI binder examples must retain actual public owner at user invocation; integrating a genuine taskbar/menu must expose the captured full native token at menu creation and retain it until invocation. Direct QA pin_request is a service baseline only and never taskbar frontend acceptance. Root sole native QA owner.

The temporal model abstracts full tokens and process/env/socket witnesses as exact epoch tokens. It covers delayed lifetime/config/plugin/session changes, before-send guard failure, at-most-once send, missing/invalid EOF and after-send witness changes as uncertainty. Runtime must check actual individual fields; model equality is not kernel/process proof.
