# Pin lifecycle refinement before event wiring

The retained primary `toolkit-interruption-v5/primary/Window.cpp` emits public window.close at2575 while m_isMapped remains true until2644. This establishes source ordering only, not installed binary equivalence or an observed native failure. Erasing the identity registry on close would let a reentrant token query resurrect the same strong owner from a still-mapped core view. A close event must synchronously retire that actual window object's generation before any reentrant query or backend call. Lifetime queries refuse the retired object even while the public mapped flag is still true. The close tombstone holds only a weak owner. A genuine later public window.open for that object creates a fresh lifetime generation; a different owner reusing an address also needs a fresh generation. Old delayed tokens never revalidate. No address/PID/stable tuple alone revives authority. Plugin unload/reload incarnation and config epoch remain distinct.

Feedback is separate from user opacity and pin state. Public close, pin/floating/fullscreen changes, special-workspace/minimize transfer and reduced/config/unload synchronously retire the exact owner lease. Retiring is irreversible: instant restore or a reverse state change before the next16ms timer must not revive feedback. Normal workspace/monitor transfers retain a lease only while the same owner/lifetime/epoch remains eligible. An own successful backend action may emit these signals during the transaction; it retires older leases, and only final complete validated success can create a new lease. Failures, partial outcomes and stale identities never create a success lease. Per-owner lease retirement cannot alter another family member's lease/pin state.

The temporal refinement distinguishes public core mapped observation from observed live generation. Core mapped alone is never authority after close. The implementation will retain weak tombstones until a genuine opening or a different expired owner. No strong lifetime retention or opacity property writes are introduced. Focus, raise, pin and float remain explicit captured strong-owner core actions with post-callback result checks and no rollback. Maximum/fullscreen pin policy remains open; existing explicit fullscreen refusal persists.

Model/tests precede event listener and registry changes. Source-only/CPU proof is not native lifecycle or legacy-window acceptance; root owns actual private QA.
