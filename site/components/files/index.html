Files

Open an installed file application through the shell’s Files integration.

Overview

Open an installed file application through the shell’s Files integration.

Anatomy

The popup presents the observed location, collection destinations, a folder path field and Open folder. Home and collections are separate explicit actions.

States

Typing edits a draft and does not open a folder. A valid path is absolute, ~ or begins with ~/; it is subject to length and control-character limits. Service and peer observations determine the displayed location.

Specimen

Real Elm interface. Simulated desktop. Client interiors are fixtures.

Behavior

Choose a collection or enter a path and select Open folder. A matching request, service, newer revision, visible peer and location establish an opened result. Refresh reads state without replaying the request.

Accessibility

Label the path field and the explicit Open folder button. Typing alone changes the draft, so keyboard and composition input do not launch a file application. Collection buttons and service status remain reachable and readable at enlarged text sizes.

Content

Files integrates with an installed file application. Show the observed peer and location only when the service supplies them; an unavailable service gives its reason and cannot open a target. A refused request asks for a refresh before choosing again. An unknown result or connection loss leaves opening unconfirmed, and refresh only reads state.

Evidence

Captures show the running interface; they are not simulated fixtures.
