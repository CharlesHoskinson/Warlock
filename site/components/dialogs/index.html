Overview

System confirmation keeps a consequential operation in the surface where it started.

Anatomy

The inline confirmation contains the consequence, Cancel and Confirm, in that order. Cancel receives initial focus. It has no modal scrim or focus trap.

States

Cancel returns focus to the System close control. Confirm submits the operation; the displayed result follows the relevant service outcome.

Specimen

Real Elm interface. Simulated desktop. Client window interiors are fixtures. Load the desktop only when you want to explore this component.

Open the full desktop scenario

Behavior

A native application can also own a modal window family. That relationship controls its eligible recipient and is separate from the shell’s inline System confirmation.

Accessibility

System confirmation stays in the existing surface, without a modal scrim or focus trap. Cancel precedes Confirm in keyboard order and returns focus to the System close control. Confirm submits the named operation; its subsequent status is announced by the owning surface. Native modal-family recipient rules are a separate client-window relationship.

Content

Name the operation the user is confirming, including network disable, restart, shutdown or logout. Keep Cancel and Confirm distinct. A submitted request is not a completed operation; show the service’s actual result.
