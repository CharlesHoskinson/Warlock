Architecture

Follow the components and messages that connect Warlock’s Elm interface to the desktop.

Main coordinates interaction through The Elm Architecture. Adapters carry messages between Elm and the desktop runtime; the runtime integrates with Hyprland and desktop services. Choose a component to inspect its source and connections, or step through a flow.

The controlled-preview entries describe an alternative QA path. The default runtime uses the controller, bar and popup documents.

Component explorer

Choose a component to see its details and connections. Arrow keys move between components in the same layer or to the nearest component in an adjacent layer. Focus and selection are independent. Escape returns focus to the selected component.

Each step shows the exact message and its connection. The highlighted line follows the current hop; the numbered list remains available below.

    All flow steps

    Open Applications from the taskbar

    A taskbar gesture reaches Main through native checks and opens Applications in the shared popup.

    1. activation.js → bar-adapter.js: submitSurfaceAction: surface-action, id=bar:applications. Captures the completed Applications gesture.
    2. bar-adapter.js → Bar: requestAction: surface-action. Requests validation against the displayed taskbar.
    3. Bar → bar-adapter.js: actions: surface-action. Returns the admitted action.
    4. bar-adapter.js → Shared GTK native host: native.postMessage: surface-action. Sends the action through the native surface gate.
    5. Shared GTK native host → adapter.js: receiveAction: view-action. Adds the originating output scope after native checks.
    6. adapter.js → Main controller: rendererActions: view-action. Delivers the Applications choice to Main.
    7. Main controller → adapter.js: surfaceCommits: view-commit, frame.mode=applications. Publishes launcher controls, popup ownership, and focus targets.
    8. adapter.js → Shared GTK native host: native.postMessage: view-commit. Submits the coordinated presentation.
    9. Shared GTK native host → popup-adapter.js: receivePresentation. Delivers the launcher frame to the popup document.
    10. popup-adapter.js → Popup: presentation. Renders search and application controls.
    11. popup-adapter.js → Shared GTK native host: presentation-applied. Acknowledges the current presentation after two animation frames.
    12. Shared GTK native host → popup-adapter.js: receiveFocus: surface-focus. Directs keyboard focus to the current launcher target.
    Search and launch an application

    Committed text filters the catalog, and selecting a result submits a launch whose receipt remains separate from window observation.

    1. Popup → popup-adapter.js: actions: surface-query, id=control:search. Emits committed search text after local composition handling.
    2. popup-adapter.js → Shared GTK native host: native.postMessage: surface-query. Sends the query after its presentation acknowledgment.
    3. Shared GTK native host → adapter.js: receiveAction: view-action. Routes the query with the popup owner's scope.
    4. adapter.js → Main controller: rendererActions: view-action containing surface-query. Updates the search and ranks matching catalog entries.
    5. Main controller → adapter.js: surfaceCommits: view-commit. Publishes the filtered application controls.
    6. adapter.js → Shared GTK native host: native.postMessage: view-commit. Submits the updated launcher presentation.
    7. Shared GTK native host → popup-adapter.js: receivePresentation. Delivers the matching results.
    8. popup-adapter.js → Popup: presentation. Renders the filtered list.
    9. activation.js → popup-adapter.js: submitSurfaceAction: surface-action, id=entry:<catalog-id>. Captures the user's explicit result selection.
    10. popup-adapter.js → Popup: requestAction: surface-action. Validates the selection against the displayed results.
    11. Popup → popup-adapter.js: actions: surface-action. Returns the admitted entry action.
    12. popup-adapter.js → Shared GTK native host: native.postMessage: surface-action. Sends the launch choice through native input checks.
    13. Shared GTK native host → adapter.js: receiveAction: view-action. Routes the choice to the controller.
    14. adapter.js → Main controller: rendererActions: view-action. Creates an intent bound to the catalog identity and generation.
    15. Main controller → adapter.js: surfaceCommits: view-commit containing application-launch. Publishes pending feedback and the launch request.
    16. adapter.js → Shared GTK native host: native.postMessage: view-commit. Submits the launch request in its controller batch.
    17. Shared GTK native host → Adapter daemon: application-launch. Forwards the admitted request to the catalog authority.
    18. Adapter daemon → Installed applications: DesktopAppInfo.launch([], Gio.AppLaunchContext()). Revalidates the desktop entry and submits it to Gio.
    19. Adapter daemon → Shared GTK native host: application-launch-outcome. Reports Submitted, Refused, or Unknown.
    20. Shared GTK native host → adapter.js: receiveNative: application-launch-outcome. Delivers the launch receipt.
    21. adapter.js → Main controller: nativeEvents: application-launch-outcome. Settles launch feedback while compositor observations establish any new window.
    Activate a window from the taskbar

    Selecting an inactive single-window group creates an activation request that the plugin applies and checks inside Hyprland.

    1. activation.js → bar-adapter.js: submitSurfaceAction: surface-action, id=bar:group:<group-key>. Captures the selected taskbar group.
    2. bar-adapter.js → Bar: requestAction: surface-action. Checks the captured action against the current presentation.
    3. Bar → bar-adapter.js: actions: surface-action. Returns the admitted group choice.
    4. bar-adapter.js → Shared GTK native host: native.postMessage: surface-action. Sends the choice through the native surface gate.
    5. Shared GTK native host → adapter.js: receiveAction: view-action. Associates the action with its output.
    6. adapter.js → Main controller: rendererActions: view-action. Resolves activation from the group's current window facts.
    7. Main controller → adapter.js: surfaceCommits: view-commit containing window-effect, operation=activate. Publishes pending feedback and the activation intent.
    8. adapter.js → Shared GTK native host: native.postMessage: view-commit. Submits the batch for native admission.
    9. Shared GTK native host → Desktop data and Warlock state: admission_write: admissions-v1/<key>.json. Records the pending window intent durably before delivery.
    10. Shared GTK native host → Adapter daemon: window-effect, effectProtocol=1, operation=activate. Forwards the admitted activation.
    11. Adapter daemon → Hyprland observation authority plugin: j/elm_observe: window-effect. Submits the operation after recording backend custody.
    12. Hyprland observation authority plugin → Hyprland on Omarchy: Desktop::focusState()->fullWindowFocus; Desktop::windowState()->raise. Focuses the eligible family recipient and raises the focused window.
    13. Hyprland observation authority plugin → Adapter daemon: effect-outcome. Reports the result after checking native state.
    14. Adapter daemon → Shared GTK native host: host-admission-settled; effect-outcome. Persists the settlement and returns its admission record and effect receipt.
    15. Shared GTK native host → adapter.js: receiveNative: effect-outcome. Consumes the admission settlement locally and delivers the effect outcome.
    16. adapter.js → Main controller: nativeEvents: effect-outcome. Settles pending activation while fresh observations determine the taskbar's active state.
    Switch to an empty workspace from Task View

    Go to workspace navigates to an observed empty destination while Task View filters only change the displayed list.

    1. activation.js → popup-adapter.js: submitSurfaceAction: surface-action, id=overview:go:<workspace>. Captures the explicit navigation choice in the open Task View.
    2. popup-adapter.js → Popup: requestAction: surface-action. Checks the destination action against the current presentation.
    3. Popup → popup-adapter.js: actions: surface-action. Returns the admitted navigation action.
    4. popup-adapter.js → Shared GTK native host: native.postMessage: surface-action. Sends the destination choice.
    5. Shared GTK native host → adapter.js: receiveAction: view-action. Routes the action under its popup owner.
    6. adapter.js → Main controller: rendererActions: view-action. Binds navigation to the observed source and destination workspace generations.
    7. Main controller → adapter.js: surfaceCommits: view-commit containing workspace-navigation. Publishes the navigation request and pending state.
    8. adapter.js → Shared GTK native host: native.postMessage: view-commit. Submits the navigation batch.
    9. Shared GTK native host → Desktop data and Warlock state: workspace_admission_write: workspace-navigation-v1.json. Records the admitted navigation durably before delivery.
    10. Shared GTK native host → Adapter daemon: workspace-navigation. Passes the request to its backend coordinator.
    11. Adapter daemon → Hyprland observation authority plugin: j/elm_observe: workspace-navigation. Submits the recorded intent without automatically replaying uncertain delivery.
    12. Hyprland observation authority plugin → Hyprland on Omarchy: changeWorkspace; rawMonitorFocus; fullWindowFocus(nullptr). Activates the checked destination monitor and empty workspace.
    13. Hyprland observation authority plugin → Adapter daemon: workspace-navigation-outcome. Reports the result after checking workspace, monitor, and focus.
    14. Adapter daemon → Shared GTK native host: workspace-navigation-outcome. Persists and forwards the settlement.
    15. Shared GTK native host → adapter.js: receiveNative: workspace-navigation-outcome. Delivers the navigation result.
    16. adapter.js → Main controller: nativeEvents: workspace-navigation-outcome. Settles navigation and reconciles the desktop presentation.
    Show an application notification

    An application notification updates bounded history, taskbar state, and the designated accessible announcement.

    1. Installed applications → Notification service: org.freedesktop.Notifications.Notify. Submits notification text and actions under the producer's D-Bus identity.
    2. Notification service → Installed applications: Notify return value. Returns the notification identifier.
    3. Notification service → Adapter daemon: wake; notification-update. Signals changed history and supplies its current snapshot when read.
    4. Adapter daemon → Shared GTK native host: notification-update. Sends the unsolicited snapshot over the backend pipe.
    5. Shared GTK native host → adapter.js: receiveNative: notification-update. Routes the update to the controller.
    6. adapter.js → Main controller: nativeEvents: notification-update. Updates notification state and applies announcement policy.
    7. Main controller → adapter.js: surfaceCommits: view-commit. Publishes taskbar state, visible history controls, and any permitted announcement.
    8. adapter.js → Shared GTK native host: native.postMessage: view-commit. Submits the coordinated notification presentation.
    9. Shared GTK native host → bar-adapter.js: receivePresentation; receiveAnnouncement. Updates the taskbar and sends an announcement when it is the designated recipient.
    10. bar-adapter.js → Bar: presentation; announcements: announcement-projection. Renders notification state and the admitted accessible announcement.
    11. Shared GTK native host → popup-adapter.js: receivePresentation. Updates notification history when its panel is open.
    12. popup-adapter.js → Popup: presentation. Renders current history entries and their valid actions.
    Save appearance in Settings

    Saving an edited Settings draft persists the proposal before committed appearance reaches each document's CSS.

    1. activation.js → popup-adapter.js: submitSurfaceAction: surface-action, id=settings:save. Captures Save settings after the user edits the draft.
    2. popup-adapter.js → Popup: requestAction: surface-action. Checks Save against the current enabled presentation.
    3. Popup → popup-adapter.js: actions: surface-action. Returns the admitted save action.
    4. popup-adapter.js → Shared GTK native host: native.postMessage: surface-action. Sends the explicit save request.
    5. Shared GTK native host → adapter.js: receiveAction: view-action. Routes the Settings action to its controller.
    6. adapter.js → Main controller: rendererActions: view-action. Creates a proposal using the captured storage revision.
    7. Main controller → adapter.js: surfaceCommits: view-commit containing shell-settings-write. Publishes pending save feedback and proposed values.
    8. adapter.js → Shared GTK native host: native.postMessage: view-commit. Submits the settings batch.
    9. Shared GTK native host → Adapter daemon: shell-settings-write. Forwards the admitted proposal to preference storage.
    10. Adapter daemon → Desktop data and Warlock state: settings.json; rename; fsync. Checks the revision and atomically saves the validated values.
    11. Adapter daemon → Shared GTK native host: shell-settings-outcome, status=Saved. Returns the saved snapshot and new revision.
    12. Shared GTK native host → adapter.js: receiveNative: shell-settings-outcome. Delivers the storage receipt.
    13. adapter.js → Main controller: nativeEvents: shell-settings-outcome. Accepts the matching saved result as committed appearance.
    14. Main controller → adapter.js: surfaceCommits: view-commit with appearance. Publishes the committed appearance.
    15. adapter.js → Shared GTK native host: native.postMessage: view-commit. Submits the updated presentation.
    16. Shared GTK native host → popup-adapter.js: receivePresentation. Delivers committed appearance to Settings.
    17. popup-adapter.js → Popup: presentation. Renders the committed appearance attributes.
    18. Popup → appearance.js: data-theme; data-text-scale; data-effects; data-reduced-transparency. Exposes the saved appearance in the surface DOM.
    19. appearance.js → WebKitGTK renderer: document.documentElement.dataset; style.fontSize. Updates the root so shell.css paints the saved appearance.
    Apply a snap layout

    Apply requests checked placement of an eligible floating Wayland window within its observed work area.

    1. activation.js → popup-adapter.js: submitSurfaceAction: surface-action, id=snap:apply. Captures Apply for the selected snap region.
    2. popup-adapter.js → Popup: requestAction: surface-action. Validates Apply against the current chooser.
    3. Popup → popup-adapter.js: actions: surface-action. Returns the admitted snap action.
    4. popup-adapter.js → Shared GTK native host: native.postMessage: surface-action. Sends Apply through the native popup gate.
    5. Shared GTK native host → adapter.js: receiveAction: view-action. Routes the action under its current output owner.
    6. adapter.js → Main controller: rendererActions: view-action. Builds the snap intent from the selected region and current geometry facts.
    7. Main controller → adapter.js: surfaceCommits: view-commit containing window-effect, operation=snap. Publishes pending feedback and a placement bound to observed native revisions.
    8. adapter.js → Shared GTK native host: native.postMessage: view-commit. Submits the geometry batch.
    9. Shared GTK native host → Desktop data and Warlock state: admission_write: admissions-v1/<key>.json. Records the snap intent durably before backend delivery.
    10. Shared GTK native host → Adapter daemon: window-effect, effectProtocol=2, operation=snap. Forwards the admitted placement request.
    11. Adapter daemon → Hyprland observation authority plugin: j/elm_observe: window-effect. Records the operation and submits its exact placement.
    12. Hyprland observation authority plugin → Hyprland on Omarchy: window->layoutTarget()->setPositionGlobal. Applies the region after rechecking window eligibility, work-area identity, and size policy.
    13. Hyprland observation authority plugin → Adapter daemon: effect-outcome. Reports the result after checking geometry and preserved focus.
    14. Adapter daemon → Shared GTK native host: host-admission-settled; effect-outcome. Persists the settlement and forwards the admission record and effect receipt.
    15. Shared GTK native host → adapter.js: receiveNative: effect-outcome. Consumes the admission settlement locally and delivers the snap result.
    16. adapter.js → Main controller: nativeEvents: effect-outcome. Settles pending feedback and reconciles subsequent geometry observations.
