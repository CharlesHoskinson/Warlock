Interaction

The Elm Architecture keeps user intent and observed desktop facts distinct.

Model, view and update

The Model holds admitted state. The view renders that state; a Msg reaches update, which produces the next Model and commands. Cmd and Sub ports connect to the Haskell runtime and native observations.

Intent, receipt and observation

An intent asks for an operation. A receipt reports its handling. Fresh observations establish facts such as geometry, activation and keyboard ownership. An accepted request alone does not prove the desktop changed.

Stable targets

Keyed controls preserve identity as content updates. A held pointer target stays bound to its original item, and focus remains attached to a meaningful control.

Input composition

Search and path inputs preserve composition events. Intermediate input from an input method is not treated as a completed query or activation.

Pending, refused and unknown

Pending uses waiting wording. Refused gives a reason when available. Unknown remains unconfirmed and never automatically retries a mutation. Submitted does not imply completion.

Refresh and recovery

Refresh requests current facts without replaying an uncertain operation. Reconnection restores observation before further state is represented as known. Try status and recovery.
