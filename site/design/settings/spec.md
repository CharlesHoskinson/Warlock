# Settings

Settings is a single scrollable preference surface. Its title and status precede the keyed control list. Close and Show help lead the list. Expanded help appears directly after its disclosure; deferred appearance toggles, motion, theme and scale, appearance save, then shortcut choices follow in source order. Each shortcut route shows its observed state, Keep, Default and Alternative choices, and the availability details supplied by the host.

## Anatomy and hierarchy

The renderer root is `.surface-popup[data-mode="settings"]`; its children are `h1`, `p[role=status][aria-live=off]`, and `.surface-controls[role=group]`. Rows are `button.control-utility` with `.control-label` and `.control-detail`; help and shortcut observations are `p.notification-text[data-settings-help]` and `p.notification-text[data-shortcut-state]`. Selectors use the actual `data-surface-control` identities. The flat source order is authoritative. There are no tabs, sidebar, rearranged rows or invented headings. At the start of each major existing run, 24px separates related controls; rows retain at least 6px gaps. Single-line rows are at least 36px high and rows with a detail at least 56px; with a coarse pointer they are at least 44px and 60px. Every row keeps a 1px border and 6px 12px padding in every state. The standard surface has 16px alignment, a 6px scroll gutter, and a 640px documentation width. The native allocation stays authoritative. Long content wraps and grows. On short surfaces the list scrolls; no sticky header hides focus.

The two deferred appearance choices are ordinary pressed buttons, not switches. Theme choices are Night theme, Dawn theme and High contrast theme; text size choices are 100%, 125%, 150% and 200%. Motion offers Follow system, Reduced motion and Full motion. Shortcut choices are scoped to Applications, System and Notifications and include existing availability details. Save motion preference, Save settings and Save shortcut choices each own an independent task boundary. The renderer emits each as `.settings-save-group > button + p.settings-save-caption`; the button carries `aria-describedby` to its caption and no `.control-detail`. Each enabled save uses affirmative fill and on-action text. The caption projection places each explanation in a visible caption outside the fill and associates it with its save button through `aria-describedby`. Refresh and Close remain quiet. Disabled saves remain readable, opaque and unavailable.

## States and behaviour

`aria-current=true` on theme, scale, motion and shortcut choices presents selected fill, a 3px brand-text leading bar and the existing Selected detail. `aria-pressed=true` on the two appearance choices retains their existing On detail and the same bar. The bar is painted inside the row as a 3px inset marker, so selection changes neither the border width nor the padding and the label never shifts. Focus is the shared blue, 2px offset ring with an opaque gap, independent of selection. Press and hover retain selection. Help uses `aria-expanded`; its paragraphs grow in normal flow, preserving drafts. Static status is quiet and uses the source wording. Pending, refused and unconfirmed results remain distinct and neutral unless typed outcome hooks support a richer grammar. Refresh reads rather than replaying a mutation; appearance refresh explicitly discards unsaved edits. Shortcut refresh preserves pending choices according to its model.

An appearance draft changes no renderer theme or root scale. `appearance.js` projects the committed `data-theme`, `data-text-scale`, `data-effects` and `data-reduced-transparency` only. Motion preference storage and application are separate facts; a saved preference is not an application acknowledgement. Shortcuts require their own saved and live-binding observations. A receipt alone does not establish application. Effects-off is a deferred appearance choice; the resolved reduced tier is a host capability, not another setting.

Settings enters and exits at 0ms. Draft changes and help expansion do not run a portal. D01 settles incompatible active decorations immediately on committed preference, visibility, capability or motion changes, without relying on an animation event suppressed by `animation:none`. No layout, outline or shadow animates here.

## Keyboard and access

The source opens focus at Close, restores it to the opener on dismissal, and preserves keyed control identity. Tab and Shift+Tab traverse controls; source help describes arrows, Home/End, Enter and Escape. Focus stays visible at scroll edges. The shared focus, high-contrast and forced-colours rules remain authoritative. Disabled text keeps opacity 1. Text scales apply once at the root; padding is in CSS px. Use no clipping, ellipsis or text shrinking. At 320px and 200% zoom, content reflows into one column. Opaque surfaces also satisfy reduced transparency.

## Required renderer work

The current flat list has no semantic group headings or group wrappers. Add source-backed, stable group labels and relationships if the integrated experience needs explicit Appearance, Motion and Shortcuts headings; do not manufacture headings with CSS or reorder controls. Selected choices already say Selected, but pressed appearance controls only say On/Off. Add a visible check/choice mark, and an unavailable/slashed cue for disabled controls, as real decorative renderer markup without changing accessible names. The motion status is currently a disabled button rather than a status paragraph; a source change is needed to express it as noninteractive content. The renderer groups each Save control with a sibling caption in `.settings-save-group`. It preserves each keyed item and control identity, moves the existing detail into the caption and associates it through a stable `aria-describedby` ID. The filled treatment applies only inside that group. Until that integration, the running renderer retains its existing neutral save rows. Existing preview descriptions remain in the accessible description alongside the caption. Typed outcome projection is required for semantic icons; CSS never parses notices. These changes require controller/renderer validation and are not represented as existing markup in the specimen.

## Content-driven geometry

The popup has no fixed height. Its maximum is the host allocation, at most 420px and the available viewport below the taskbar. A flex scrollport holds the keyed list; rows do not shrink and multiline content grows. At short heights the entire popup scrolls. The content-driven documentation panel never reserves an empty 680px. Three independent enabled saves use their actual control identities. An enabled state requires the corresponding source model to be ready and dirty; a receipt does not make another boundary saved.

The host supplies the available popup block size after accounting for the current taskbar geometry. Area CSS fills that allocation and does not subtract a fixed viewport clearance. The 6px list gap combines with an 18px leading group margin for 24px between major groups. Hover applies only to enabled controls on fine hover-capable pointers. A selected unavailable choice keeps its selected fill and bar while retaining disabled text and semantics. A visible unavailable cue requires the renderer enhancement above.

The independent save examples use documentation headings outside the source-shaped renderer. They illustrate distinct task boundaries without introducing headings or wrappers into Elm's flat control list. Each scale fixture has its own document root; the committed scale applies exactly once.
