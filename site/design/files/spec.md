# Files

Files offers shell access to the installed file application. The popup is a Windows-style quick-access panel: the most recently observed location as an address pill, collection destinations as tiles and an explicit folder path. It does not browse the visitor's filesystem.

## Anatomy and hierarchy

The renderer creates `.surface-popup[data-mode="files"]`, an `h1`, a static `p[role="status"][aria-live="off"]` and the `.surface-controls` scrollport. Source order is Close Files menu, Refresh Files state, `.notification-text[data-files-content="files:location:state"]`, Home, Recent, Images, Videos, Documents, Downloads, Large files, Screenshots, the path input and Open folder. Buttons retain their `data-surface-control` identities; collection identities begin `files:collection:`. The input is `.launcher-search[data-surface-field="control:files-path"]`. The current renderer places `.control-label` and `.control-detail` inside each button. The completed path projection moves the Open folder detail to a sibling caption and adds a sibling label for the existing field. No wrapper, renderer icon or section title is assumed.

In the runtime popup document (`body.popup`), the shell arrangement places every control on a twelve-column grid with 8px gaps, in source order. Close and Refresh form a quiet toolbar row, six columns each, at least 2.5rem high, with 13px labels, 18px glyphs and Refresh's detail beneath in 11px secondary text. The location reads as an address pill across the row: at least 2.5rem high with fully rounded ends, a 1px hairline (text at 9%), the canvas at 62% as a well with a soft inner shadow, and 13px text at 500 after an 18px folder glyph in brand text. Home and the seven collections are tiles of three columns each, four to a row: at least 4.75rem high, with 12px corners, a 1px hairline, the 4% tile fill and a 28px glyph in brand text centred above the 13px name. The visible “Folder path” label follows across the row as 12px uppercase secondary text at 600 with 0.06em tracking. The path field takes eight columns and Open folder the remaining four, side by side, each at least 3rem high with 12px corners: the field on the well fill with the essential border, and Open folder on the tile fill with its folder glyph in brand text and its detail beneath in 11px secondary text. At 150% and 200% text the tiles take half the row and the field and Open folder each take the full row; at 200% Close and Refresh also take the full row. An unavailable tile places the shared unavailable cue in its top inline-end corner beside the glyph, where it never meets the name, and its glyph turns secondary text. Effects off and reduced transparency make the well the opaque recessed surface. Effects off and high contrast remove the address pill's inner shadow, and high contrast draws hairlines with the essential border on the opaque surface.

The area stylesheet's own arrangement, which the standalone specimens show, is a list: the location on an opaque recessed panel with 12px padding and 6px corners, unboxed collection rows with 6px gaps, 16px separation around the location and path groups, and a path field at least 44px high followed directly by Open folder. In either arrangement Open folder becomes a label-only affirmative action when enabled, with its explanatory detail in the following neutral caption, only once the renderer emits the associated label and caption; the button references that caption with `aria-describedby`. The existing renderer keeps the detail inside the button, so Open folder keeps its neutral treatment (the essential outline in the list, the tile in the shell arrangement) until both projections are present. Refresh and Close remain quiet. The input uses Inter for editing; the location is a single source-provided string, so CSS does not guess which substring is a path. Retain 6px focus gutters. Popup width preference is 480px, while host allocation is authoritative. Scroll vertically and preserve the whole focus ring. At short heights the whole popup scrolls.

The input has the accessible name “Folder path”, a placeholder and a visible label. The renderer emits the label as a keyed sibling from the existing `ariaLabel` and `domId`, so the input keeps its identity, keyed node and composition handlers; CSS does not manufacture it. Renderer requirement: move the Open folder detail into a visible caption associated through `aria-describedby`, retaining the field node, keyed identity, event handlers and source order. Until the renderer emits that caption, Open folder keeps its neutral treatment.

## Behaviour and keyboard

Opening reads the current service snapshot and focuses Close Files menu. Close returns focus to the Files opener. Tab follows source order; native button activation invokes the associated action. Typing only edits the draft. Preserve `compositionstart`, `input` and `compositionend`, keyed identity and scoped publication/lease acknowledgements; do not open on keystroke or composition completion. A valid path is an absolute path, `~`, or a `~/` path, subject to the 512-character and control-character limits. Invalid or unsupported values leave Open folder unavailable. Home and collection targets are separate supported intents.

Open folder, Home and collections send an explicit request tied to the current service and revision, then close the popup. Pending prevents another opening. Refresh sends a read, never a repeat mutation. A refusal asks for refresh before choosing again; an unknown outcome remains unconfirmed and is not replayed. A later observed revision can reconcile pending without replay. An Opened receipt needs the matching request, service, newer revision, visible matching peer and location before it is presented as opened. Existing peer identity remains authoritative.

Files popup entry and exit are immediate. Focusing an existing application or changing its location has no portal. Only newly observed application-window incarnation creation or removal invokes the shared portal.

## States and accessibility

The status paragraph carries source-provided ready, pending, unavailable, refusal and unknown wording without classifying free-form text by colour. No success mark appears for pending or unknown. Disabled actions keep full-opacity secondary text and native disabled semantics. The source does not supply an unavailable/slashed cue; add that as a renderer projection, not CSS-generated accessible text. The input remains editable while operations are unavailable. No selected collection state is projected. Focus is the shared 2px blue outer outline, 2px offset and opaque gap, with 6px scroll padding and margin. Preserve the focus policy and single announcement owner; the static status has `aria-live="off"`.

Night, Dawn and high contrast use shared semantic tokens. Forced colours use system colours: the glass panel paints Canvas, the address pill a CanvasText border, unavailable glyphs GrayText, a focused control ButtonText on ButtonFace and a focused field FieldText on Field. Reduced motion and all effect tiers retain immediate popup entry and exit. Text wraps without clamping. Test long paths, 100–200% text, 200% zoom, 320px effective width, text-spacing overrides, IME and keyboard focus at every scroll edge. No layout or target changes occur on hover or press.
