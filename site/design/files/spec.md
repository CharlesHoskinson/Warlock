# Files

Files offers shell access to the installed file application. The popup presents the most recently observed location, collection destinations and an explicit folder path. It does not browse the visitor's filesystem.

## Anatomy and hierarchy

The renderer creates `.surface-popup[data-mode="files"]`, an `h1`, a static `p[role="status"][aria-live="off"]` and the `.surface-controls` scrollport. Source order is Close Files menu, Refresh Files state, `.notification-text[data-files-content="files:location:state"]`, Home, Recent, Images, Videos, Documents, Downloads, Large files, Screenshots, the path input and Open folder. Buttons retain their `data-surface-control` identities; collection identities begin `files:collection:`. The input is `.launcher-search[data-surface-field="control:files-path"]`. The current renderer places `.control-label` and `.control-detail` inside each button. The completed path projection moves the Open folder detail to a sibling caption and adds a sibling label for the existing field. No wrapper, icon or section title is assumed.

Location uses an opaque recessed surface and wraps anywhere. Collection rows use unboxed neutral surfaces and 6px gaps. The location and path groups have 16px separation from adjacent groups. The path field is at least 44px high; Open folder follows directly as a label-only affirmative action when enabled, with its explanatory detail in the following neutral caption. The button references that caption with `aria-describedby`. The existing renderer retains the neutral outlined fallback until both projections are present. Refresh and Close remain quiet. The input uses Inter for editing; the location is a single source-provided string, so CSS does not guess which substring is a path. Headers and scrollport align at 16px; retain 6px focus gutters. Popup width preference is 480px, while host allocation is authoritative. Scroll vertically and preserve the whole focus ring. At short heights the whole popup scrolls.

The existing input has the accessible name “Folder path” and a placeholder, but no visible label. Renderer requirement: add a visible, programmatically associated `label` for the existing input without replacing its identity, keyed node, input or composition handlers. Do not manufacture the label with CSS. The specimens show the required renderer projection and identify it as an enhancement to the current renderer. [The renderer projection patch](files-label.patch) adds a keyed sibling label using the existing `ariaLabel` and `domId`; the keyed input and its composition handlers remain unchanged. D01 integrates and compiles the patch and extends it to move the Open folder detail into a visible associated caption while retaining the field node, keyed identity, event handlers and source order. The caption associates with Open folder through `aria-describedby`. The current patch adds only the label; it does not implement the caption.

## Behaviour and keyboard

Opening reads the current service snapshot and focuses Close Files menu. Close returns focus to the Files opener. Tab follows source order; native button activation invokes the associated action. Typing only edits the draft. Preserve `compositionstart`, `input` and `compositionend`, keyed identity and scoped publication/lease acknowledgements; do not open on keystroke or composition completion. A valid path is an absolute path, `~`, or a `~/` path, subject to the 512-character and control-character limits. Invalid or unsupported values leave Open folder unavailable. Home and collection targets are separate supported intents.

Open folder, Home and collections send an explicit request tied to the current service and revision, then close the popup. Pending prevents another opening. Refresh sends a read, never a repeat mutation. A refusal asks for refresh before choosing again; an unknown outcome remains unconfirmed and is not replayed. A later observed revision can reconcile pending without replay. An Opened receipt needs the matching request, service, newer revision, visible matching peer and location before it is presented as opened. Existing peer identity remains authoritative.

Files popup entry and exit are immediate. Focusing an existing application or changing its location has no portal. Only newly observed application-window incarnation creation or removal invokes the shared portal.

## States and accessibility

The status paragraph carries source-provided ready, pending, unavailable, refusal and unknown wording without classifying free-form text by colour. No success mark appears for pending or unknown. Disabled actions keep full-opacity secondary text and native disabled semantics. The source does not supply an unavailable/slashed cue; add that as a renderer projection, not CSS-generated accessible text. The input remains editable while operations are unavailable. No selected collection state is projected. Focus is the shared 2px blue outer outline, 2px offset and opaque gap, with 6px scroll padding and margin. Preserve the focus policy and single announcement owner; the static status has `aria-live="off"`.

Night, Dawn and high contrast use shared semantic tokens. Forced colours use system colours. Reduced motion and all effect tiers retain immediate popup entry and exit. Text wraps without clamping. Test long paths, 100–200% text, 200% zoom, 320px effective width, text-spacing overrides, IME and keyboard focus at every scroll edge. No layout or target changes occur on hover or press.

No selected state, file thumbnails, uploads, bookmarks, destructive operations or directory tree is introduced.
