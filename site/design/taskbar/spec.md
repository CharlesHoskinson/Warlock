# Taskbar

## Overview
The top-mounted taskbar provides application access, window groups, utilities, recovery and persistent feedback in a Windows-style bar across the top of the screen. It is stationary and immediately present. In Night and Dawn it is frosted glass over the wallpaper; high contrast, effects off, reduced transparency and forced colours make it opaque. The source order stays intact: recovery controls when present, pinned and ordinary groups as running application pills, then utilities: Applications (Start, with the folded W), Task View, Switch windows, Notifications, Files, System and Settings. Notifications, Files, System and Settings form a tray at the inline end of the toolbar, directly before the status chip at the inline end of the bar. Detached state places utilities before applications. Nothing in CSS changes this sequence.

## Anatomy
`SurfaceRenderer.viewWithPreview` emits `.surface-bar` with a keyed `.surface-actions[role=toolbar]` and sibling `.surface-status[role=status][aria-live=off]`. Buttons contain optional decorative preview, `.control-label`, `.control-detail` and optional hidden description. `bar:group:` and `bar:pin:` identities map to `.control-group`; `bar:recovery-refresh` maps to `.control-recovery`; other controls map to `.control-utility`. Actual utilities include Applications, Task View, Switch windows, Notifications, Files, System and Settings. Scoped IDs, publication and lease remain unchanged.

The bar is `calc(3rem + 8px)` high, the same expression the native host uses for its exclusive zone, so the allocation follows the committed root text size while insets stay in CSS pixels. The toolbar scrollport has 6px block and 10px inline padding and a 4px gap between controls. Every control has 10px corners; at rest its fill and border are transparent, except the active application's fill. Buttons keep intrinsic utility widths; groups have 16px inline padding, start at 104px and cap at 200px. Application labels may ellipsize with their full accessible names retained. Utilities stay readable. A 6px scroll margin and scroll padding keep the complete focus outline within the scrolling area. Applications (Start) keeps a 10px margin before it and paints the folded W as a 22px glyph in brand text; a 1px hairline, inset 12px from the top and bottom, stands 8px before it, between the application pills and the shell controls. Notifications takes an automatic inline-start margin, so the tray of Notifications, Files, System and Settings sits at the inline end of the toolbar while Start, Task View and Switch windows follow the application pills. The status is a quiet chip vertically centred at the inline end: 12px secondary text at a 1.35 line height on the 4% tile fill, 10px corners, 5px 12px padding, a 4px gap before it and 10px after it, occupying only its content width up to `clamp(160px, 22vw, 320px)`. Where details show, they occupy one line and ellipsize; the existing accessible name preserves their complete wording. The renderer enhancement supplies a keyboard-reachable disclosure for persistent status, with the full text available visually and without a second live announcement. Full application details remain available in the accessible name; a separate visual disclosure for truncated application details requires renderer support. The idle status has no stripe.

### Compact arrangement
In the shell skin each control is the toolbar's content height less 2px: 42px of the 56px bar at 100% text. It keeps a 1px transparent border and has no block padding. A group shows only its label, on one line, 14px at 600 with 0.005em tracking, centred in the pill; its detail stays in the DOM, visually hidden, and the button's accessible name carries it. A utility shows its 20px glyph (22px for Start), an 8px gap and its 14px label at 500 on one line, with 12px inline-start and 14px inline-end padding; a non-empty utility detail follows the label as a small pill of 11px text at 600 in on-action colour on the action fill. Below 1180px of bar width every utility except Applications collapses to its glyph: its label keeps its text node and the accessible name at a 0px font size, and the button narrows to 52px: 11px of inline padding around the glyph and its 8px gap.

The area stylesheet alone, which the standalone specimen loads without the skin, fills the same `3rem - 4px` with controls that keep a 1px border and 12px inline padding and stack label, a 2px gap and detail in a centred column. At 100% text that column needs 38px of the 42px content height. With WCAG text-spacing overrides (line height 1.5, letter spacing 0.12em, word spacing 0.16em) it needs 41px, and at every root size from 16px to 32px the column stays inside the control. In both arrangements added letter and word spacing widens controls instead of growing the bar: utilities keep their full labels and the toolbar scrolls horizontally, while group labels ellipsize with their complete wording retained in the accessible name.

## States
Each running group carries a pill centred 3px above its bottom edge, 3px high with fully rounded ends. A group with open windows shows a 14px pill in secondary text; a minimized group shows the same pill at 55% opacity; a group in attention widens it to 22px in the warning colour; the active application widens it to 28px in brand text and fills the group with the selected wash (the action fill at 22%, 30% under a hovering pointer). The pill reads `data-window-state` (`open`, `minimized`, `attention` or `active`) and `data-active-application`; a zero-window pin has no pill. Observed window focus adds a neutral 24 × 3px top marker. Keyboard focus uses the shared 2px focus outline and opaque 2px gap, only while `.surface-actions[data-document-focus=true]` owns document focus. Selection, focus and hover stay independent. The visible state words (Minimized, Pinned launcher, the group count and attention wording) live in the visually hidden detail, so the accessible name carries them; the pill width and colour are the visible cue. Pin identity and “Pinned launcher” identify a zero-window pin. Disabled controls retain full opacity and disabled semantics. Attention is steady, without glow. Pending, refused and unknown feedback preserves source wording and uses its typed outcome symbol on a neutral surface. A neutral untyped status is not classified from its text.

## Behaviour and keyboard
One available family activates, minimizes when active, or restores when minimized. Multiple families open the picker. A zero-window pin invokes its available launcher. The adapter retains arrow, Home and End navigation, native focus ownership and scroll-to-reveal. Enter and Space use button activation. Recovery reads current observations and does not repeat uncertain actions. Status is static `aria-live=off`; the existing announcement owner speaks changes once.

The bar appears and disappears at 0ms. Hover fills (text at 7%) apply only to a hovering fine pointer, `(hover: hover) and (pointer: fine)`, so touch input never leaves a hover fill behind; press fills (text at 11%) apply to every pointer. A launch intent has no portal. Only an observed newly mapped application window starts the shared portal; focus, minimize and restore do not.

## Accessibility and renderer requirements
The repository renderer derives `data-window-state`, pressed state and `data-active-application` from detail text and gives attention precedence over active. The staged test-drive renderer reads typed `activeApplication` and `windowFocused` facts from the host. D01 projects typed independent `data-active-application`, `data-window-focused` and attention facts on each group, retaining simultaneous states. The CSS reads `data-active-application` and `data-window-focused` independently, and shows neutral presentation when the typed activity attribute is absent. The running pill also reads `data-window-state`; D01 supplies that attribute from the typed family state rather than from detail text, and a group without it shows no pill. The renderer emits an explicit decorative warning element from typed attention. It does not infer focus or attention from text. The attention triangle is decorative and the existing detail, through the accessible name, carries its meaning. Groups show no application icon: CSS has no per-application identity and never derives one from a label. Per-application icons require a typed, keyed icon reference for each group from the renderer, emitted as decorative `aria-hidden` content inside the group button, with the accessible name, identity and order unchanged. D01 supplies a decorative `aria-hidden` warning glyph from typed attention, typed outcome symbols, and an unavailable cue for disabled controls. These additions preserve the existing accessible names, status announcement ownership, DOM identity and ordering. Until then the source detail provides the attention and operation wording, and the focus marker and outcome symbols remain absent. D01 provides a keyboard-reachable way to reveal overflowed persistent status without adding a duplicate announcement. D01 supplies the shared focus implementation and validates the 6px paint gutter in the real adapter and host.

Use `night`, `dawn`, `high-contrast`, forced colours, effects-off, reduced motion and reduced transparency with the same geometry; only the glass becomes opaque. Forced colours paint the bar Canvas, the glyphs and running pills CanvasText, and the active group a CanvasText border. At 800px and 200% text scale all enabled controls remain reachable by horizontal scroll. Test 100/125/150/200% scales, 200% browser zoom, 320px effective width, long names, text-spacing overrides, keyboard-only traversal and focus on both scroll edges. No control or status obscures its focus indicator.

## Projection contract
`ActionProjection.focused` identifies the observed focused incarnation and `Taskbar.groups` maps its root to the family; group membership supplies the window-focus fact. `Taskbar.Family.active` derives from that observation; `Family.attention` aggregates admitted member attention independently. `Presentation.barControls` carries both facts through the keyed `bar:group:` or `bar:pin:` control, including pins resolved to a group. `SurfaceRenderer` decodes typed booleans and emits the three attributes without changing control identity, publication, lease or source order. The group detail retains both facts when both apply. A missing fact omits its attribute. The status disclosure retains the existing `aria-live="off"` owner and makes the full outcome available on keyboard request. The committed renderer does not yet provide these projections or disclosure. The staged renderer currently supplies a window-focus attribute, but still derives activity from detail text.

## Disclosure integration contract
The renderer retains the existing keyed status node and its `aria-live="off"` status owner. A keyboard-operable disclosure control follows the toolbar and exposes the complete current status in an opaque bounded panel. Enter and Space toggle it; Escape closes it and returns focus to its trigger. Opening does not move focus away from the taskbar unless the user navigates into the disclosure. Its expanded state is expressed by `aria-expanded` and linked by `aria-controls`. The panel never becomes a second live region. The disclosure trigger and panel reserve focus paint space and remain within the output. The source-shaped specimen demonstrates Enter, Space, Escape and focus return in the same bar as the status. D01 implements the same state in Elm and validates it in the actual renderer and adapter. The native taskbar host is height-bounded; the full panel uses an allocated anchored popup surface with a focus return path, not overflow outside the bar host.

The warning symbol is an explicit `aria-hidden` element emitted by Elm inside the group button beside its label, and the button's accessible name carries the attention wording. No generated CSS text conveys the symbol. Typed false overrides any legacy active state. No focus or attention fact is inferred from text or hover in the enhanced projection.

## Focus scrolling integration
The adapter measures the focused control after focus and after presentation or resize. Its allowed horizontal interval is the toolbar client rectangle inset by 6px at each end. If the control crosses either inset, it adjusts `scrollLeft` by the signed difference and remeasures after layout; the 6px scrollport padding makes both outermost controls reachable. The adjustment uses the actual physical rectangles and scroll position, including right-to-left scrolling, and never changes selection or document focus. The focus-applied path uses the same reveal routine after `focus({preventScroll:true})`. The current adapter's `restoreOnly` early return must still perform the reveal when the selected control already has focus. Document focus gates both restoration and the visible ring. The specimen reference is [specimen-interactions.js](specimen-interactions.js); it demonstrates focus-in scrolling only and does not replace production host navigation, handshakes or Elm state.

## Integration boundary
The committed renderer emits a static `.surface-status` and derives activity from detail text. It does not emit the disclosure, independent typed facts or typed outcome glyphs. D01 adds those source-backed projections and the Elm-owned disclosure before the production acceptance can pass. Until then the CSS gives missing facts neutral presentation and the original words remain available. The generated studies do not show the full source controls or exact cues; they are labelled Generated concept study and the source-shaped specimen is authoritative.
