# Engine lifetime remains an explicit authority requirement

Installed metadata `/usr/lib/qt6/qml/Quickshell/quickshell-core.qmltypes` exposes readonly Quickshell.processId and instanceId, reloadCompleted/reloadFailed, and PersistentProperties.loaded/reloaded. `/usr/lib/qt6/qml/Quickshell/Io/quickshell-io.qmltypes` exposes actual Process.processId. This metadata identifies supported properties; it does not prove instanceId changes on every engine reload or equate a PID with a QML object lifetime.

The [primary Quickshell reload documentation](https://quickshell.org/docs/v0.3.0/types/Quickshell/Quickshell/) states that a soft reload can reuse windows. Therefore an unchanged native layer address alone cannot prove unchanged QML object/engine identity. The [PersistentProperties documentation](https://quickshell.org/docs/v0.3.0/types/Quickshell/PersistentProperties/) describes state transfer and loaded/reloaded signals. Neither document establishes installed implementation equivalence; keep that limit explicit.

Batch V1 and the frontend CPU observation helper intentionally require an external exact engine/config epoch. Their positive synthetic tests are not evidence that such a native epoch has been observed. Do not supply a guessed constant or claim actual engine authority merely from PID/start, config bytes or layer addresses. Root's private pairing must supply a reviewed observed epoch and invalidation route before launch/scene/input acceptance. A future product scope implementation should use an actual reload/lifecycle witness with representability and stale-generation refusal modeled first; if this requires new source, stage a fresh batch derivative and preserve V1.

The physical keyboard opener is separately source-backed by installed snap.lua's real SUPER+T taskbar cycle binding. It is setup only. Menu capture and Return still require the actual keyboard surface layer, full captured owner and genuine release. Current B has not implemented or accepted its full host/GUI campaign.
