# Owned restore focus transaction — unapplied proposal

The B13 run recorded six ordered focus command envelopes taking 548.665 ms,
including 24 persistence spans taking 238.212 ms. The scene expired during its
second real refresh before validation or capture. This instrumented run does not
establish historical B12 per-call costs or successful effects from return events.

## Narrow change

Add an optional native adapter capability that performs the original monitor,
workspace pair for each exact stored member in the original order, in one owned
native-effect envelope. Keep all three actual motionRefresh invocations, all
three captures, original helper counts, controller atomic reservation lock,
original two-second receipt deadline, one-second helper limits and baseline38 /
fault34 predicates. Existing generic adapters retain their old apply method.

The owning transport is the existing hyprctl repl, captured by a sealed owned
launch. Its Lua body invokes the actual hl.dispatch / hl.dsp.focus APIs. Batch
splitting is rejected: the actual batch parser continues after an error and
hyprctl may exit zero despite partial failure. A successful process exit or raw
`ok` response therefore cannot discharge this transaction.

Before dispatch, retain every Python stored field / parsed metadata / exact fresh
member identity check. Capture the exact state and metadata raw strings. In the
compositor, before each original focus operation, re-read those exact strings,
check the actual selected window's address, hexadecimal stable ID, PID and
mapped lifetime, and check the selected output's native geometry/scale/transform.
This strengthens the old per-member checks; it does not replace them with a
caller boolean. Stop the Lua loop on the first failed guard or action result.

The Lua body returns one bounded JSON receipt with the exact fresh nonce, total
operation count, completed prefix count and typed success flag. It increments
the count only after the actual dispatcher returns a table with exact bool
`ok=true`. The caller requires exact keys/types/nonce/count and complete output.
Before Keeper.complete, a typed source-bearing transaction rechecks the original
Python stored material/member guards and current ownership. Malformed, missing,
partial, nonzero or changed-source results leave the native-effect job uncertain
under the existing durable ownership policy, even after leader/group closure.

The service holds its original atomic receipt lock while the native transaction
runs. New ingress cannot replace that scene during the operation. Original
atomic focus work could cross the receipt deadline; known complete effects still
need normal owned-job closure, while the expired scene gains no subsequent seed
or presentation authority. Check expiry immediately before dispatch and after
normal completion, retaining the same absolute deadline. Unknown completion is
never relabeled safe because it timed out or the process disappeared.

Empty/all-visible plans retain the old zero-focus no-op path. Scope is 1..64
unique exact members, 2..128 original operations; the actual three-member family
performs exactly six. The model abstracts the actual family as three members and
six operations, not a general proof of parser, kernel confinement or frame timing.

## Required source mapping and limits

Pin official source bytes at the actual clean efb5099 commit, the actual selected
installed core SHA da8fcacf… and hyprctl SHA 2780a8bb…, plus V21 plugin source and
B13 version/log/source witnesses. Do not equate a V3 candidate with this installed
runtime. Source correspondence is not a reproducible compiler proof.

There is no native build, new plugin API, direct socket bypass, effect parallelism,
focus deduplication, synthetic helper/job receipt or deadline extension. Proposed
runtime edits remain outside frozen V27/B13. A new collector must explicitly bind
the new source; baseline helper gates still count the three real refresh wrappers.
Known savings concern avoiding five owned launch/registration/completion envelopes;
end-to-end success and the remaining hidden capture cost require root's later run.
