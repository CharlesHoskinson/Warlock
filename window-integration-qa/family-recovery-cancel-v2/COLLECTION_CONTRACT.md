# Recovery V17 native collection contract (unfrozen)

Root alone owns native launches. This packet will pair the independently reviewed
corrected Recovery V17 closure with the original accepted family baseline and strict main,
process, source, runtime, transport and cleanup oracles. All actual old failures
and old closures are retained. This source stage contains the original38-gate baseline and two initial fault
collectors (compatible restart and actual closed nested peer). No collector
launch or native acceptance is claimed. Other cases listed below remain open.

The original family baseline must run first unchanged. Recovery collection then
archives complete raw immutable journals, exact service PID/start and lease
root/lock/nonce/session, all actor resource identities, renderer/helper executable
and sealed source roles, keeper registrations and authenticated terminal files.
Only an exact registered service lifetime can be stopped. Killing a renderer or
service is a fault stimulus, never proof of normal cancellation or closure.

Each recovery case binds one exact accepted receipt/captured identity/full member
scope plus original symbolic intent and any returned exact native results. Root
must observe the service gone, old keeper groups truly terminal, actor callback
and presentation authority gone, and capture files still present before restart.
Restart uses the same anchored runtime/root/lock/session with a fresh genuine
owner nonce. Helper query ancestry must admit only exact registered query jobs;
wrappers must not block trusted Snap/family queries or invent native authority.

For cancellation, archive two complete guarded client/native-family/output
observations, per-member present/absent/reused/unmapped current identity and
geometry/workspace/pin, actual durable non-settlement acknowledgment while the
retained capture inode/material is still present, then exact directory disposal
and complete old/new helper closure before new API exposure. Require no native
writes to surviving or replacement members after cancellation reservation.

For compatible recovery, the original symbolic toggle/activate must resolve
once, preserve any prepared endpoint and returned results, and settle only the
fresh exact current family through original guarded core calls. A repeated crash
must not recompute an opposite endpoint. Unfinished native effects/export,
unowned/replaced roots/sources, malformed/unstable observations or unknown helper
closure must quarantine with no API listening and retained unresolved state.

Cases: compatible presentation restart; definite closed peer/captured member;
reused address; unmapped peer; changed observed native family; crash after durable
cancel acknowledgment before source disposal; crash after source disposal before
final journal; native-effect uncertainty. All normal cases must retain the original
baseline and main preservation gates, explicit native unload, complete normal
fixture closure and owned private cleanup. Fault cases separately archive expected
product quarantine and actual fixture lifecycle; forced harness cleanup cannot
be reported as normal product cancellation. Current user/current-receipt live
cancel and interruption/reduced-motion ingress remain separate from this recovery path.

## Current source implementation

`native_integration.py` preserves every original baseline check AST and runs the
ordinary defaultV10/ToolkitV21 route against exact frozen V17.
`native_faults.py` requires that separate same-packet baseline, all38 gates/all15
main guards/all3 normal fixtures before any fault host. It minimizes normally,
requests restore, observes a fresh actual early interior frame, and stops only
the exact registered service through pidfd. Complete raw journal, owner/lock,
authenticated old keeper terminal and every retained actor capture are archived
before restart. The helper query registry changes only after old service lifetime
is gone; root/session/source/member guards and accumulated query budgets remain.

The restart uses `service_recovery_observer.py`, passing the exact documented
`recovery=factory.recover` constructor binding. The wrapper delegates real
NativeRecovery; read-only persist/dispose hooks retain actual checksum journals
and descriptor-relative inode-bound capture bytes. Persist failures produce no
acknowledgement witness; readback/material errors retain raw evidence and refuse.
A durable completed recovery snapshot must equal live startup recoveryHistory
before API readiness is accepted; new startup journal need not retain obsolete
top-level recovery keys. Closed-peer cancellation requires durable acknowledgement
with retained captures, no returned member results or endpoint success, unchanged
survivor geometry/workspace/pin/focus, then exact old resource disposal. Compatible
recovery requires three actual returned guarded restore results and original
family geometry/pin/deepest focus. All owned client/helper/transport/main/source
cleanup gates remain mandatory; expected service SIGKILL is recorded separately.

Repeated crashes at acknowledgement/disposal, reused/unmapped/changed families,
unfinished native-effect quarantine, C1/new reduced-validation pairing, and live
user/interruption cancellation are not accepted by these first two collectors.

Final native oracles additionally require original public workspace/output for
every compatible member, independent same-process peer preservation for both
fault cases, and an actual typed live owner/public start plus exclusive anchored
lease and SO_PEERCRED/read-only state API witness. Before/after root/lock/socket
and owner identities remain equal; raw refusal evidence is persisted.
