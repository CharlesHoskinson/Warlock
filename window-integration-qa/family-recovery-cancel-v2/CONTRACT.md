# Continuous family reversal acceptance

This fresh campaign extends the accepted FamilyV8 baseline. Existing frozen
sources, failed runs, and acceptance predicates remain evidence. This directory
is preparation, not a completed native run.

Use one owned private host and the same real taskbar, exact family identities,
native service API, actual renderer and guarded native compositor module.
Run the original minimize/restore baseline before adding this episode:

1. Start minimize and observe an actual complete interior presentation.
2. Request restore while that actor is active; observe an interior presentation
   for the new receipt. Start minimize again before that transition ends.
3. Require both reversals to reuse the same actor, source images, upload count,
   member order, output identities and generations. No new captures are allowed
   during these retained-source reversals.
4. Each retarget origin must equal the latest accepted presented frame for its
   output at retarget application, including sequence, timestamp, bounds and
   every member rectangle. A requested or submitted frame is insufficient.
5. Queued provisional motion has no native authority. Once a new retarget is
   accepted, old-token ready/endpoint events must never authorize a native effect.
   Native commits require the current validated receipt and exact family sources.
6. Observe the final minimize endpoint, ordinary actor retirement and persistent
   previews. Restore using a fresh actor and require exact original geometry,
   per-member pin state, deepest-modal focus and unchanged independent peer.
7. Renderer, service, shell, Qt, helper and native module cleanup must be normal,
   with clients stopped before the compositor. Main desktop observations remain
   unchanged; no main input or restoration writes are permitted.

A readonly polling observer may retain the actual bounded renderer event ring
under its existing lock. It cannot send renderer commands, change callbacks,
alter service state or substitute events. Its timing perturbation is disclosed.
Direct service requests are a bounded API integration route; genuine preview
clicks remain a separate acceptance requirement.

The full episode allows at most four exact motionTarget queries per member
(baseline minimize/restore, new initial minimize, final fresh restore) and nine
exact motionRefresh queries (three baseline restore, up to three superseded
restore, three final restore). The superseded worker can stop between queries;
six through nine refreshes are valid only with the complete ordinary terminal
helper evidence. These bounds authorize no other identity, command or ancestry.

Cadence measurements retain timestamps and gaps without inventing a new pass
threshold. This campaign alone establishes neither physical display smoothness
nor production installation. Raster acceptance requires the separately verified
default rendering path and unchanged original image oracle.

Use the frozen production-default V10 renderer without experiment, readback or
raster fixture flags. Require its exact `production-default` selection for every
actor. This adds one gate to the original 29 and eight continuous episode gates,
for 38 mandatory native gates. The accepted default44 collector is retained.
