# Exact private Snap helper lifecycle

Before adding the observer, specify its authority. Preserve all frozen older
packets and the actual candidate helper bytes. Materialize the new helper only
inside the selected owned runtime HOME, beneath a wrapper with a distinct frozen
source hash. Set HOME/PATH/XDG/observer configuration only on the selected private
compositor, verify them through actual Lua getenv, then load the full unchanged
candidate Snap Lua and actual Omarchy binding helpers. No main environment writes.

The wrapper accepts only hydrate once or forget-closed for one exact previously
queried native address/stableId/PID, with a matching original command. Require
the QA scope/core limit, exact compositor PID/start/UID, and genuine ancestry
(compositor directly, or its exact /bin/sh -c invocation). The pinned Hyprland
Executor.cpp uses one fork then /bin/sh -c; do not invent double-fork ancestry.
Require owned private runtime, full-EOF j/version IPC and matching socket peer
and inode. Neither a helper name nor the possession of an environment token
grants registration.

Record wrapper and actual delegate PID/start/PGID/ancestry/argv/source digest
before releasing a pipe gate to exec the unchanged helper exactly once. Preserve
arguments/environment/stdio and actual exit status. Record terminal status under
the same locked owned log. The wrapper may not call native dispatch or modify
helper results. Gate overhead is diagnostic and excludes cadence acceptance.

Only already registered exact operations may execute. Duplicate hydrate, duplicate
close lifetime, malformed identities, wrong HOME/instance/socket/ancestry/source
or replaced configuration/log reject before delegate exec. Failure is retained;
it is not repaired by accepting an unregistered helper or a name allowlist.
Compare the opened configuration descriptor's actual UID/mode/device/inode with
the initial pathname witness, then recheck the pathname after reading. Revalidate
the actual backend source after the pipe gate before exec. These checks do not
claim resistance to arbitrary concurrent same-user writes between the final
check and exec; frozen campaign inputs are not mutated during execution.

Before unload, require exactly one completed hydrate, one normal zero-exit close
helper for each actual closed fixture lifetime, no unknown operations, and all
registered wrapper/delegate PID/start identities gone. Preserve records outside
the disposable runtime. Existing host no-helper and clients-first gates remain.
This proves helper supervision, not address reuse timing or held gesture behavior.
