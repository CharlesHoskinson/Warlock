# ABI client connection and lifecycle safeguard

The old ABI files/reports and frozen attempts stay unchanged. This fresh revision tests only public AT-SPI Manager D-Bus ABI with fabricated packets. It makes no native input, reader navigation, compositor, X11, speech or braille claim.

1. Require the shared qa_run.py scope before any session/AT-SPI connection or client factory. Use its owned0700 /run/user/$UID/wqa/<4hex> runtime before private D-Bus. LimitCORE is exactly1 unless explicitly diagnostic.
2. Require an explicit private session bus address inside that runtime; verify owned socket/peer credentials and successful D-Bus connection. Inspect a supplied AT_SPI_BUS_ADDRESS or already-owned org.a11y.Bus address, validating private transport before key calls. Do not autoactivate a missing accessibility service. Absence of the separate AT-SPI registry bus is recorded and allowed for the direct Manager-only ABI proof, because that official backend uses the session-bus KeyboardMonitor API.
3. Before constructing official Orca/public Device, require the exact live unique owner and introspected KeyboardMonitor methods/signatures. Force Manager preference, remove legacy preference, and avoid DISPLAY. After factory construction require actual AtspiDeviceA11yManager. Refuse X11/Legacy/unknown fallback BEFORE any keysym/keycode/grab API. A valid pure-Wayland Manager remains supported and maps keysyms directly without X conversion.
4. Recheck connection open and exact manager owner before each key operation and periodically while waiting. Owner disappearance/replacement or bus loss terminates cleanly and retains failure. No implicit device migration or Xlib probing is performed. Intentional X11 backend tests require a separate live-display guard and are outside this Manager ABI fixture.
5. Normal cleanup requests client exit first, waits both clients and confirms subscription removal while service is alive, then stops the service, then exits its private D-Bus scope. Failure cleanup likewise attempts every exact owned client before service. Use captured PID/start/group identities for bounded fallback; forced cleanup is recorded and fails normal-shutdown acceptance. Never terminate a main/user client or accessibility service.

Meaningful offline tests exercise refusal before factory/key APIs, Manager/noDISPLAY permission, owner-loss refusal, and subprocess launch outside the required scope. Real fabricated-packet ABI execution needs root's reviewed scoped command; no compositor/GUI launches in offline tests.

Primary source evidence: retained official at-spi2-core2.60.7 Device.new_full can fall back even when Manager preference is set; A11yManager map_keysym_modifier stores direct keysyms, whereas DeviceX11 mapping calls XKeysymToKeycode. Installed at-spi2-core is2.60.6-1. The retained handoff's exact crash attribution is not reclassified from source similarity alone.
