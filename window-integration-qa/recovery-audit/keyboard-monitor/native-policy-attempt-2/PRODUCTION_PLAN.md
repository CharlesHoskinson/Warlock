# Proposed production packaging after native policy gates

No production build, main plugin load or autostart change is authorized by this plan. The private v5 library cannot load on the main session by design. A separate fresh candidate and root review are required.

1. Close the native policy matrix or preserve each failure as a blocking correctness issue. Actual US host CKeyboard command success is bounded evidence; it cannot replace permission, IME, native keymap, lock, disconnect and device cleanup tests.
2. Extend the formal service model before implementing startup adoption and retirement. On successful PrepareUnload, atomically enter an irreversible retiring state in the compositor loop: clear grabs/subscriptions and reject WatchKeyboard, GrabKeyboard and SetKeyGrabs until this plugin instance exits. New native key packets pass through. A loader's query followed by external unload alone leaves a reactivation race in v5. A false PrepareUnload leaves existing subscriptions active. Accepted held native keys retain their natural releases, with no synthetic duplicates.
3. On startup, adopt existing valid KeyboardMonitor name owners through a bounded ListNames/GetNameOwner control-plane pass; reconcile owner changes queued during initialization. Do not query D-Bus on the per-key path. Test a real registered official client both before service start and after a service restart; merely owning a generic name is insufficient evidence of official reader recovery.
4. Build a fresh exact-ABI production library at a new user-local versioned path. Replace the private guards with reviewed real-session guards: runtime owned by the current UID, exact compositor ABI/version, exact session bus/runtime target and primary manager ownership. Never overwrite a loaded library. Stage source, compiler/build IDs, dependency/license inventory, hashes and rollback before requesting main deployment.
5. Provide a user-local loader/unloader that resolves an explicit or uniquely identified compositor and never retargets ambiguously. A normal unload calls the retirement/quiescence API on that same instance and verifies success before unloading its exact library. If keys are captured, it fails without altering capture. Do not terminate user apps or require a main compositor restart. A reload retires/unloads first, then loads a fresh ABI-matched library. Autostart integration may start this passive bridge only after root reviews and authorizes it.
6. Preserve ScreenReaderEnabled=false and the reader's current profile. The bridge never starts Orca, enables reader status or injects keys. Existing reader AX compatibility wrappers remain agent-owned. Actual user opt-in should launch the reviewed strict Wayland reader wrapper; when a real manager owner exists, the official DeviceA11yManager path bypasses the legacy grab shim. Test actual main commands only after an explicit GUI/deployment grant.
7. Preserve client identity, full window states, active keyboard state/locks, focus/cursor, outputs, exact catalog bytes, main plugin list, accessibility socket inode/connectivity and prior reader state around deployment. Retain failure evidence and provide exact source/runtime backups and rollback paths.

Forced raw core plugin unload or error ejection while captured keys are held remains unsupported maintenance. Exact core source exposes a release-only bind risk through KeybindManager's unmatched-release fallback; ordinary client release suppression does not prove shortcut safety. Normal wrappers enforce quiescence, and no synthetic release is introduced. Any future claim supporting forced unload requires a real core fix and native proof.

The official DeviceA11yManager also probes PointerLocator.QueryPointer; the keyboard-only candidate currently returns UnknownInterface, which appeared as a warning in the private Orca logs. Keyboard command success does not establish pointer-monitor integration. Review that interface separately before claiming complete manager compatibility.

Main compositor restart, physical hotplug, physical keyboard hardware and broader non-US input behavior remain independent untested gates.
