The immutable full private PointerV5 campaign passed185 acceptance and19 preservation gates (report fd4c8678b208f5ff56ce0e6e35f403a6e40e6a3329947b9792336fae9816d2b4). ## Native session and owner
Production initialization must validate exact running compositor commit/signature, canonical owned nonsymlink0700 runtime, exact own session bus socket and stable owner UID. Main runtime is /run/user/UID; an isolated proof may use exact owned /run/user/UID/wqa/4hex only with the existing explicit private flag and scope guards. Do not infer a main target from private env. Native current signature comes from compositor state. Manager ownership remains DO_NOT_QUEUE and names alone never request interception. Input permission/IME/device/keymap semantics are the accepted185 policy; no package broadens permissions.

Production has no org.omarchy.KeyboardMonitorProbe method/interface. Only compositor Lua omarchy_a11y exposes identity(), capability_status(instance,package,incarnation,clientUnique), prepare_unload(instance,package,incarnation). Each load generates a fresh256bit random nonce; unknown/stale tokens fail before reading quiescence or changing subscriptions. Capability status is read-only, verifies exact Manager owner/current registered client and reports actual quiet/lock-clean/pre-replay state. The adapter's accepted fresh-device marker/public ownership checks remain required. This does not give a reader registration D-Bus maintenance authority.

## Normal retirement/reload
False PrepareUnload preserves exact policy/captured-key/virtual-lock/pointer subscriptions/work. True requires accepted unloadQuiescent, irreversibly retires watch/grab/query and cancels pending pointer work; no callbacks reactivate afterward. Accepted held native keys receive natural releases; no synthetic release is introduced. Forced raw/error core unload with captured keys remains unsupported. Normal wrapper unload requires exact per-load nonce before preparation and before exact path API unload; failed retirement never permits raw unload. Unload failure after retirement leaves a passive retired bridge.

Every wrapper IPC uses exact-instance hyprctl -i and matching env, bounded full reply, process UID/PID/start and socket inode/peer revalidation. Strict explicit/env target never falls back; absent target requires exactly one instance. Validate immutable versioned source/artifact path+hash+inode/maps+unique plugin name/version/ABI. Serialize managed actions with a user-owned runtime flock. The retained v1 actual-source counterexample shows that compositor/artifact identity alone cannot protect plugin incarnation; nonce repair is mandatory. A same-user uncoordinated raw core swap after final verification is an explicit unsupported interference boundary: path-only core unload is not an atomic lease. The model covers serialized managed paths; it does not claim protection against that raw race.

## Reader and actual capability semantics
Package the original signed Orca50.2 prefix/dependencies/provenance plus explicitly labeled Omarchy Orca compat signed-v3 (only mouse_review.py differs) and accepted process-only CapabilityAdapter/Reconnector. Production bootstrap injects read-only exact-instance Lua verification rather than private Probe. It runs only when user explicitly starts the reader; normal bridge package/load/reload never starts it or changes ScreenReaderEnabled. Bootstrap sets strict Wayland modifier handling as accepted, preserves real speech/settings/profile, and does not carry silent factory/private QA portal/VFS overrides into user apps.

Keyboard capability means protocol/hook support for explicitly subscribed readers and permission-enabled actual input. It does not promise hardware/general-keymap proof beyond retained native acceptance. Pointer capability uses actual logical dd, exact unique AX identity or truthful UnknownToplevel; same-PID ambiguity is refused. Official libatspi public callback retains integer conversion; signed-v3 restores signed bit representation without inventing a signal. No pointer mapping is fabricated for unexported apps.

## Deployment and rollback
Create concrete versioned user-local payload, pinned manifest, bootstrap/control scripts, source/provenance/licenses and reviewed integration fragments. Never overwrite a loaded .so; never write /usr/share/omarchy. Deployment is separate from activation: prepare backups/exact hashes and immutable source closure; approval flags stay false until production native proof/review. Install creates versioned files and backups mutable launcher/integration pointers with guarded atomic writes; reader intent remains untouched. Rollback normally retires the exact active package first, then restores only files matching this deployment's installed hashes, preserving unrelated newer edits. Main config changes/autostart/start/load remain root-coordinated and unexecuted here.

## Install transaction and failure semantics
A plan enumerates every payload file and source hash and the exact prior mutable launcher bytes. Apply is unavailable while productionAccepted=false. Copy into a new version directory only; preexisting version directories fail. Mutable launcher writes use no-follow directory/file checks and exact expected old SHA, with private persisted backups. Rollback restores only matching deployed launcher SHA after proving the package is not mapped in any owned compositor; a loaded bridge must first use normal guarded retirement/unload. Rollback leaves immutable payloads for audit. No automatic fallback to raw unload, older namespace, default compositor or enabled reader exists.

The standalone reader launcher checks actual ScreenReaderEnabled twice before running Orca's entry. Its code-path environment preserves HOME and XDG_CONFIG_HOME/XDG_DATA_HOME/XDG_CACHE_HOME/XDG_STATE_HOME, speech CLI and settings. It installs no QA profile/customizations/silent factory. Bridge startup may precede or follow an already explicitly requested reader: owner replay uses the accepted public adapter; maintenance itself never constructs Orca. Actual production runtime/capability transport and user speech/profile startup remain required fresh native gates.
