## Evaluation tickets

Before each command, the guarded actual harness reserves an immutable ticket with a fresh nonce, exact harness PID/start/argv/source/executable, selected compositor PID/start/socket/version full EOF, exact native artifact/command and immutable private configuration descriptor/path/hash witness. The ticket declares one unload evaluation, two load evaluations, or one explicit ctl reload evaluation. Each occurrence has an ordinal and exact hydrate budget, keyed by ticket and ordinal. No additional evaluation can consume an authorized slot silently.

A frozen owned Lua prologue runs before unchanged full Snap. It checks the armed nonce/kind/limit, increments the compositor's persistent environment ordinal, and captures that ticket/ordinal in the actual child environment. Each exact wrapper still proves actual compositor ancestry/PID/start, exact argv/source/private environment, current selected IPC peer/version/full EOF and source recheck after its execution gate. It matches that child environment to its pre-reserved ticket/ordinal; it never labels callbacks solely from a mutable latest generation counter. Dynamic environment reads use actual Lua getenv or the executing child, never assumptions about /proc/PID/environ reflecting setenv.

One hydrate delegates exactly once per actual evaluation. Inactive relay applies only while the actual plugin provides file_drag_active. A load transaction runs its two queued evaluations in the same idle batch; ConfigManager cleanTimers cancels/removes prior Lua timers before the next evaluation. Thus the first evaluation's inactive callback is superseded; only the second/current context has one inactive relay obligation. Unload contexts have no plugin file_drag_active and no relay obligation. This is a source-backed context lifetime distinction, not a larger blanket helper budget. Unexpected callbacks, duplicate ordinals, extra evaluations, missing required callbacks, wrong ticket/root/source/env/argv or nonzero terminals fail.

All actual evaluation ordinals and required helper starts/terminals/process identities are archived. Before advancing feature authority, every prior expected callback must normally complete and all exact actual helpers must be gone; the actual current ordinal must equal the declared count. Original explicit ctl reload remains a separate one-evaluation ticket after genuine plugin unload/load and their required callbacks; its original action is not removed.
