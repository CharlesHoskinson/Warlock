regular, uid1000, mode0600, unlinked4MiB tmpfs file under its exact newly created
mode0700 private profile. Its BrowserMetrics filename encodes that exact PID;
fdinfo/device/inode match the rw-s full-range VMA. Root identity and fresh
mapping remain exact. This is private mutable data, analogous to the already
allowed live private profile/cache data; no source code or native authority is
granted. V11 remains a failed full-flow campaign.

Fresh acceptance requires the exact captured browser PID/start/UID/scope/frozen
executable and private profile/runtime inode ownership. Exactly one matching
producer FD must have regular type, exact full mode0600, owned UID, nlink0,
size4194304, O_RDWR without O_PATH, exact target/device/inode and runtime tmpfs
mount. Only the canonical BrowserMetrics hexadecimal time/PID filename under
that profile is eligible. VMA must be rw-s, offset0, aligned, exactly4MiB and
match that producer. No executable alias may appear in the complete observed
owned batch or fresh browser/compositor samples.

Require before/after exact FD number, target, inode, device, owner/mode/nlink/size,
flags and mount, profile/parent identity, browser lifetime and VMA. A fresh
confirmation after ordinary strict disk validation must agree before input.
mtime/ctime and data bytes may change because the allocation is writable data;
no immutable-content proof is claimed. Disappearing/replaced/duplicate/malformed
or unreadable witnesses invalidate before input. Only the exact raw browser
snapshot and mapping line can consume the proof. Authority is bounded to these
observed owned snapshots, never global or continuous proof.

mappings still refuse. Original stable code freeze, Files read-only UUID proof,
