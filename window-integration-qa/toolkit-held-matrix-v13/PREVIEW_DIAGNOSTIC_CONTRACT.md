# Held V9: retained preview allocation diagnostics

Frozen V8 and its failed fourth case remain immutable. This derivative keeps
all52 case actions, pointer protocol/motions, source-card identity, strict native
arrival/click/frontend/retirement oracles, and every evaluation-ticket guard and
budget unchanged. V22, ServiceV12/readbackV4 and frontendV1 remain paired.

The diagnostic must durably record a proposed icon or exact source preview
point BEFORE sending its unchanged motion, including exact QS lifetime, actual
widget state/item, native layer allocation, cursor, input lifetime, extents and
known released transitions. The copied production QML adds only read-only
allocation diagnostics: actual popup card/content and clipped Flickable viewport
rectangles in the same layer-window coordinate space as preview item positions.
Original source bytes are retained and verified independently from these exact
diagnostic copy hashes. No property affecting layout/input/action is changed.

Each bounded arrival poll records actual native and QML states before the
original arrival decision. Only the existing actual cursor tolerance and exact
QS layer input owner admit arrival; recorded geometry cannot grant click
authority. Missing/malformed/error evidence remains a failure and is retained.
The journal uses a fresh O_EXCL/no-follow owned0600 file, full JSON records,
flush/fsync before each command or decision, and a terminal success/error event.
No observed clip hypothesis changes the point, retries the action or scrolls.

The model distinguishes proposed observations, motion, actual owner/cursor
evidence and a genuine click. Partial/failed evidence cannot authorize a click.
A recorded or emitted point is not native delivery. Failure teardown preserves
all source/helper/client/QS/native ordering and retains feature failure.
