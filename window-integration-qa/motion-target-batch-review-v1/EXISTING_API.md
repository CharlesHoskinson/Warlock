# Existing real taskbar endpoint API and bounded batch proposal

Inspection is read-only. Installed widget and accepted C1 widget65/candidate Pin widget66 expose only motionTarget(encoded identity), not motionTargets. Existing lookup enumerates actual bar module widgets, selects each actual matching member by address, String(stableId), typed PID, refuses hidden/unrendered/clipped icons or missing real monitor, maps actual icon coordinates into the real bar window, sorts current candidates by actual home flag, and returns the first candidate or null. Existing response contains visible/home/screenName/monitor origin/rect, without explicit member or widget lifetime identity.

Proposed fresh derivative: retain existing one-target function and delegated geometry function byte-for-byte. Add bounded duplicate-free ordered array API for exact typed {address,stableId,pid} records. Capture the actual moduleWidgets list once during one synchronous QML IPC evaluation, perform the same real per-member lookup and actual home-first selection, and return every requested identity with the selected real target or null. No fabricated target, override fallback, active-window substitution, refresh/action/focus or native input. Reject malformed/duplicate/oversized requests before lookup. Keep ordering exact, preserve distinct same-process and same-app members, and do not fill a missing member from another family's result.

Actual widget lifetime identity needs an explicitly reviewed representation before implementation: a per-shell monotonic instance-generation token assigned to each real module QWidget/QML object at creation, bound to the exact actual QS PID/start/config externally. Object enumeration index, monitor ID, home flag, or an invented native pointer is insufficient alone. Retain actual screen/monitor/bar/icon allocation alongside the instance token. A synchronous list holds current references for the lookup; no claim of a globally immutable renderer/layout snapshot follows. Consumers must refuse stale process/widget/output/layout witnesses before native scene authority.

Service integration is a separate root-owned source branch. Validate the returned input/output vectors and raw real IPC peer/EOF, require complete eligible endpoints for the whole captured family before atomic plan/token mutation, retain previous one-target failure policy and source closure. Empty/null/missing/duplicate/stale endpoints cannot create authority. One IPC request may reduce measured launch overhead; no static/model test or timing adjustment proves latency acceptance. Existing crop helper cost remains separate.
