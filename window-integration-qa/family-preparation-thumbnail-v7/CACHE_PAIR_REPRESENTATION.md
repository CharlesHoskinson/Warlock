# Three exact cache pairs

The formal and product requirement remains three exact immutable family preview
pairs: one JSON pointer and one PNG per captured native lifetime. The unchanged
`capture_evidence.unchanged_pairs` validates those identities and all six actual
file hashes, then returns a six-entry dictionary. V2 correctly passed both strict
interior reversal origins but incorrectly required its returned dictionary length
be three. That failure and all source/native evidence are retained unchanged.

V3 requires six dictionary entries, exactly three JSON and three PNG, after the
unchanged exact three-pair validator. The original strict renderer oracle, product
V13/V10, all38 gates, helpers and normal lifecycle remain. This corrects the
harness representation; full native acceptance requires a new complete run.
