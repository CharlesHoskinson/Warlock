# Same-process keyboard stage deployment plan

Root owns execution. `prepare_deployment.py` is read-only against the live explorer and creates a private review package under QA. It never signals PID667402, writes live source, changes flags or performs file operations.

The original already runs the responsive stateful host. Its three PersistentProperties strings share the candidate's reloadableId and schema. Therefore this deployment uses existing JSON transfer and skips FILES_OPEN automatically. No legacy migration file is needed. The guarded scope remains idle hidden Home, empty selection/clipboard, no prompt/menu/preview and no in-flight operation.

The prepared package substitutes a fresh durable user-only native URL outside the application's watched tree. Its V4 binary is byte-identical to the reader-tested extension. It must be installed to a new path, with no loaded library overwritten. Only the shell import URL differs from the tested candidate; a copied real reload must prove module resolution before execution.

Before mutation, revalidate the15 original source hashes, candidate hashes, scripts/spec hashes, exact PID/instance/process start and fresh public/full UI state. Prepare all replacement bytes and private backup first. During a short exact-pidfd stop, atomically replace all15 QML files. If any replacement fails, restore original bytes while still stopped, then continue. Resume once so the watcher coalesces changes.

Verify same PID/instance and ready state, hidden visible/backingVisible values before native mapping, exact public history/preferences and full exported UI state. Use semantic native client comparisons (address/stableId/PID/geometry/workspace/pin/fullscreen), rather than entire volatile clients JSON/list order. Verify focus/cursor/layers, catalog/dashboard bytes, clipboard/primary raw/MIME hashes, accessibility flags/socket inode, and operation/spec hashes. Do not call files open/toggle during deployment.

Retain the successfully loaded stateful host. Reverting to a stateless legacy host could reopen FILES_OPEN and lose navigation history. Root decides rollback/recovery from the concrete ready/error/state evidence.

This stage has scoped native reader coverage only. Gallery/tree/Home media/pin/recent/storage/details reader activation still needs its own bounded proof if required for acceptance. Keep those limitations visible in the deployment decision and central report.
