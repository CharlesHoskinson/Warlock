# Actual family motion-target batch

This fresh source derivative preserves the existing motionTarget IPC and motionTargetFor function exactly. It adds one synchronous read-only motionTargets IPC request. No refresh, freeze, begin, focus, input, action, synthetic target, fallback window or service mutation is permitted.

The encoded input is an array of 1–512 records with exactly address, stableId and pid. Address and stableId are canonical lowercase hexadecimal strings; PID is an actual positive int32 integer. Address is 0x-prefixed, nonzero, at most64 bits. StableId is nonzero, unprefixed, at most64 bits. Reject extra keys, malformed types, duplicate exact identities and repeated addresses even with different lifetime tokens before enumerating widgets. The request is at most128KiB. Preserve input order and exact identity values.

Capture the actual moduleWidgets list once. Every returned target comes from the unchanged real motionTargetFor lookup on an actual widget. Select eligible candidates using the existing home-first rule and stable enumeration order. A missing/hidden/clipped/unrendered member returns null; no other member substitutes. Exceptions, duplicate/invalid widget generations, unstable geometry or allocation witnesses refuse the whole observation. Missing targets do not confer scene authority.

The new witness records actual widget and task-delegate generations, current screen name and geometry, monitor id/geometry/scale, bar offset/size/position, icon map/size, flickable clip and allocation. Generations are assigned monotonically to the actual QML objects using a shared JS library, bounded by safe integer representability. They are logical object lifetimes, not native pointers. They are scoped to the exact externally observed QS PID/start/executable/config AND QML engine generation. A new engine/config reload invalidates all prior witnesses even if its counter resets. Consumers must provide that external epoch; response values alone cannot establish process/engine authority.

For each selected candidate retain actual QObject references during the synchronous observation, compare before/after actual monitor/bar/group/item/icon/screen references and exact allocation snapshots, and compare the unchanged legacy target with independently copied actual witnessed translation. No epsilon or invented offsets. Refuse mismatches. The response reports a bounded observation, not an immutable display frame or globally atomic scene snapshot. Consumers revalidate process/engine, member lifetime, actual output/layout witness before committing native scene tokens. All required family endpoints must be eligible before any atomic plan/token mutation.

One actual IPC request is counted as one bulk query. Per-member eligibility and real widget/output obligations remain separate. Model/CPU tests establish parsing and selection policy, not genuine GUI geometry, IPC lifecycle or latency. Root owns private native pairing and service implementation.
