# Actual preparation timing observation

The original V5 integrated baseline failed with three captures retained, no
renderer seed or uploads, and the original controller deadline. Individual
preparation phase costs were not observed. This fresh derivative observes actual
Python call/return boundaries in the exact frozen V20 service before proposing a
performance change. The inherited baseline and fault checks, budgets, production
methods, actor types, callback source proofs and source binding remain unchanged.

The observer uses Python's profiling hook; it replaces no product method,
callback, command, process or result. It records bounded monotonic spans in
memory, tagged by actual source path, code symbol, thread and selected primitive
identity/argv fields. No disk I/O occurs in the profiling callback. Events do not
prove success: Python's return event can also accompany an exception. Results
and native authority come only from the inherited service and baseline checks.

An existing profiling hook refuses setup. Callback errors or event overflow are
latched; they never throw into product execution and never yield complete timing
evidence. Late/unmatched returns cannot become completed spans. Observation
stops before exclusive/fsynced evidence publication, including failed service
closure, so inherited terminal-binding failure cannot erase the timing packet.
Outstanding spans, missing endpoints, source changes, failed persistence and
faults make the observation incomplete. The packet is diagnostic only and never
claims native baseline, physical cadence or production acceptance.

The original failed V5 sources and results are immutable and inherited into the
new freeze. Main desktop writes, restoration writes and fault runs remain
unauthorized. Private native launch still requires root review, complete source
freeze, the five crash-noise safeguards and a serial root-owned QA scope.

The formal model checks bounded recording, source stability, latched faults,
unmatched boundaries and absence of semantic authority. Actual CPU tests check
profiling real concurrent functions, unchanged return/exception identity,
preexisting hook refusal, overflow, callback fault and exclusive persistence.
Neither can prove native preparation performance without the private GUI run.
