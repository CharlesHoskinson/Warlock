# Exact installed batch callbacks

Independent review of the unfrozen V7 candidate found that a frozen source hash
does not identify the method installed for a callback role. Five different
genuine BatchPreviews methods could be installed under the wrong roles and pass
initial binding. A later comparison to that initial witness preserves the error.
The retained CPU counterexample is external; original GUI gates are unchanged.

Before first actor binding, after its disk witness, and at both terminal samples,
each installed stage, finish, discard, require_releasable and require_disposable
method must have exactly the corresponding canonical BatchPreviews function
and be bound to that actor's actual BatchPreviews instance. The adapter finisher
must have the canonical NativeDesktop.finish_capture_previews function and be
bound to the same actual desktop. A different genuine object or another genuine
method of the same frozen module is refused. Existing command/root/preview,
module/lease, callback snapshot and source checks remain mandatory.

The typed role model precedes this runtime correction. Role IDs abstract actual
Python function identity and bound owner identity; source=true alone never grants
role authority. The role model grants no native effect, helper settlement or GUI
acceptance. Actual kernel fixtures must demonstrate wrong role, wrong owner and
replacement refusal before the original 38-gate native baseline can run.
