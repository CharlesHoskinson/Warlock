# Browser focus setup before coordinate calibration

V14's retained actual failure has native cursor/hit Browser and native focus and
pointer owner Files, with no DOM pointermove. The actual private policy remains
`follow_mouse=0`. The existing calibration requires a real page pointer event;
moving a pointer to a window under this policy does not establish its delivery.

V15 explicitly establishes Browser native focus as fixture setup before any
layout/DOM capture used by the coordinate witness. This setup is never an
original feature acceptance, textarea click, trusted edit, Files raise, or user
physical input proof. All original fifteen acceptance calls remain exact.

The setup has an exact owned Browser PID/start/address/stableId, private attached
CDP session and private compositor guard. Immediately before dispatch, one
synchronous Lua transaction resolves the public window wrapper and requires the
public native `window_lifetime` equality with all three window selectors. It
invokes the official focus dispatcher with that exact address selector, without
a yield, checks the same native lifetime afterward, and retains the raw command
ACK. An ACK alone cannot authorize calibration. Bounded actual native observation
must show Browser nativeFocus, pointer owner, live pointer surface, clear input,
and unchanged owned process/window lifetime/session. Before/after setup DOM
draft value, selection, clicks and original event log remain exact; setup is
allowed to change active DOM focus but is not credited as textarea focus.

The primary focus dispatcher resolves the selector synchronously and delegates
to Config::Actions::focus, which calls fullWindowFocus and warpCursor. Captured
primary sources explain the intended route; actual private native observations
prove the setup state. They do not prove installed source revision equivalence.

All subsequent geometry pairs, each motion, each selected DOM sample and final
pre-click observation require the same exact Browser focus snapshot, Browser
pointer/hit owner, owned lifetime/session and original V14 clear-input/layout/
timeOrigin/draft guards. No fallback to another window, follow_mouse change,
guessed inset, synthetic DOM event, CDP input, or arbitrary evaluation is added.

Warping to the Browser surface center may already put the pointer at the first
candidate. Candidate ordering then swaps the two existing integer interior
points. Before writing either move, its destination must differ from the actual
current native cursor; zero displacement refuses. Both candidates remain exact
two-token integer commands within the private output, and the original strict
two actual event translations remain mandatory. Candidate ordering has no
coordinate authority and cannot satisfy any original feature gate.

Missing/refused command ACK, stale owner/session, wrong observed focus or pointer
owner, grabs/held buttons, unchanged cursor destination, layout change or focus
loss revoke calibration before any button. Every raw setup/motion observation
is saved before validation, including failure. Later genuine Files presses must
still begin with Files unfocused, then prove exact native focus/raise and unchanged
real copied callback. The existing strict code/data/runtime/main/lifecycle guards
and immutable V14 failure remain unchanged. Root alone may execute native QA.
