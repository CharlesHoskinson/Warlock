## Source points and proposed changes

Frozen V10 Renderer.cpp is a standalone Wayland/EGL renderer with Qt JSON, rather than Qt QPA or a scene graph. CommitLedger.hpp38 MemberFrame stores source plus rectangle; line50 Frame has no derivative. Line81 accept copies the pending immutable frame after successful swap and current generation/identity/source/time/sequence checks, then retains it as an output origin. Lines133–152 retarget/sceneRectangles/prepareFamily currently copy accepted positions and interpolate linearly. Renderer.cpp446 and478 independently derive drawing and submitted members at the same progress; line648 shares one batch time across outputs.

1. Add velocity to MemberFrame and trajectory epoch, common duration, source order, output generation and sampled elapsed time to immutable Frame metadata. Generate one SceneSample per output at the common batch time. Use its rectangle vector for existing GL drawing and pass this exact sample into prepareFamily; do not resample at submission time or combine historical geometry with a current velocity.
2. At a retarget, take each output's exact latest accepted displayed Frame and copy its rectangle plus analytic velocity pair for each ordered source. Prepare all output curves and one common duration intersection before changing the ledger token. Commit the plan atomically after all identities/source order/generations/targets and floating bounds validate. The primitive's 64-member cap cannot flatten 64 members across multiple outputs; expose a bounded all-output duration solver or calculate equivalent verified intersection separately, then instantiate per-output curves with the same duration and assert actual durations equal. Empty intersection cancels/refuses through the normal existing policy without authority or partial state.
3. Keep the derivative from the sampled immutable Frame at the existing presentation acceptance, not recomputed at feedback time. Sample time and presentation timestamp are distinct. Mixed-output origins may have different most-recent displayed sample times; preserve each exact pair. C1 in the curve parameter does not prove physical cadence or remove a held-feedback interval.
4. V10 Renderer.cpp578 resets startedNs unconditionally for every valid same-token start. Make start one-shot or idempotent per trajectory epoch. Initial scene uses zero velocity; later retarget already establishes its own common start. Duplicated start must not restart from the origin.
5. Keep canonical double seconds for actual curve parameterization; do not truncate a nanosecond-scale duration to integer zero or round it upward beyond the allowed interval. Define duration representability/minimum-cadence refusal separately from mathematical continuity. Analytic calculations have floating rounding; telemetry must store the actual evaluated analytic result, with independently specified derivative tolerance for numerical audits.
6. Retain existing ledger swap/presentation/resource/source validation, old-token authority refusal, retirement, discarded-feedback failure and reduced-motion behavior. Constructor or sampling failure must invoke normal cancellation and produce no native grant. No source acquisition/upload is added on reversal.

## Diagnostic guarantee and required evidence

Keep static diagnostic mix(), sample command, sample progress, original member JSON fields and raster oracle unchanged. Add ordinary-motion kinematics evidence separately, sourced from the same immutable frame. Preserve shader selection, prefix composition, pixel coverage, source bytes and buffer ownership. The runtime-constant diagnostic mode must remain unable to invoke native validation/start authority.

Before native review, formal/offline tests should cover duplicate start; wrong epoch/order/generation; submit without successful swap; early/delayed/stale/discarded feedback; repeated family retarget; mixed-output global duration, empty intersection and partial-plan refusal; reduced motion/resource cleanup; and matching immutable GL/submitted/accepted geometry plus velocity. Fresh ordinary motion/reversal/mixed-output/reduced-motion campaigns and original diagnostic raster gates remain necessary. No deployment or physical cadence claim follows from this primitive review.
