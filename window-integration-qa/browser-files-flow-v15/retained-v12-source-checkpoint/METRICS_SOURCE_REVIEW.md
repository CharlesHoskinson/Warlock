# Browser V12 runtime data source handoff

This stage grants bounded classification only to the exact root browser's
owned writable unlinked tmpfs data. Retained V11 attribution remains diagnostic
and V11 remains a failed campaign. No histogram contents or installed source
branch equivalence is asserted.

## Formal sequence

The initial21-case model and2000 traces are retained in `metrics-first-model`.
Independent review demonstrated still-valid identity replacement hidden by
Boolean predicates. The current model carries exact FD/device/inode/mount,
runtime/root/executable/profile/parent/target/captured snapshot/mapping tokens,
complete flags and explicit O_PATH refusal, plus epoch invalidation of partial
and confirmed proofs.50 named cases and2000x100 traces passed before runtime
changes in `metrics-formal-identity-before-implementation.json`.

The captured snapshot token binds the original root maps hash; fresh root maps
may change elsewhere while preserving the exact candidate VMA and bounded
executable-alias absence. Contents, timestamps and FD position are deliberately
outside the immutable witness projection.

## Runtime refinement

`owned_metrics_data.py` takes fresh runtime/profile anchors before browser
launch. It captures both full samples, including errors, before predicate
checks. Each sample includes exact root and compositor PID/start/UID/scope,
frozen executable and mount namespace, runtime/profile/BrowserMetrics parent
directory metadata, runtime tmpfs mount record, full matching FD inventory,
stat/readlink/fdinfo/raw mountinfo, and fresh root/compositor raw maps.

A candidate requires canonical uppercase hexadecimal PID filename, one producer
FD, full mode0600 including special bits, regular owned unlinked exact4MiB
file, O_RDWR without O_PATH, exact complete flags/mount/device/inode/target,
and page-aligned rw-s fullsize offset0 VMA. Directory paths must be canonical
nonsymlink owned mode0700 objects. The confirmed parent anchor is retained
across successive calls. All captured owned map rows and fresh root/compositor
maps prohibit executable aliases by device/inode.

The original exact root raw maps hash and mapping line are the only classifier
binding. `mapping_evidence.validate` optionally supplies the actual captured
row identity; all existing raw-only callers keep their old behavior. A
descendant, Files, compositor or other batch cannot reuse the root proof.
Every new observation and post-disk confirmation revokes prior partial state
first. Read errors, valid replacements, disappearance, duplicates, mapping or
metadata changes refuse; no stale observation remains usable after failure.
Empty candidate snapshots are refreshed too and refuse newly appearing metrics
mappings before input.

`private_session.mapped_inputs` records raw evidence and both metadata samples
before strict disk validation, then repeats the witness after ordinary strict
disk and existing copied-Files proof validation. It explicitly asserts
accepted+confirmedAfterDiskValidation+usableForInput before returning. All
ordinary/deleted code guards and the original browser draft/caret, Files
callback, reload/focus, sandbox/network and lifecycle oracles remain mandatory.

## Kernel tests and remaining authority

CPU-only tests use real tmpfs, real procfs, real shared4MiB mmap, and exactly
one producer FD (`trackfd=False`), with actual duplicate/permission/size/access/
O_PATH/fullflags/inode/alias and directory replacement faults. Their owned
qa-harness scopes contain no GUI processes. They test mutable contents,
timestamps and position variation, stale partial proofs, exact row binding,
complete batch and fresh compositor alias refusal, failed diagnostic retention,
and candidate absence transitions. Two test-expectation failures remain
retained; neither weakened a runtime predicate.

Original seven models and Python suites must pass with the new metrics model.
No native browser/Files campaign is accepted from offline tests. Root owns the
source review, freeze, preflight and original15-case actual campaign. No main
GUI/config/sudo/input/deployment operations were performed here.
